## 播放与时间码

- **试听也按你选的发送方式发时间码**：在设置里选了「只发四分之一帧」，以前只有正式播放照做，编辑器和灯光工作台里试听时仍会先发整帧定位，用 CH345 这类接口时会出现「试听出灯、正式不出灯」或反过来。现在试听和正式播放用同一个接口、同一种发送方式。
- **只保留 Windows 原生音频一种播放方式**：备用的浏览器音频播放方式去掉了。所有歌都用 Windows 原生音频播放，时间码和音乐用同一个声卡时钟，不会再因为设置里还留着旧的播放方式而拒绝播放。以前在旧播放方式下选过播放设备的电脑，现在声音从 Windows 默认播放设备出，设置页会写明，重新选一次就好。
- **有画面的歌，画面没准备好也照常播放**：以前有机位或素材的歌，画面准备失败（比如 OBS 没连上、素材文件变了）就整首不播。现在按“随时可以播放”：音乐和时间码照常走，画面标红并写明原因。画面需要时间准备时（比如第一次生成定位缓存），仍会先等画面准备好再开始。

## 灯光与 MA2

- **控台 Show 另存新名字、换了 IP 都不用重新读取**：联动台只按编号认控台。每天把 Show 另存成新名字，或者控台换了 IP，联动台会自动把工程里的素材、分类和每首歌在控台上的位置改到新的名字和地址，接着同步，不再提示「控台的 Show 或版本变了」「这首歌绑定的控台、Show 或页面有变化」，素材也不再显示「来自另一个 Show」。只有一种情况会停下这首歌：控台上同一个编号的序列换了名字，这时可能打开了另一个 Show，提示里会写出两边的名字。
- **控台上新建时间码节目不再让自动同步停下**：以前控台上的时间码节目一有增减（包括联动台自己给新歌建的），已绑定歌曲的自动同步就会停住，要重新读取控台。现在照常同步。
- **两种灯光同步合成一个**：控台上原有时间码的歌，和联动台新建序列的歌，现在用同一个同步、同一个状态。一首歌同步失败只停在这首歌上，写明原因，其他歌照常同步；以前已绑定歌曲有一次失败，所有已绑定歌曲的自动同步都会一起停下。控台上原有时间码的歌，编辑器里打开的那首每 2 秒核对一次控台，其他歌 30 秒一次，以前是每 2 秒把所有已绑定的时间码整条读一遍。
- **断线、播放中只是等待**：控台上原有时间码的歌在断线或播放时不再算同步失败，连上、停止后接着同步。真正失败时仍不自动重试，下一次编辑或点“刷新同步”再试。
- **改名也跟着实时同步走**：右键改了控台 Cue 的名字，实时同步开着时随下一轮同步写到控台；同步暂停或用本机 onPC 时，这次改名单独写一次。
- **“新建与同步”面板认得原有时间码的歌**：这类歌显示它跟着哪条 Timecode，可以单独刷新同步，不再显示「创建到按钮第 1000 页」。
- **同步前存档一分钟最多一份**：以前原有时间码的歌每写一次控台就存一份工程，存档会越积越多；现在和新建序列的歌一样，一分钟内的连续写入只存一份。
- **去掉设置里的「启用编辑后自动同步」**：它是实时同步之前的旧入口，作用已经包含在顶部的「实时同步」里。
- **播放时显示控台在不在跟**：连着控台网络、并在灯光工作台推杆页连过一次网页遥控时，播放中每秒读一次这首歌刚触发的执行器。对得上，顶栏「灯光」写「控台在跟」；连续两次对不上，写「控台没在跟」并标红，说明哪个执行器停着或停在哪个 Cue，音乐照常播放，日志里也记一笔。只接 MIDI 线或读不到时，写明为什么无法确认，不会乱报。这项只读控台，不发任何控制。
