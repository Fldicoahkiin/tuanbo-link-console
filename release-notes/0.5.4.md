- **MIDI 接口不再被一直占着**：以前打开过编辑器、灯光工作台等用到 MIDI 的页面后，联动台会一直占着电脑上所有的 MIDI 接口，单用户的 USB MIDI 接口因此打不开，正式播放发不出时间码，P1 也连不上（日志里是「错误码 7」）。现在联动台只在用到时打开要用的那一个接口，用完就关；停止播放后时间码接口马上空出来，P1 等其他软件可以接着用。
- **播放优先**：正式播放要用某个 MIDI 接口时，编辑器里对这个接口的试听和预览会先停下并说明原因，播放结束后再用。
- **切歌更稳**：连续切歌或重新准备歌曲时，偶尔会读到上一首的播放状态而报错，现在会等这首歌准备好再继续。
- **MIDI 提示更清楚**：接口被其他软件占用、同一个接口同时设成了两种输出、电脑上有好几个 MIDI 输出不知道用哪个时，提示会写明发生了什么、该去哪里改。
- **文案更好懂**：界面、提示和报错都改成了日常的说法，比如「内部主控」改叫「联动台播放」，「预检」改叫「开播前检查」，「布防」改叫「待命」，「尚未」统一成「还没」。出错时先说发生了什么，再说该怎么做；常见的提示里不再出现「会话」「受管」这类内部用词。
- **随时可以播放**：开播前检查只提示、不再拦：灯光有改动还没同步到控台、关联需要重新确认时，也会直接播放，并照常发送这首歌的 MTC 时间码，控台按它现有的时间线跑灯。不再弹“不带灯光播放”的对话框。
- **只按 MTC 起始码配对**：P1 的音频和控台时间线只看 MTC 起始码是否一致来配对，控台上改了 Cue 的时间不会再让配对失效。
- **控台录的时间线也能在联动台里改**：以前控台上录的时间线里只要有联动台不转换的动作（比如按键松开、带特殊参数的 Cue），整条时间线就只能看不能改。现在可以在联动台里改 Cue 的时间、增删 Cue，并写回控台上同一条时间线；联动台不转换的动作保持控台原样，按键松开跟着按下一起移动。
- **两边同时改不再卡住**：控台和联动台改了同一个点时，以联动台为准写入，控台上的旧版本先备份在控台上，自动同步不再停下来等人选。
- **编辑器试听的时间码对齐控台**：在编辑器里试听时发出的 MTC 时间码从这首歌的起始码开始，和正式播放、控台时间线一致。
- **新歌在控台上好找**：新歌的序列和时间码节目用同一个编号（两边都空着的第一个号），名字都是歌名的拼音；按钮放在第 1000 页 101–190 格的空位，1000 页满了自动放到 1001 页，依次往后。
- **控台和联动台同时编辑更稳**：写入前会再确认一次控台上的序列。控台上刚改过，或者这个编号刚被别人占了，这次就不写，也不会把别人的序列当成这首歌的；稍后重新读取控台后再写。
- **控台上改的也会回到联动台**：联动台新建的歌，在控台上挪了 Cue 在时间码节目里的时间、删了 Cue 或触发、给新录的 Cue 加了触发，下次同步时联动台的时间线会跟着改，不会再被联动台改回去。两边改了同一个点时以联动台为准，控台上的旧版本先备份在控台上。
- **导入 P1 后能看到每首歌的 MTC 起始码**：导入 P1 工程时，每首歌的 MTC 起始码按 P1 里的原样带进来，导入完会逐首列出。节目单的卡片上也直接显示每首歌的 MTC 起始码，和其他歌重叠时标黄。
- **同名的本地歌会提醒**：之前拖进来的歌和 P1 里的歌同名、起始码却不一样时，导入后会列出来。确认是同一首歌，可以一键改成 P1 的起始码，这样就能和控台上按老流程录的时间线配对；已经在控台上编了灯的歌只提示，不替它改。
- **“生成点击播放联动工程”不再改起始码**：以前会把所有歌的 MTC 起始码重新排一遍，控台上按原起始码录的时间线就对不上了。现在每首歌保留原来的起始码，只给还没有起始码的歌排新的。
- **节目卡片分开写内容**：以前卡片上的“0 Cue”只算画面动作，编了灯的歌也显示 0。现在分开写“几个灯光点 · 几个动作 · 几个素材”。
- **MA2 换了 IP 也能自动连上**：以前一键连接只认上次保存的控台 IP，控台换了地址就一直连不上。现在保存的地址完全没有回应时，会自动搜索一遍：只找到一台控台就直接连上并保存新地址，同时告诉你换成了哪个 IP；找到多台时请你选；都没找到时说明要检查什么。控台有回应但登录失败时不会去连别的控台。
- **日志更好查**：MA2 连接记录写明连的是哪个地址；导入、写回 P1 工程会记下每首歌的 MTC 起始码；诊断包里加上电脑各网卡的 IP；同样的开播前检查结果不再每次整段重写，日志大约小一半。声卡断流时的提示从一串数字改成“声音断了一下，重新播放即可”这样的说法。
