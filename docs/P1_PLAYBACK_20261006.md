# P1 原始起点与播放切场景修复（0.4.42）

本次针对另一台测试主机提出的两项问题：导入 P1 后无需重新填写 MTC 起始时间；点击播放自动执行场景 Cue，不需要拖动播放头。

## 已确认的代码问题和改动

1. `.hia` 的 `MidiStartTime` 在现有导入命令中已经写入 `playback.mtcOffsetMs`。缺口是旧工程仅保留 `p1Media.midiStartTime` 时，播放器没有使用该值。统一歌曲起点解析：明确的本地播放设置优先，否则读取保留的 P1 原始值；不额外叠加已实际裁剪的源音频起点。显式编辑为零仍是有效设置。新导入直接保留 P1 值，不自动分配新起点。
2. 节目属性直接显示可编辑的“MTC 起始时间”，不再藏在折叠区。播放、停止时的时间显示和按时间配对共用起点规则。修改保留原始导入值作为来源，保存重开后本地修改继续有效。
3. OBS 应用音频窗口采集失败会阻断整个画面布防；拖动预览绕过了该准备步骤。采集异常现在单独记录和显示，本机音频与可用画面动作继续。不会把采集失败表示为 OBS 已收到音乐。
4. `ObsMediaScenes` 用旧的 `CurrentProgramSceneChanged` 缓存省略切换请求。真实 OBS 验收发现外部切场景后事件尚未送达，开场 Cue 被错误标为成功且没有切换。移除此项跳过：每次明确的场景 Cue 都发送请求；图层结构复用和运行时 Cue 去重保持。测试未通过扩大超时消除问题。
5. 浏览器播放器的通道异常此前只更新界面提示；现在也进入运行日志，并对同一提示去重。原生 OBS 状态新增经 Zod 验证的采集提示，避免画面正常时掩盖音频采集故障。

## 操作

导入 P1 的 `.hia` 及其歌曲素材，节目属性会自动显示 P1 原有的 MTC 起始时间。不需要重新输入。如果打开的是仅保留 P1 原值的旧工程，也直接读取该值；明确手工编辑过的起点不被旧原值覆盖。只需配置一次实际连接控台的 MIDI 输出端口。
