# 团播联动台参考产品研究

2026-09-10 更新：用户已授权以其自研 IBC 为功能对齐目标，保留联动台原有 UI 风格。以下早期“仅参考、不兼容”的结论已被此次要求更新；当前实现与尚未覆盖项以 [IBC 功能对照](./IBC_PARITY_20260910.md) 为准。

## 结论

团播联动台只承担节目单、Cue、时间码、OBS/MIDI 动作、状态与日志。OBS、P1、抖音直播伴侣继续拥有正式画面、正式音频和直播出口。

HiRender S3 是成熟的媒体播控系统，能力范围明显大于本项目。IBC 是轻量音频 Cue 工具，工作流接近本项目，但其运行时可靠性不足。两者都只作为产品与交互参考，不作为兼容目标。

本机合法学习版 `5.2.7` 的只读检查显示，S3 主界面采用 Qt5 Widgets/Quick 的停靠面板式桌面架构，控制端、显示端、媒体服务、采集、NDI 和外部控制能力由不同可执行模块或插件承载。联动台不复制这些专有实现，只吸收通用工作台规律：顶部命令与模式切换保持紧凑，资源、参考舞台、属性和时间线固定在同一屏，上下文属性随当前选择变化，时间码和播放状态使用高对比显示。

## 能力差距矩阵

| 能力 | HiRender S3 | IBC | 团播联动台决定 |
| --- | --- | --- | --- |
| 节目管理 | 成熟节目、窗口与时间线双模式 | 播放列表 | 有序节目单，操作员手动选择当前节目 |
| 时间线 | 媒体与控制命令统一时间线 | 音频波形加场景 Cue | 参考素材、OBS、P1 MIDI、灯光 MIDI/MSC 四条显式轨道，不承载正式媒体 |
| 时间码 | LTC/MTC 监看与控制 | MTC 输入与偏移 | P1 MTC 为唯一自动时钟，每节目归零 |
| 设备联动 | MIDI、DMX、网络与专用控台 | OBS WebSocket、MIDI | OBS WebSocket 5.x；P1 与灯光控台分别使用独立 MIDI/MSC 端口档案，暂不直接驱动 DMX |
| 预监与输出 | 多媒体服务器、预监、多屏输出 | 本地音频试听 | 仅耳机试听参考音频，不输出 Program |
| 运行安全 | 主备与专业播控流程 | UI 定时器容差触发 | 单调时钟、跨越触发、丢码冻结、显式恢复 |
| 直播伴侣 | 未发现官方原生联动 | 无 | 完全独立于联动台，只采集 OBS 输出 |
| OBS 深度控制 | 未发现官方 OBS WebSocket 5.x 证据 | 场景切换 | 场景、来源、滤镜、音量、媒体、转场、截图 |
| 日志 | 产品内部状态 | 本地文本日志 | 结构化脱敏事件日志与诊断导出 |

## 吸收的设计原则

- 编辑与现场运行分离。
- 当前节目、当前 Cue、下一 Cue 和时间码始终可见。
- 动作以有序列表呈现，现场前统一预检。
- 波形只用于定位和试听，正式音频仍由 P1 输出。
- 采用“媒体—时间线—属性检查器”的稳定三栏关系：本地视频/音频/图片与 OBS 已有摄像头及可视采集来源统一显示在媒体列表；纯音频、场景、滤镜和转场不伪装成媒体，控制仍通过 OBS 动作 Cue 配置。
- 媒体库使用文件夹树、列表列、缩略图、状态、筛选、搜索和上下文菜单；不再设置“工程资源 / OBS 资源”分页，只吸收通用工作流，不复制 S3 素材、界面或专有实现。
- 参考舞台默认 `1080×1920`（`9:16`），可显式切换 `1920×1080`（`16:9`）；主工作台分隔线可拖动调整，布局仅保存在本机 UI 状态。
- OBS 可视采集来自 WebSocket 库存及 input kind 分类，覆盖摄像头、采集卡、NDI、显示器、窗口和游戏采集，并递归读取来源组；联动台不直接枚举、打开或采集设备。
- 外部设备断线必须显式告警，恢复需要操作员确认。

## P1 1.14.2 工程验证

本机受控测试确认，P1 的 `.hia` 是 UTF-8 XML，根节点为 `playerRoot`，播放列表位于 `videoPlayList/videoPlayElement`。纯音频通常使用 `mediaType="4"`，但带音轨的 MP4 会使用 `mediaType="1"`，因此该编号不能单独证明素材是否可作为节目音频。联动台对音频容器直接复制，对 MP4 等媒体容器验证并提取首条真实音轨为 WAV，用于编辑参考与波形，同时保留 P1 原始素材路径。容器无可解码音轨、文件缺失、格式不支持、时长无效或源工程在确认后发生变化时会阻断整次同步。

本机随 P1 安装的官方《P1 用户使用手册》《P1 使用 MIDI 时间码的操作》和《P1 连接时间码盒子方法》确认：先让 P1 连接可用 MIDI 输出，在设置中勾选“发送 MTC”并设置发送帧率；双击素材后 P1 从 0 开始发送 MTC，也可以逐素材设置 MTC 起始时间。手册给出的链路是物理 USB-MIDI 输出至时间码盒，再转换为 MTC/LTC。本机已在 P1 1.14.2 实际播放同一工程时分别监听 loopMIDI 与 Windows MIDI Services 的两个原生软件环回，三次均收到 0 条 quarter-frame，P1 也持续显示 MTC“未发送”；因此当前机器不能把软件端口枚举当作签收证据，需使用物理 USB-MIDI OUT→IN。联动台不能在应用内部伪造端口或时间码。MTC 数据不携带播放列表、曲目名称或素材 ID。联动台继续采用“每节目从 0 开始”的业务规则，不用人为时间偏移伪装曲目 ID；因此 P1 直播放要求操作员先在联动台选择同名当前节目并完成布防。任意在 P1 切歌后自动识别节目，必须有额外且已验证的曲目标识协议，当前 P1 官方资料未提供该协议。

工程工作区采用与 P1 操作习惯一致的三区结构：上方为参考试听、Cue 摘要和正/倒计时，下方为左侧播放列表、中间音频卡片库和右侧当前音频属性。双击音频卡片或点击编号可设为当前节目。该实现只吸收通用布局和操作顺序，不复制 P1 代码、素材、商标或专有控件。

Cue 时间线采用剪辑软件式直接操作：顶部只保留可点击的选择、切割、删除、首尾定位、逐帧、播放/暂停、吸附与缩放工具，不使用难读的说明字段或浏览器原生音频控件。视频拖入后由 FFmpeg 提取内嵌音轨缓存并在音频轨显示真实波形，避免 Chromium 对 MP4 容器解码支持不一致；统一预览时钟按工程帧率推进，音频和视频只跟随该播放头。片段支持双侧修剪、播放头切割、复制粘贴、相邻复制和右键菜单；切割作为单个 Command 原子执行，并为右侧片段保留正确的素材入点。

指定播放头下的片段与 OBS Cue 有效性统一由 core 的纯时间线解析器计算，时间线高亮、参考舞台和正式运行事件都消费同一解析结果；区间统一为左闭右开，选择状态不参与内容生效判断。视觉图层列表第一行就是最上层，拖动手柄松手后才提交一次排序 Command，撤销恢复同一图层身份与舞台叠放顺序。

OBS 隐藏的显示器采集可能在场景项变换中报告 `0×0`。适配器必须用该输入的 `monitor_id` 属性绑定和 OBS `GetMonitorList` 的结构化显示器数据解析真实分辨率，再按原始比例请求预览；renderer 不得把 `0×0` 猜成 `1×1`，也不得用输出画布尺寸冒充来源尺寸。该预览仍是编辑参考流，不改变来源显隐或 Program 输出。

写回采用独立的 `*.联动台.hia` 和原子替换，不修改用户原工程。P1 没有在本机资料中暴露可验证的工程热重载协议；产品不通过虚拟键盘、坐标点击或强制结束进程来制造“一键重载”。

## 明确拒绝

- 不复制 S3 的媒体服务器、舞台渲染、多屏、融合、采集和 DMX 范围。
- 不采用 IBC 的 UI timer 容差窗口触发。
- 不使用假波形、假电平、静默异常或隐式降级。
- 不保存或输出 OBS 明文密码；IBC 现有日志中的凭证必须视为已泄露并轮换。
- 不检测、启动、关闭或通过任何方式控制直播伴侣。
