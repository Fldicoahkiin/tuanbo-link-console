# 设置界面设计与覆盖清单

## 当前基线

2026-10-14 用户批准设置区完整改版，随后明确指出“还是丑”“看不清看不懂”，要求苹果桌面工具的干净、清楚、有层次的观感。后续实现以这些反馈为优先：正文与控件 15px、说明 14px、标题 24px，减少重复导航副文案，首屏先说明状态和下一步。旧版 13 页检查清单废止。

保留三列与现有 17 个 SettingsCategory 标识。宽窗口导航 216 / 208px，中窗口 184 / 192px，有效宽度不足 900px 时 120 / 144px。内容靠左，普通表单最多 960px，导航独立滚动、内容只有一个页面滚动区。顶部状态栏、详细、一键连接保持原有外观。

深色设置内容使用清晰的深灰层次，浅色使用独立的灰白配色。颜色集中在 device-connections.css，只作用于设置区。连接摘要允许单层背景；其他分组依靠标题、对齐和分隔线。正常操作不弹出全屏维护界面。单色 Lucide 图标、清晰焦点、减少动态效果均保留。

## 实现边界

- SettingsControls 提供标题、字段、分组、Switch、密码、反馈、操作区、展开区、确认对话框。
- SettingsNavigation 记忆本次会话各分类最后访问项；IntegrationSettings 记忆已访问页面和滚动位置，显式 SettingsLocation 定位优先。
- settings-session-store 仅记录未保存分组与会话 revision；密码留在组件内存，不写 UI 偏好。
- OBS、程序维护使用独立保存边界。mergeProgramSettings 的单测检查 OBS 地址、凭证引用、自动连接与无关 MIDI 草稿不会被维护保存夹带。
- 离开设置有未保存草稿时显示继续编辑 / 放弃修改；丢弃会清除密码并恢复遮罩。工程修改仍经 LinkCommand。
- ObsPreviewSetup 在 OBS 与程序维护中复用，并读取共同的预览检查结果。
- 保留既有 IPC、协议 DTO 和工程 schema，不新增设备权限、自动重试或购买行为。

## 自动化与人工验收

运行 `pnpm build` 后执行 `node scripts/check-device-settings.mjs`。脚本启动使用临时数据目录的 Electron 测试，按导航源定义遍历 17 页；不连接操作者的开发窗口，不修改当前工程。

基础矩阵：17 页 × 深浅主题 × 1180×720 / 1540×960 / 1920×1080，共 102 张截图及布局结果。另测 125%、150%、200% 页面缩放、展开区与页尾。输出：`apps/desktop/test-results-settings-redesign/`。页面缩放不等于 Windows 系统 DPI，二者必须分别记录。

自动化检查包括：标题、横向溢出、最小文字字号、草稿隔离、跨页保留、分类记忆、密码显隐与退出遮罩、退出确认、快捷键撤销及焦点恢复、OBS 保存成功但连接失败、更新阶段。授权与订单使用现有 `license-settings.browser.spec.ts` 测试替身。

人工已复核 OBS 深浅主题、音频页及 MA2 首屏，发现并修复旧窄屏导航隐藏标题、旧按钮字号、通知遮盖导航、MA2 首屏长说明等问题。102 张截图的逐张人工复核、全部连接条件分支、Windows 125% / 150% / 200% 系统显示缩放、真实 OBS / P1 / MA2 与支付联调仍须单独记录；不得将自动截图或替身测试当作这些验收已完成。
