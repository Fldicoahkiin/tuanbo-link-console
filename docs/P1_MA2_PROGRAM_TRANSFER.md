## 当前使用步骤

1. 在最终电脑运行包含本轮修改的联动台；在 MA2 导入并启动随软件导出的新版桥接插件。旧插件没有 LIST 能力，不能只更新电脑软件。
2. 设置中选择实体控台 / 网络 onPC，填写实际控台地址与允许远程登录的 Show 用户。登录和插件检查成功后继续。
3. 在“现场节目导入”读取 P1 当前工程或选择 `.hia`；保存联动工程，使音频复制到工程资源目录。
4. 点击“扫描控台全部时间线”，核对 Show、读取异常、帧率、偏移和每首歌对应的 Cue。
5. 对已核对且当前支持的时间基准选择歌曲，点击“导入已配对灯光”。已绑定对象使用“查看与同步此时间线”进入现有差异比较及显式同步。
6. 有非零歌曲起始时间码、特殊偏移或不支持数据时，导出现场核对包用于下一轮适配，不把失败项目当成已迁移。

实时播放仍需解决既有 MIDI 故障并在最终电脑实测；编辑后自动同步和播放中更新尚未实现。当前入口不应作为已完成现场替换 P1 的承诺。

## 用户要求

1. 设置中自动识别当前连接的实体 MA2 控台所有录制了时间线的 Cue。
2. 将最终使用电脑上 P1 的对应音频及 MA2 对应灯光时间线一键导入联动台。
3. 联动台播放音乐时实时触发对应灯光。
4. 联动台编辑 Cue 引用和时间线后，更新对应实体控台时间线。

## 数据来源与识别

音频从 P1 工程引用的原始媒体读取；灯光编排从 MA2 当前 Show 的 Timecode 对象、执行器和 Sequence/Cue 引用读取。不能从 MIDI 时间码还原音频或完整灯光工程，也不能假定 MA2 保存了 P1 的原始音频。

设置入口拟为“设备连接 → MA2 控台 → 现场节目导入”：

- 当前控台、Show、版本、扫描时间与连接状态。
- 全部实际 Timecode 对象目录；显示有事件的时间线，同时明确空对象及未支持对象数量。
- 每个对象显示编号、名称、帧率、Timecode 偏移、Slot、轨道、执行器、Cue 引用及事件时间。
- 扫描为只读，不执行灯光 Cue；单个失败明确列出，不把部分扫描显示成全部完成。
- 换控台、换 Show 或连接失效时，旧目录与待提交结果失效。

全池目录协议及上述设置入口已实现，验证范围见本轮记录；实体控台仍需现场验证。

## 音乐配对与一键导入

先读取 P1 工程中的歌曲身份、原文件、时长和原始 MidiStartTime，再读取控台时间线。已确认的绑定优先；歌曲名只用于建议，不作为唯一身份。

第一次出现同名歌、重复音频、重叠时间码区间、一首歌多条 Timecode 或一条 Timecode 含多首歌时，需要明确配对。配对保存后可一键更新已绑定节目；再次导入不得重复创建或覆盖本地未处理修改。音频逐字节复制并核对摘要，最终打包工程可带回开发电脑。

**必须保留现有 P1 起始时间码、MA2 偏移和帧率。** 现有“生成点击播放联动工程”调用 allocateP1TimecodeRanges 重新分配区间，不能直接用于迁移已经配好 MA2 灯光的现场工程。

当前 P1ProjectService 已能读取 P1 工程并复制媒体；MA2 转换器仅接受已验证的 30 FPS、零 Timecode 对象偏移。其他帧率、偏移和跨歌曲时间线需要实际现场样例及原生回读测试后接通，不能默默归零。

## 播放

保留显式选择的内部主控与 P1 跟随模式，单次会话只使用一个音乐时钟。最终采用哪种工作方式等待用户选择。

使用现场已有 MA2 时间码节目时，由音乐实际播放位置加原始时间码映射输出 MTC，MA2 执行绑定的 Timecode。还需确认控台目标 Timecode 已正确选定、Slot 和执行状态正确，不能仅凭 MIDI 端口连接就显示可以演出。同一绑定不得同时走 MTC 播放和逐点 Cue 直接触发，以免重复执行。

现有真实 MTC 测试仍有 Windows WinMM 兼容通道故障，见 MA2_ONPC_ACCEPTANCE_20260915.md。该问题未解决前不得宣称播放链路已通过。

## 编辑与写回

编辑范围是 Cue 引用、事件时间、轨道绑定及已支持的执行器动作和 Master 事件；Cue 内灯具颜色、位置、效果等参数继续由 MA2 管理。

当前是读取快照、比较冲突、备份、导入目标 Timecode、回读确认的显式同步，播放期间禁止写入。它不是实时编辑协议。

所需新增能力：

- 停止播放时可选“编辑后自动同步”，合并连续拖动，只写最后确定的编辑结果；显示待同步、同步中、已回读、冲突、失败。
- 控台反向修改检测需关联当前 Show 和绑定对象，不能用导出时间戳作为修改判断。
- 双方都改时停在冲突，不自动覆盖、不重放结果不明的写请求。
- 若要求音乐播放中编辑即生效，需要独立实现及验收控台支持的事件级更新方式。现有整对象 XML 导入不直接用于热更新，必须验证不会重启时间线、重复触发或漏触发；已过去、正在执行、尚未执行的事件要有明确规则。

## 验收门槛

1. 真实 onPC 扫描结果与原生 Timecode 池及导出事件总数对应；空对象、重复引用和不支持事件不漏报。
2. 真实 P1 工程与音频导入后，歌曲、原时间码、Cue、偏移及引用对应，重复导入保持幂等。
3. 以现场时间码配置播放两首歌，验证切歌、暂停、继续、定位、重播、结束和无重复触发。
4. 软件改时间、控台改时间分别往返通过；双方冲突、换 Show、断线及迟到响应不覆盖错误目标。
5. 若启用播放中修改，独立验证播放头连续、已执行事件不补发、未来事件在修改后正确执行。
6. 最终在实际电脑及实体 MA2 上复验；onPC 和模拟测试分别记录，不能替代实体闭环。
