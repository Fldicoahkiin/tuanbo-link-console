# 停止状态拖动黄线的 OBS 画面定位

## 原因与修复

内部主控编辑器在停止状态下，`useEditorTransport` 只更新游标并提前返回；实时画布一直显示 OBS 当前正式场景，因此时间线移动后仍可能停留在旧场景或已停止的视频黑帧。

停止时的显式定位现在通过独立的编辑预览操作执行：解析当前位置的场景与素材叠加，准备所需应用自有素材场景，计入片段入点并调用原生暂停定位。预览视频静音，不准备正式音频、不布防、不发送灯光 Cue，运行状态保持 idle，工程仍可编辑。连续拖动合并等待中的旧位置；停止、切换工程或进入正式会话后，迟到操作不再继续切画面。定位失败显示并记录，不自动重试。

## 验证

- 相关 79 项单测通过，覆盖位置合并、素材入点、机位覆盖与恢复、叠加、失效操作、正式播放回归。
- 类型检查、修改文件 ESLint、构建通过。
- Windows 独立便携 OBS + Electron 实测通过。使用自生成运动视频，在从未播放且没有歌曲音频的工程中，定位 2 秒显示非黑色实际视频帧；5 秒切至机位；8 秒恢复视频；连续往返拖动后 OBS 暂停在 1 秒。随后能删除时间线片段，验证未取得运行编辑锁。
- 可复现测试：`apps/desktop/test-e2e/editor-stopped-preview.spec.ts`。需要通过 `TBLINK_OVERLAY_OBS_EXE` 与 `TBLINK_OVERLAY_OBS_URL` 指定独立测试 OBS，禁止指向现场实例。
- 本次证据：`artifacts/stopped-preview-20261005/e2e/`。测试实例已正常关闭；未重启现场 OBS，未验证用户工程中每个摄像头场景自身是否有信号。
