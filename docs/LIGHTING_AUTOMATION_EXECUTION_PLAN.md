## 2. 执行顺序

### A. 先恢复可用的灯光播放

1. 复现普通播放只走音频、不触发网络 Cue 的问题，覆盖 P1 工程本地编辑试听、内部主控浏览器音频、内部主控原生音频三条路径。
2. 核对实际播放时钟、输出准备开关、灯光输出模式、连接状态、事件编译、调度和停止边界。
3. 移除灯光工作台“选了输出但还必须打开隐藏开关”的不一致；视觉编辑器的可选试听语义独立保留。
4. 准备前后发生取消、切歌、跳转时，迟到结果不得复活输出；异步网络错误不得丢失。
5. 按播放、暂停、恢复、定位、循环、结尾、停止、设备断开顺序建立自动化回归。模拟验证和实机验证分别记录。

### B. 把研究引擎接成真实服务

1. 固定并核验模型／依赖版本、摘要与许可；Beat This! 三模型、All-In-One 分层运行，取消旧 RMS 候选算法的默认职责。
2. 将研究脚本拆成严格输入、进度、结果、错误协议；模型原生日志走独立日志流。
3. Electron 适配器只负责本地路径、任务、进程、缓存和 DTO 校验；算法和质量判断留在领域／分析层。
4. 统一音源身份，必须接到实际播放的最终音频；缺少最终音频、工程位置、模型或设备时返回明确原因。
5. 单任务队列、去重、缓存校验、取消、超时、故障、迟到结果丢弃、切歌／关工程处理。
6. 现场运行状态阻止新分析并协作暂停；用户显式恢复，不能悄悄重跑或切换 CPU/GPU。

### C. 完成识别质量工作

1. 20 首可行性筛选；随后至少 150 首，80 开发／30 校准／40 盲测；同曲变体同组，关键类别盲测不足 100 实例则补充。
2. 两名有音乐／灯光经验的标注者建立和复核真值，歧义单列。不得把三模型投票当人工真值。
3. 节拍使用真实逐拍时间，第一拍独立判断；局部变速／剪接重新起拍；半速、倍速、错相位区不盲目融合。
4. 结构边界和标签分别评分；标签不可靠但边界可靠时可显示中性段落；自然淡入淡出不强行对拍。
5. 重击／Drop／最后一击、滚奏／渐强、静音／声部撤出分别建模和验收；不能用总音量峰值冒充语义事件。
6. 阈值在校准集确定，再在盲测集一次性检查；同时报告正确率、召回率、覆盖率、按歌曲／音乐类型统计。
7. 达不到标准就保持该能力关闭。若节拍或基本分段不通过，不发布“完整自动分段卡点”。

### D. 工程数据、纠错与试听

1. 严格结果包含音源身份、引擎版本、beats、downbeats、sections、events、局部速度、质量摘要与纠错记录。
2. 应用、移动、删除、边界纠错及撤销全部使用命令；撤销自动应用后，组件重渲染不能立即重复应用。
3. 保持既有 Cue 时间和 tempo map；新可靠结果只在用户操作时作为吸附依据。
4. 同源重分析合并纠错；换源、损坏缓存或版本不符立即排除旧结果，不接受迟到写入。
5. 独立监听使用实际拍点；点击声不会进入正式节目输出。对实际播放和录制回读进行延迟、累计漂移测试。
6. 保存重开、旧工程兼容和旧程序拒绝覆盖保存均建立回归用例。

### E. 正式 UI 与自动工作流

1. 仅改时间线区域；保持 Cue 上沿、单行工具栏、时间标尺、缩放与密集标签设计。
2. 分析入口接真实状态机，展示当前音源的状态与必要操作；不再长期保留“验证中”说明作为功能替代。
3. 当前音源首次进入自动排队；重复进入读取缓存；批量歌曲顺序运行、整体进度和取消。
4. 结构、普通拍、小节第一拍、演出事件有明确视觉区别；缩小降采样绘制，不删除底层点。
5. 不显示低可信候选、不出现逐项勾选、灵敏度滑杆和手填 BPM；无可靠结果时明确显示“本次未生成可靠结果”。
6. 所有触控目标、键盘、焦点、Escape／点击外侧关闭、低宽度窗口、空态／错误态／长任务态均检验。

### F. Windows 发布验收

1. `pnpm typecheck`、`pnpm test`、`pnpm lint`、`pnpm build`。
2. Electron e2e 全集；若先前测试仍依赖已删除 UI，按新产品行为更新，不能删除关键断言规避失败。
3. `pnpm verify`、`pnpm verify:release`，Windows 原生环境完成。
4. preload 有修改时完整重启 pnpm dev；检查用户正在运行的是本次代码／构建。
5. 安装包离线运行、模型缺失／损坏、CPU/CUDA 明示、真实设备断开与控台动作实机回读。
6. 交付实际 UI 截图、真实音源核对页、逐类误差／漏检报告、耗时与失败案例、安装与模型许可清单。

## 3. 精度发布门槛

| 能力 | 精度／覆盖要求 |
|---|---|
| 普通节拍 | ±50ms，正确率≥99%，召回≥95% |
| 小节第一拍 | ±70ms，正确率≥98%，召回≥90% |
| 匹配拍点误差 | 中位≤20ms，P95≤50ms |
| 结构边界 | ±250ms，正确率≥95%，召回≥85% |
| 显示的结构标签 | 正确率≥95%，另报覆盖率 |
| 重击／Drop 起点／最后一击 | ±80ms，正确率≥98%，召回≥80% |
| 滚奏／渐强区间 | IoU≥0.7，正确率≥95%，召回≥80% |
| 静音／连续性 | 纯静音零拍点；不得漏过持续两小节以上的半速／倍速／错相位 |
| 性能 | 指定机器5分钟首次端到端P95≤180秒；缓存≤2秒 |

以上为要求，不是成绩。现有一个 50.965 秒样本只证明推理跑通，不能替代完整质量数据。

- 底部时间线已精简：Cue 紧贴标尺和波形、整数编号隐藏 `.000`、有意义小数保留。旧参考网格的开关、绘制和隐式吸附删除；已有 tempo map 及原始 Cue 引用保持。
- 控台素材可直接拖入时间线，按当前目录校验引用，经工程命令保存；密集标签、屏幕外选中定位、取消拖动、撤销重做和保存重开覆盖。上方布局沿用原工作台，不作本轮重排。
- 本地编辑试听与正式内部主控按实际音频驱动灯光。断线报错、暂停／恢复／停止、自然结束、定位不补发均有软件回归。换源按工程路径、相对音源和摘要重新绑定，失败不播放旧音频、不空跑。
- 正式原生播放器接到主进程 `NativeProgramHost`：自动换歌、通用 MIDI、直接灯光及已有后台 OBS 读取设备时钟；UI 仅转发操作、显示状态。严格 DTO、会话隔离、停止打断准备、迟到关闭及关闭失败保护新增九项单测通过。界面崩溃后须确认自有输出停止，才解除运行退出保护。
- 真实 WASAPI 的正式按钮、暂停继续、切页、元数据编辑、切歌、曲尾暂停通过；界面阻塞 4 秒仍后台接续，界面崩溃后自有引擎退出。日志 `lighting-native-host-verified.log`、`lighting-native-boundary-complete.log`。

- 分析验证服务已经接入真实 Python 进程、CPU／CUDA、单任务队列、去重、缓存、取消、现场协作暂停和显式恢复；切工程的状态及迟到结果隔离已验证。界面如实标明识别验证版本，正式结果仍为零。
