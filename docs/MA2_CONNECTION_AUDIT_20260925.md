# 0.4.29 控台发现与直连检查

用户报告另一台电脑接入 MIDI 和网线、开启控台网络连接后，自动连接及局域网搜索均未找到控台。现场无法复现；本轮在当前 Windows 电脑调查，不将本机通过视为另一台电脑或实体控台验收。

## 已修复的软件问题

- 已保存的 IP 原本仍强制通过搜索重新识别；现在直接使用保存的连接和凭证，不依赖 Art-Net 广播。失败明确报告，不自动尝试其他设备。
- ArtPoll 从固定全局广播改为按各网卡掩码计算定向广播。广播错误不再静默隐藏；`/32` 地址明确提示没有广播子网。实现参考 [Art-Net Casting](https://art-net.org.uk/casting/)。
- TCP 建连后独立等待设备横幅，避免分段提示符导致提前误判。
- 修复本机地址全部被跳过的问题，本机 onPC 可以被发现；不同本机入口仍可能显示为多个地址，不能据此认定为多台物理控台。
- 搜索结果默认显示待确认端口，并可查看网卡 IP、掩码、搜索范围及警告。自动发现失败保留结果并展开手动 IP 设置。
- 直连超时显示命令/监视端口、各自 TCP 阶段及已连接的本机地址；区分端口不通、缺少 MA2 提示与登录未确认。

## 本机只读检查

- Windows 为目标 `2.97.214.223` 选择物理以太网，本机地址 `2.97.214.222/32`，使用显式的目标主机路由。没有修改 IP、路由或防火墙。
- 目标 TCP 30000 与 30001 在各 2 秒检查窗口内均未响应；原因不能仅据此确定为防火墙或控台开关。
- 原生 Electron 搜索成功返回本机 onPC 入口和一个未确认设备；目标 `2.97.214.223` 未被找到。仅探测 TCP 横幅及发送 ArtPoll，未登录或向控台发送演出命令。
- Web MIDI 枚举成功，当前端口为 P1 MTC、Tuanbo MA2、测试回环等虚拟端口；未验证另一台电脑上的 USB-MIDI 驱动或实体线缆方向。

## 验证

- `pnpm verify` 通过：类型检查、956 项单测通过（40 跳过）、Lint、构建及桌面产物校验。
- 新增定向广播计算、无网卡/自动地址诊断、分段 TCP 横幅、保存地址绕过搜索、未知设备不擅自登录、端口已通但缺少提示等回归。
- 2 项连接桌面测试在构建版和 0.4.29 打包版均通过；使用模拟连接结果，未进行实体登录。
- 安装包、内置资源、版本及发布清单校验通过。

现场下一次测试：填写当时控台实际 IP，点击“保存并连接”，无需先搜索到。如果失败，保存完整报错和“本机网卡与搜索范围”。电脑上的 MIDI 端口与网络发现是独立连接；无需关闭整个 Windows 防火墙。
