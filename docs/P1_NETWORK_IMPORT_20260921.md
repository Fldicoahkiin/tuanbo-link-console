# P1 音乐与 MA2 Cue 网络导入 · 0.4.9

## 现场流程

1. 安装桌面上的 0.4.9 安装包。在设置 → 设备连接 → MA2 控台选择“实体控台 / 网络 onPC”。
2. 首次点击“导出控台插件”。把 XML、Lua 放到 MA2 识别的 U 盘插件目录，在 Plugin 池空闲位置 Import `tblink_bridge.xml`，运行并保存 Show。软件内置插件文件不等于已安装到控台。
3. 电脑、控台接入同一局域网；控台开启 Telnet Login Enabled，使用 Show 用户登录。IP 不包含用户名和密码，软件不能自动获取密码。
4. 保存并连接后点击“检查插件通信”，确认显示“插件通信正常，可以读取灯光 Cue”。
5. 在下方选择 P1 `.hia`。普通文件入口和一键入口都会导入音乐，再扫描控台全部时间线、读取完整事件与 Cue 引用、配对歌曲并保存。导入后使用本软件内部主控播放，保留 P1 原始歌曲时间码。
6. 查看逐首导入结果。编辑器切换歌曲查看灯光事件。时间线名称与 MP4 歌曲名称匹配时忽略媒体扩展名；缺失音频的占位节目不参与自动配对。
7. 保留 MIDI 线，设置 MTC 输出。现场先确认控台时间码走动，再确认现有灯光时间线跟随。本地发送成功不等于控台已收到。

## 明确限制

- 无法配对、读取异常或不支持的时间格式会明确列出，不生成虚假的 Cue。跨多首歌曲的单一 Timecode 暂不自动拆分；需在控台拆分或明确核对编排。
- 当前原生转换支持已验证的 MA2 XML 3.3.4 / 3.7.0 和 30 FPS，其他版本和帧率不可当作已经兼容。
- 缺失音频文件无法凭 P1 工程恢复，保留待修复节目；存在的可解码音频继续导入。
- 插件缺失时保留已导入的音乐，明确报告灯光未完成。批量灯光导入保持原子性，读取期间工程或 Show 改变会拒绝应用。
- 既有灯光绑定保留编辑结果，后续更新使用双向同步，不重复导入覆盖。
- 网络用于读取/同步控台工程，MIDI 用于播放时间码。不能用网络登录成功代替声光同步验收。

## 验证

- Windows 全量类型检查、单元测试、Lint、构建及发布产物校验。
- Electron 测试：两个 P1 节目普通文件入口自动读取两个 Timecode，实际小数 Cue 1.250 / 7.500 保存并显示在编辑器；使用内部主控播放。
- Electron 失败测试：插件缺失时音乐保留，灯光未完成状态明确。
- 安装包插件导出验证 XML、Lua、安装说明完整。
- 网络测试替换了控台 IPC，使用本机采集的原生 XML 样例；不代表实体控台、MIDI 硬件与现场灯光已经验收。
