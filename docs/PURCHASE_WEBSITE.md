## 用户流程

1. 查看产品用途、单机授权、联网要求和期限起算规则。
2. 从服务端可售订阅中选择套餐，填写购买主体、归属名称和电脑数量；服务端最终决定价格与限额。
3. 页面生成 256 位随机订单领取凭据，先保存到当前标签页的 `sessionStorage`，再要求用户下载 JSON。存储失败不发出创建请求。
4. 用户确认文件已经保存后创建订单，拿到正式支付宝网关链接。网页不自动打开或代付款。
5. 用户主动查询，只有服务端验签核款后的 `fulfilled` 交付才显示激活码。回跳参数、按钮和浏览器自报状态不会发码。
6. 激活码保存在用户手中，输入桌面软件完成机器绑定。领取权限为订单创建起七天；过期或文件丢失需要支持人员核实并恢复领取权限。
7. 创建响应丢失时导入此前下载的凭据，使用原令牌与原请求恢复同一订单。状态未知时不允许清除当前订单另开新单。
8. 尚未提交的草稿，以及服务端明确返回未创建订单的商品变更/限额/暂停错误，可返回选择套餐。导入文件中的可清除标记不被信任。

JSON 文件包含购买人名称和订单领取令牌，相当于该订单的领取密码，**不是发票**。订单令牌只放在 Authorization 请求头，不进入 URL、统计事件或服务端日志。页面没有第三方脚本、字体、分析服务或外部图像。`sessionStorage` 不等于加密保险箱：同源脚本能够读取，因此部署必须使用独立产品域名、HTTPS 和配置中的 CSP，不能混入其他项目脚本。浏览器关闭或清除数据可能丢失当前会话，文件是找回依据；无法提供文件下载成功的跨浏览器保证，按钮文案要求用户确认。

网页导出的凭据格式与桌面加密订单记录不同，不承诺两者可直接导入互换。网页购买后，把交付激活码填入桌面即可。

## 构建与部署准备

```sh
pnpm --filter @tb/licensing-server build:web
```

输出为 `apps/licensing-server/dist/web/index.html`、`purchase.js`、`purchase.css`。浏览器构建独立于授权服务 Node bundle，默认服务端 build 不会自动发布网页。

准备好的 Nginx 文件是 `apps/licensing-server/deploy/purchase-site.conf`，**已用于本次官网发布**：

- 仅替换原 `tuanbo-link.jinhefilm.com` HTTPS 占位 server block，不能重复 include 同名站点，也不能覆盖 api、updates、金河分镜等站点。
- 将三份构建产物发布到 `/srv/tblink-purchase`；保留旧版本以便回滚。正式发布记录需要文件哈希、来源提交、备份、`nginx -t` 和公网页面/API 检查。
- 本域名只代理 `/v1/catalog`、`POST /v1/orders`、`GET /v1/orders/:id`，使用同源请求，无需放开 CORS。三个代理覆盖客户端 IP，沿用服务端分组限速；不开放 `/admin`、激活或支付回调。
- 回调仍为 `https://api.tuanbo-link.jinhefilm.com/v1/payments/alipay/notify`。
- HTTPS 页面和接口保持 no-store，CSP 禁止第三方脚本、iframe 嵌入、表单原生提交；外链支付宝使用新标签页和 no-referrer。

- 关闭商品目录并不会禁止历史订单凭据恢复/领码。不可只隐藏按钮却开放未经确认的生产目录。

CF 沿用已准备的 `tuanbo-link.jinhefilm.com` 解析；本次只调整团播官网 Nginx block，不修改商品目录、付款开关和其他项目站点。
