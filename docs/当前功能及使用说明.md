## 1. 软件定位与职责

团播联动台用于把音乐、节目切换、视频画面、OBS 动作和灯光事件编排到同一条时间线上。操作员可让联动台播放音乐，也可继续使用 P1 播放音乐，由联动台跟随 P1 的真实 MIDI 时间码执行动作。

| 系统 | 职责 |
| --- | --- |
| 团播联动台 | 节目单、素材管理、内部音乐播放、参考波形、时间线、Cue、MTC、MIDI、MA2 工程交换、设备连接与预检 |
| OBS Studio | 正式场景、视频解码、来源、滤镜、裁剪、转场及最终画音输出 |
| P1 | 可选的外部音乐播放器和 MTC 主控；内部主控模式无需运行 P1 |
| MA2 / MA2 onPC | 灯光 Cue 内容、Sequence、Executor、Timecode 和实际灯光执行 |
| 抖音直播伴侣 | 登录、直播间、采集 OBS 和推流，由操作员独立管理 |

联动台不包含 Program 输出窗口，不直接采集摄像头或麦克风，不提供 RTMP、NDI、虚拟摄像头或内置视频合成，不控制 OBS 推流/录像，也不控制直播伴侣开播/关播。通过 OBS 引用摄像头来源不等于联动台自行采集摄像头。

## 3. 页面与入口

当前主导航为“节目单”“编辑器”“设置”。旧文档中的“五工作区”“独立灯光设置页”“维护与诊断页”等名称不作为本版操作路径。

### 3.1 节目单

管理播放列表和歌曲，设置节目名称、备注及播放参数；在此进行正式音乐播放和选歌操作。歌曲属性包含逐曲音量、裁剪范围、结束行为、快捷键及时间码相关参数。

### 3.2 编辑器

上半区为参考画布及属性，下半区为贯穿编辑区的时间线。选中素材、Cue、灯光点或轨道后，右侧显示相应属性。通过资源库放入本地素材或 OBS 场景/来源。

灯光轨道直接在原时间线上编辑；节拍/循环及文件交换从时间线灯光菜单打开。节目同步可从轨道属性进入，没有已有轨道时仍可读取并导入控台 Timecode。

### 3.3 设置

| 分类 | 主要内容 |
| --- | --- |
| 设备连接 | OBS、MIDI、MA2、本机程序、插件与脚本导出、MSC 地址 |
| 播放 | 单击/双击行为、键盘选歌、预加载、淡入淡出等播放偏好 |
| 画面与同步 | 完整场景/受管输出选择、画面与时间同步相关设置 |
| 外观与更新 | 外观参数与软件更新 |

不同工作模式下显示的设备要求不同。不要用旧截图推断当前按钮位置。

## 4. 工程、节目和素材

### 4.1 文件保存

- 普通工程使用 `.tblink` schema v1；包含灯光数据的工程使用 schema v2。
- 旧程序应拒绝保存其不支持的新版灯光工程，防止灯光数据被丢弃。
- 工程保存节目、时间线、素材引用和灯光编排；设备地址、MIDI 端口名、外部程序路径保存在本机档案。
- OBS 和 MA2 密码、更新凭据使用 Electron `safeStorage`，不写入工程文件。
- 参考音频位于工程的 `assets/reference-audio`，本地媒体位于 `assets/reference-media`，波形缓存位于 `cache/waveforms`。

移动工程时应一起复制 `.tblink` 和配套资源目录，只复制工程 JSON 不代表已携带素材。打开工程时如工程文件夹缺少素材，会列出缺失项；选择 `.tblink` 原来所在的文件夹，软件只在其中相同的相对位置查找，SHA-256 一致才复制回当前工程文件夹，逐项显示「未找到」或「内容不一致」。之后也可从工程菜单「找回缺失素材」再次打开。找回的音频如在原文件夹有波形缓存，会一并复制。换电脑后需要重新配置本机设备，并准备对应 OBS 场景集合。

### 4.2 编辑与恢复

首次保存后自动保存后续修改。保存或恢复失败会报错，不应通过新建空工程覆盖原工程。工程编辑支持撤销和重做；只聚焦字段而未改变内容不应产生撤销记录。

### 4.3 导入素材

导入保留原文件字节，并使用 SHA-256 去重或核验。预览代理、缩略图及波形用于编辑，不替代交给 OBS 的原素材。文件缺失、被替换或损坏可能阻断预检。

源素材分辨率、放大比例、OBS 画布与输出缩放、直播端编码仍影响清晰度。低分辨率素材放大后不会变为原生高清。

## 5. 内部音乐主控

### 5.1 首次使用流程

1. 新建或打开工程，保存到确定的工程目录。
2. 明确选择“本软件主控”，添加一首或多首音乐。
3. 在设置中连接 OBS，选择完整场景切换或受管素材输出。
4. 如需灯光，在设置中选择时间码输出端口，并在控台核对 MIDI 输入和 Timecode 槽。
5. 选择歌曲，设置逐曲音量、有效裁剪范围和结束行为。
6. 在编辑器放入画面、场景切换点或灯光事件，保存后返回节目单。
7. 完成预检，在排练状态验证首个节目，再开展正式演出。

### 5.2 播放行为

支持播放/暂停、停止、重播、上下首、拖动定位和逐曲结束行为。空格播放/暂停、Esc 停止；文字输入期间不应触发歌曲快捷键。顺序播放包含设备预检和媒体准备间隔，不承诺无缝拼接。

正式音频位置来自媒体实际播放位置；界面刷新或本地计时器不独立推进正式节目。定位时恢复目标时刻应有的画面状态，不补发已经跳过的 MIDI/MSC 等一次性动作。暂停时定位仍保持暂停。

### 5.3 音频进入 OBS

软件检查可复用的桌面音频通路；没有明确可用通路时，使用应用拥有的内部正式音频采集。完整场景模式可在目标场景加入应用自有音频项，以维持切场景后的音乐输出，不重设原有视觉源。

内部主控默认关闭视频原声，避免音乐与视频重复出声；需要素材原声时显式开启相应设置。编辑试听也可能被 OBS 桌面音频采集，现场应核对监听和正式输出。

### 5.4 时间码

每首歌有灯光时间码起点/偏移，改动顺序、数量、时长或偏移后应重新核对控台编排。底层支持的时间码格式不等于每种工作流都已验收：当前 30 fps 有本机一小时媒体时钟回环证据；其他现场帧率应按实际配置单独验证。

播放时灯光只走时间码：有灯光的歌播放时由 Windows 原生音频引擎发送 MIDI 时间码，控台上这首歌的时间码节目按时间跑灯；软件不再在播放中经网络或 MIDI 逐个发 Cue。歌曲里保存的“控制方式”只影响编灯时的同步、试听，以及 P1 跟随工程在灯光工作台里的预听。停止播放时，如果连着控台网络，会关闭这首歌用到的执行器；没连网络会提示无法发送关闭。MTC 不再提供开/关按钮。

### 5.5 灯光状态与开播前检查

节目单和灯光工作台为每首歌显示灯光状态：

| 状态 | 含义 |
| --- | --- |
| 可演出 | 控台时间码节目已确认配对，起始码和帧率已核对；播放时发时间码，控台跑灯 |
| 编灯中 | 有改动还没同步到控台；现在播放会跑控台上的旧版本 |
| 需处理 | 配对失效或未确认、起点不一致、帧率不对等，悬停查看原因 |
| 未确认配对 | 有起始码但控台节目尚未确认配对；过渡期仍照发时间码 |
| 未匹配 | 控台上没有这首歌的时间码节目 |

点歌、快捷键或空格从停止开始播放前会检查：“编灯中”“需处理”，或“可演出”但时间码端口不在、起始码或帧率不对时，弹出“无灯光播放 / 取消”，原因记入日志。没有操作员在场的开播（曲尾自动下一首、MIDI 控制、跳曲）检查不过时，直接无灯光播放并标红。灯光路线在开播前定好，同一首歌的定位、循环沿用，不中途切换。

## 6. P1 跟随

### 6.1 配置流程

1. 在 P1 整理并保存 `.hia` 音频工程。
2. 在联动台保存 `.tblink`，选择 P1 跟随并读取当前 P1 全部音频。
3. 检查歌曲与列表；重复读取同一音频时保留已有编排。
4. 在联动台编排画面和 Cue。
5. 生成独立的 `*.联动台.hia`，核对新增、更新和移除结果。
6. 在 P1 手动打开生成的文件一次，配置真实 MTC 输出和联动台输入。
7. 恢复自动监听，在 P1 点击歌曲，从明确映射的开头启动联动。

原 P1 工程保留。联动台没有确认可用的 P1 热重载接口，不会强关原有 P1 或用坐标点击伪造重载。

### 6.2 跟随规则

- 软件按已分配的原生时间码区间识别歌曲，不凭相似名称或位置猜测。
- P1 自动选歌当前限制为 24、25、30 fps，不开放 29.97df 自动映射；30 fps 有限定实测。
- P1 暂停和停止均可能不发 MTC，仅凭时间码不能区分两者；默认冻结并暂停活动视频。
- 同位置继续、明确切歌或从头重播可按规则恢复/建立新会话。
- 中途首次接入、未知区间、反向或异常跳变不会补发历史动作。
- 点击“停止联动”后，需明确恢复监听，不能依靠迟到时间码偷偷重新启动。
- P1 1.14.2 已有通过兼容修复连接本机 loopMIDI 的记录；端口存在不代表正在发送时间码。
- 自动映射总区间含间隔限制在 15 小时以内，避免已观察到的 P1 高小时字段问题。

## 7. OBS 画面编排

### 7.1 完整场景切换

适合已在 OBS 调好拉腿、裁剪、滤镜和机位的场景。把现有完整场景放入时间线，零秒可作为初始场景，后续点位切换场景。

这一模式不强制切入受管画面，也不执行不兼容的来源变换等动作。旧受管素材可保留，但不会自动转换为完整场景。定位/重播时恢复目标时间之前最近的有效场景，不切到未来场景。

### 7.2 受管素材编排

适合由联动台安排本地视频、图片和已有 OBS 来源的片段。OBS 负责原始媒体播放、图层和合成；联动台发布应用拥有的输入/场景项并控制入点、变换、层序和结束清理。

同一视觉层不允许片段时间重叠。既有用户来源不能被冒领或删除；名称或类型冲突、所有权不明应阻断。底层动作类型存在，不代表可绕过当前模式与所有权检查操作任意对象。

### 7.3 创建来源

媒体库加号/空白处右键提供八类 OBS 来源。填写名称和目标、配置设备或参数、应用并加入节目。设备选项来自 OBS；新来源先作为隐藏草稿，回读一致后应用，取消清理本次草稿。

OBS 保存来源配置，工程保存引用。已应用的外部来源不应被理解为可随 `.tblink` 自动搬迁，也不能把本地撤销等同于删除 OBS 外部对象。

### 7.4 采集预览脚本

在“设置 → 设备连接”导出 OBS 预览脚本，在 OBS“工具 → 脚本”加载 `tblink_preview.lua`。导出和加载是两个步骤，以设备页状态确认是否就绪。

脚本帮助本机摄像头、窗口、显示器来源维持编辑预览，不切换正式场景，不启动推流/录像。当前桥限定本机 OBS；远程 OBS 仍使用原截图能力。已有显示器采集真实预览记录，摄像头和窗口仍需按实际设备确认。

## 8. Cue 与时间线编辑

支持播放/暂停预览、首尾定位、逐帧移动、滚轮平移、Ctrl+滚轮缩放、片段拖动、两侧修剪、切割、复制粘贴、相邻复制及右键菜单。常用媒体剪辑快捷键包括 S 切割、Ctrl+C/V、Ctrl+D；具体作用取决于当前选区和编辑焦点。

Cue 可配置名称、备注、时间、启用状态和动作。现有动作模型包括场景切换、来源显示、变换、层序、滤镜开关、静音/音量、媒体控制、转场、来源截图以及 MIDI Note/CC/Program/MSC。实际可用性由工作模式、目标存在性和权限规则决定。

自动 Cue 使用真实时间的跨越判定。排练首个失败动作阻断后续，直播记录失败并继续后续动作；两者均不自动重试失败动作。

## 9. 灯光编排与文件交换

### 9.1 编辑范围

灯光时间线独立运行，不要求安装 REAPER。支持灯光、MIDI、控制曲线轨道，名称、颜色、分组、静音、独奏、锁定与排序；支持片段移动、修剪、拆分、合并、多选、批量编辑和跨节目剪贴板。

可在灯光片段双击打点、拖动事件，播放时按 M 打点，并选择固定 Cue 或按已读 Cue 列表连续打点。属性中设置 Cue 编号、Sequence、Executor、动作与标注；节目标注与控台原生 Cue 名称分别保存。

MA2 Master 点支持时间和值编辑、时间线曲线反馈及同步。主推杆的原生量化和采样表现仍受控台格式限制，不能把画出的曲线视为任意精度的物理推杆回放。

### 9.2 节拍与曲线

支持基础 BPM、拍号、变速点、保持速度/渐变至下一点、时间锁定与节拍锁定、循环区域、标记、量化及模板。渐变改变节拍锁定事件的实际时间，时间锁定事件保持其绝对位置。

曲线处理包含边界连续性与复杂转换保护，无法可靠转换的情况明确报错，不静默改变形状。循环尾部与暂停/定位的音符释放已有专门处理，但物理输出仍需验证。

### 9.3 试听、联动与录制

默认音乐编辑用于听歌和编排；明确选择“音乐与灯光联动”后才输出设备。暂停、定位和结束会处理应用发出的活动音符。录制可接收 MIDI 及部分 MSC 反馈，结束形成可编辑录制片段。

MSC 反馈缺少可靠 Sequence 绑定时保留原始消息并报告，不猜测序列。MIDI 命令被 Windows 接收仅说明发送通路完成，不提供灯光执行回执。

### 9.4 文件交换

| 格式 | 当前用途 | 限制 |
| --- | --- | --- |
| `.mid` / `.midi` | 导入/导出音符、CC、Program、压力、弯音、SysEx、节拍和标记等 | 受标准 MIDI 时间网格及消息精度约束 |
| `.tblight.json` | 本软件灯光编排、模板及绑定数据交换 | 仍须核对新电脑的设备和目标绑定 |
| `.rpp` | 导入 REAPER MIDI 编排、节拍、区域、轨道状态、循环、偏移、倍速及已支持 Take | 不导入完整混音、插件、所有媒体与所有 RPP 变体 |
| MA2 Timecode XML | 检查、转换与限定对象同步 | 不是完整 MA2 Show 无损导入 |

导入先显示转换预览和警告，确认后追加到当前灯光编排，可撤销。RPP 引用外部 MIDI 时应同时提供相应文件；缺失或同名歧义不能随意替换。

渐变节拍和区域可借助本软件 MIDI 扩展保存更多信息；其他软件可能只看到阶跃节拍近似或区域起点。不能把本软件自身往返一致写成跨软件无损兼容。

## 10. MA2 连接与双向同步

### 10.1 连接配置

在“设置 → 设备连接”选择本机 onPC 或网络目标。网络档案可保存多台控台，最多 128 项；启动只连接最后选定目标，不表示同时向全部控台发送事件。

网络配置包含 IP、命令端口、监视端口、用户与安全保存的密码。发现功能只读识别 TCP 特征，不猜登录账号；默认搜索受限本地子网及保存地址，不能保证发现所有跨网段设备。MTC 端口、事件输出端口和 MSC 设备号需要分别核对。

导出配套 MA2 插件后，按随附说明安装。TCP 开放、登录成功、插件可用、读取成功和写后核对是不同状态；版本能力检查通过不等于全部功能已适配。

### 10.2 同步工作流

1. 停止音乐与灯光播放，确定目标连接和 Timecode 编号。
2. 读取目标 Timecode，或明确创建新的专属 Timecode。
3. 读取执行器及关联 Cue，核对 Sequence/Executor 绑定，导入当前节目。
4. 在本地编排后重新读取控台，检查事件对应关系；重复 Cue 的含糊身份由操作员确认。
5. 查看“共同基线、本地修改、控台修改”的三方差异，对冲突明确选择保留哪一方。
6. 核对帧对齐及合并结果，执行同步。
7. 软件复核版本及绑定范围、写前备份、写入并回读；只有回读确认后才更新本地基线。

支持范围已有事件时间、小数 Cue 引用、执行器动作、轨道名称/静音/顺序/增删以及 Master 点等限定本机验证。当前同步界面按 30 fps 对齐，不能将其视为任意控台时间单位已全面验证。

播放期间禁止工程写入。目标改变、工程改变或旧预览过期后须重新读取。写入超时或结果不确定时保留备份信息，先回读确认，不自动重发、不自动回滚。

### 10.3 当前验收缺口

本机 onPC 文件桥已有专属对象写入、备份、回读和还原记录；真实 TCP 监视协议及本机发现也已有读取证据。但允许远程登录的实际账号、命令端口登录、完整网络 SYNC 往返和实体控台全链路尚未签收。

## 11. 异常处理与现场操作

| 现象 | 含义与处理 |
| --- | --- |
| MIDI 端口可见但没有时间码 | 核对发送端、输入映射、帧率及真实 quarter-frame；不能改用假时钟掩盖 |
| 时间码端口播放中被拔掉 | 标红“Windows MIDI 输出失败”，音频继续；插回后本首不自动恢复，停止后重新播放即重新打开端口 |
| P1 暂停后画面冻结 | 属于保护行为；同位置继续或从明确开头重播，主动停止后需恢复监听 |
| MTC 丢失/异常跳变 | 冻结自动 Cue；手动跟随需要明确重同步，未知位置不补执行 |
| 内部音频停滞或 MIDI 严重滞后 | 停止内部播放和时间码，显示错误；修复后明确重播 |
| 原生音频引擎意外退出 | 显示“播放引擎已退出”；再次播放会启动新的引擎 |
| OBS 断线 | 音频和时间码继续，画面动作标红失败；用“一键连接”重新连接后，按当前位置重建画面（暂停中则在暂停位置重新准备），并标红记录 |
| 界面进程崩溃 | 正在播放的节目在后台继续（音频、时间码、OBS、灯光），窗口自动重新加载并接管；未保存的修改按恢复副本提示找回。一分钟内再次崩溃时改为询问是否重新加载 |
| 主进程意外错误 | 记录原始错误并提示，软件继续运行，播放不中断 |
| 停止清理失败 | 保持错误状态，确认外部状态后再次停止处理，不把失败当完成 |
| 素材缺失/校验不符 | 用工程菜单「找回缺失素材」选择原工程文件夹，或重新导入并核对编排；不用缓存代理替换正式素材 |
| MA2 同步未确认 | 记录备份位置，重新读取目标，核对是否已部分写入 |
| 更新不可用 | 检查当前安装版本及更新凭据；保存工程后再执行更新 |

日常开场顺序：打开并核对工程 → 确认主控模式 → 连接必要设备 → 核对画面和正式音频 → 预检 → 排练暂停/定位/停止 → 开展演出。结束时停止联动并确认受管输出清理，保存工程。只允许正常关闭本次由联动台启动且所有权明确的外部进程，不强杀用户原有程序。
