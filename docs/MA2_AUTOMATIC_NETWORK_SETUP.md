# 0.4.30 自动连接与电脑网卡配置

## 0.4.31 现场连接反馈修复

现场截图为电脑 `2.0.0.97/24`、控台 `2.0.0.98`，命令和监视 TCP 端口均超时，尚未进入账号验证阶段；另一次自动连接暴露了 IPv4 Zod 校验 JSON。截图不足以确定端口超时由错误网卡、线缆、控台服务或防火墙中的哪一项造成。

- 自动和手动连接统一校验输入，接受两端空白与全角数字/句点，其他无效地址给出中文提示。拒绝带端口或内部不可见字符的地址，不猜测其含义。
- 主进程从当前网络方案或本次 Windows 启动的地址记录解析电脑源地址，重新核对网卡 GUID、连接状态和地址仍然存在，再将源地址绑定到两个 TCP socket；不存在时中止，不改走其他地址。没有软件配置记录的连接继续由操作系统选路。
- 手动“保存并连接”也执行网卡准备，使界面所选网卡和电脑 IP 实际参与连接。
- 同网段提示不再声称通信已通；超时显示选定的电脑地址，不把未绑定 socket 的 `0.0.0.0` 当作实际本机地址。
- 本机隔离 KM-TEST 适配器验证：临时添加 `192.0.2.200/24` 后 Windows 自动建立 `192.0.2.0/24` 的 on-link 路由，`Find-NetRoute 192.0.2.201` 选中该适配器。随后删除测试地址成功，没有修改实体网卡。没有证据表明原实现漏建路由，本次未添加额外路由操作。

本轮仍未连接现场实体控台，不能把上述修复或模拟测试视为现场连通验收。

0.4.31 验证结果：`pnpm verify` 通过（967 项通过、40 项跳过）；打包版 4 项 Electron 用例通过，涵盖无效 IP 中文提示、全角输入、配置/连接顺序、取消授权、恢复、保存目标直连、手动连接与错误布局。上述界面测试的外部网络接口为模拟。NSIS 安装包与版本元数据、发布清单检查通过，产物位于 `apps/desktop/dist/0.4.31/`。

主入口为“自动连接控台”，手动连接与网卡设置收进备用区域。已保存/填写的控台 IP 先检查电脑网络；首次使用先进行只读发现。当前没有已知地址、且控台不响应发现时，仍须提供一次控台 IP，软件不猜测整片 IPv4 网络。

## 流程

1. 读取 Windows 网卡和 IPv4 地址，自动优先选择实体有线网卡。排除 ROOT、SWD、VMBUS 软件网卡自动候选，包括即使报告 HardwareInterface 的 KM-TEST 环回适配器。多张适用网卡要求明确选择。
2. 已在同网段则直接连接；否则生成一个不同于控台及本机既有地址的同网段电脑地址，界面显示网卡、地址和影响。
3. 固定目的的 Windows 管理员授权操作使用 IP Helper `CreateUnicastIpAddressEntry` 增加临时地址，不使用会关闭 DHCP 的 `New-NetIPAddress`，不覆盖既有地址、默认网关或 DNS。等待系统地址重复检测完成；失败清理本次新增地址，清理失败保留恢复入口。
4. 配置成功才尝试控台登录。取消授权或配置失败不会继续登录、自动重试或改选其他设备。
5. “恢复原配置”仅移除本软件记录的新增地址。记录绑定网卡 GUID、前缀及系统启动时间。电脑重启/网卡重置后临时地址可能失效，重新点自动连接可重新配置。

依据：[Microsoft CreateUnicastIpAddressEntry](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-createunicastipaddressentry)、[Microsoft New-NetIPAddress](https://learn.microsoft.com/en-us/powershell/module/nettcpip/new-netipaddress)。临时地址不是永久网络设置。

## 验证

- 963 项单测通过、40 项跳过；类型、Lint、构建及发布产物校验通过。
- 4 项打包版 Electron 测试通过：自动配置先于连接、授权取消阻断、恢复入口、保存地址直连及设置布局。连接与管理员接口采用模拟。
- Windows 原生只读网卡枚举、IP Helper 结构编译/实际回读均通过。
- 另在本机已存在的 Microsoft KM-TEST 环回适配器执行真实配置，使用打包版公开 IPC 增加 `192.0.2.200/24`，读回确认后调用恢复。前后全部网卡 IPv4 地址快照一致，实体网卡未修改；记录为 `network-setup-native-write.json` 与 `network-setup-native-write.log`。测试需管理员权限，不修改实体网络进行自动测试。
- 未对实体控台进行本轮登录/出灯验收；另一台电脑的防火墙、控台账户及网络服务仍可能阻止连接。自动电脑 IP 配置不改变控台本身的网络或权限设置。
