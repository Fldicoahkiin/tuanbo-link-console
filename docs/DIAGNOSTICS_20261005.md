# 异机测试日志与诊断（2026-10-05）

## 操作入口

- **设置 → 设备连接 → 运行日志**：直接在设置内容区显示日志，没有弹窗。可筛选会话、节目、Cue、设备、结果与级别，点击刷新获取新记录；列表最多显示最近 500 条匹配记录。
- **运行日志 → 导出日志**：保存可直接阅读的 `.txt`，包含本机保留的历史会话，不受当前列表筛选限制。
- **运行日志 → 导出诊断包**：保存 `.tbdiag.gz`，将此文件从测试主机发回即可排查。
- **运行日志 → 附加问题说明与灯光数据**：可填写问题描述，并选择附带当前工程已读取的 MA2 原始数据，再导出诊断包。原始数据不存在时无法凭空补齐，需先完成控台读取。此区域默认收起，日志直接显示。
- **打开日志文件夹**：打开当前软件实例实际使用的数据目录下的 `link-logs`，无需猜测正式、内测或开发版本的目录名称。

未激活主机也可以查看、记录和导出日志；该能力不解锁节目输出。异常退出后重新打开软件，仍可导出上次已落盘的记录。导出失败会显示原因，不会显示成功；取消保存显示“已取消导出”。

## “检查并修复”实际范围

原“高级与诊断”已改为 **程序维护**，不再放置日志或诊断导出入口。页面按“联动台预览没有画面”“无法自动启动程序”等问题组织；程序位置按需展开，启动参数等技术项默认收起，等待时间使用秒。

按钮已改名为 **检查并修复 OBS 预览组件**。它检查或部署随软件提供的 OBS 预览桥，并核验连接和真实预览帧；必要时按现有权限与进程所有权流程处理 OBS 重启。它不是 MA2、MIDI 或全部节目的综合检查，也不会修复用户灯光编排。

## 诊断内容与边界

诊断包记录产品版本、Electron/Node 版本、系统、CPU/内存、进程与 GPU 状态、OBS/MA2 连接快照、问题描述及保留的日志。默认不附带原始 MA2 数据；勾选后才添加当前工程的读取缓存。

导出会脱敏密码、凭据、令牌字段及已知秘密值。不打包音视频素材、授权私钥或崩溃内存转储。工程名称、设备名称、网络地址以及日志中的文件路径可能用于排错；包由用户自行保存和发送，不自动上传。

新增启动、界面异常与未处理异步错误记录；保留现有 Electron 子进程退出记录。硬崩溃、断电或磁盘故障发生前尚未落盘的内容不能保证恢复。损坏的单行日志明确标记文件与行号，其余有效记录继续查看和导出，原文件保持不变。

## 验证方法与交付范围

`apps/desktop/test-e2e/diagnostics.spec.ts` 启动真实 Electron 构建，验证设置子菜单、无日志弹窗、实际文本与 gzip 落盘、脱敏、取消、保存失败、未激活诊断能力以及同一数据目录关闭重开后的历史记录。仅保存对话框的路径选择由测试接管，日志 IPC 与文件读写使用实际实现。截图与导出样本保存在 `artifacts/diagnostics-20261005`。

日志单元回归覆盖并发写入、等待落盘、限量查询、完整导出和单行损坏恢复。测试不代表另一台主机或实体控台已验收，也不替代声光画面六小时稳定性测试。

本轮为当前开发树修复，未生成新的安装包；另一台主机必须安装包含这些改动的版本后，才具备上述入口。
