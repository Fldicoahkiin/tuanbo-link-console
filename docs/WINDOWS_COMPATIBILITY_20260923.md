## 0.4.25 MIDI 系统调用卡死隔离

2026-09-24 在 Windows 11 10.0.26200 实际复现。原版和全新配置均出现界面不响应，关闭后的后台进程不退出。只读线程抓取发现 Windows MIDI 枚举停在 `winmmbase!midiInGetNumDevs → wdmaud2 → RPCRT4`。对照实验在进入 Chromium MIDI 前拒绝该调用，菜单、界面计时、关闭及进程退出均恢复。这解释了为什么仅改 CSS 或增加 JavaScript Promise 超时没有解决故障。

- 新增随安装包部署的原生 MIDI 检测小程序：独立进程枚举输入/输出，不打开设备端口、不发送 MIDI。系统调用超过 1500 毫秒由检测程序自行报告并退出；本机实测超时退出码 2，约 1612 毫秒，无检测进程遗留。
- Electron MIDI 权限只在检测成功后放行；并发请求共用检测，失败结果保留，不自动重试。用户在“音频与 MIDI”重新检测时显式复查。系统设备故障不再拖住工程编辑和窗口关闭。
- 各 MIDI 调用处统一呈现中文处理说明。修复原有错误过滤正则不区分大小写而将 `Windows` 误判成全大写系统错误码的问题，并支持跨 Electron 隔离上下文的错误消息。
- 没有禁用 GPU、关闭系统服务、改动系统 MIDI 驱动、控制 OBS 推流/录制或修改用户工程。
