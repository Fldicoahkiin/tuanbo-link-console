## 北极星

在不接管正式音视频和推流职责的前提下，让操作员用一个窗口完成节目选择、Cue 编排、MTC 跟随、OBS/P1/灯光联动、预检和现场排错。

## 当前边界（2026-09-09 用户授权内部主控）

- OBS 是正式画面的制作与输出端；内部模式由联动台正式播放音乐，并接入 OBS。
- P1 跟随模式以 P1 为事实源；内部模式以音乐实际播放位置为事实源，并输出 MIDI 时间码。两种模式不自动切换。
- 抖音直播伴侣是软件之外的登录、直播间和推流端，只采集 OBS 输出。
- 联动台不输出 Program、不采集设备、不控制开播/推流/录像、不自动点击第三方 UI。
- 本地视频、图片和视频内嵌音频的正式播放由 OBS 完成。联动台只在固定名称的受管 OBS 场景内维护自身拥有的媒体输入、场景项、变换、层序和启停，不修改用户其他 OBS 来源。
- `.tblink` 不兼容旧 ShowPackage。

## 数据与分层

`.tblink` 只保存可移植业务定义。本机集成档案保存 exe、MIDI 端口、版本和超时；OBS 密码独立使用 `safeStorage`。层次固定为 Schema/Domain → Registry/Adapters → Stores/Runtime → Components → IPC。

所有 LinkProject 写操作走 Command。工程采用同目录临时文件加原子替换；失败保留原文件并显示临时文件路径。参考音频和本地媒体按 SHA-256 去重，波形为可重建缓存。资源文件夹及素材归属写入 `.tblink`，文件夹父级、无环层级和素材引用在 Schema 层强校验。工程画布默认 1080×1920，可显式切换 1920×1080；现场预检要求 OBS 基础画布完全一致。P1 音频只用于参考波形和试听；时间线中的本地视频、图片及视频内嵌音频发布给 OBS 受管场景作为正式输出，摄像头和采集设备始终由 OBS 管理。

## 执行模型

状态机为 `idle → preflight → armed → running → timecodeLost/paused/error → stopping → idle`。Cue 只在上一有效帧小于 Cue 且 Cue 小于等于当前有效帧时触发。时间倒退、归零、丢失和异常跳变都不会补执行或自动重放。

外部 P1 播放模式下，`armed` 在尚无首帧时持续等待操作员播放，不把尚未开始的节目误判为信号中断；首帧仍必须来自节目开头。接收首帧后，或从当前 MTC 布防时，500ms 断流保护生效。状态进入暂停、丢失、错误或停止时，尚未发送的队列及 Cue 内后续动作失效，恢复后不会重放旧队列。停止清理不受此取消条件阻断。

OBS 使用官方 WebSocket 5.x；允许切场景、场景项、滤镜、输入静音/音量、媒体来源、转场和截图，并允许在“团播联动台输出”受管场景中按所有权规则创建或更新本地媒体输入和已有 OBS 来源的场景项。MIDI 支持 Note On/Off、CC、Program Change 与 MSC GO/STOP/RESUME/LOAD，且每个动作显式引用端口档案；MSC 的 Device ID 与 Command Format 也是动作显式参数。灯光 Cue 不直接驱动灯具，而是通过独立 `lighting-output` 端口档案向外部灯光控台发送 MIDI/MSC；端口或档案缺失必须阻断预检。

## 现场安全

预检必须覆盖工程资源、Cue/动作参数、OBS 鉴权、输出画布、P1 正式音频输入和动作目标、P1/MIDI/MTC、OBS/P1 验收版本、磁盘、凭证解密与日志脱敏。直播伴侣完全不进入联动预检。

外部进程按规范化 exe 路径、PID 和启动时间跟踪。只关闭本次启动项，优先正常关闭，不强杀；OBS 推流或录像时拒绝关闭。
