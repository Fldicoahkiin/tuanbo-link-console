# 授权与更新验收

## 产品规则

- 无有效付费凭证时仅显示激活和购买入口，不挂载工程工作区；主进程对工程、设备输出和运行接口再次检查授权。
- 每次启动联网验证激活码与机器码。凭证缺失、签名篡改、机器不匹配、过期、吊销、联网失败和试用凭证均不能取得新的使用授权。
- 已验证并正在运行的演出允许完成；停止后再次运行必须通过授权检查。已授权打开的工程允许保存，以免到期造成数据丢失。
- 更新采用“检查 → 下载 → 确认重启安装”；当前使用固定 HTTPS 地址、完整安装包及 SHA512 校验，不自动降级、不安装预发布版、不在退出时静默安装。运行中或工程未保存时拒绝安装。

## 可重复执行

本地单元测试覆盖 `license-service`、`license-access`、`secure-profile-store` 与 `update-manager`。浏览器用例覆盖授权页、工作区入口和更新中心；它们使用模拟桥接，不能代替 Windows 主进程验收。

GitHub 手动工作流 `Verify Commercial Windows` 执行：

1. 在 Windows 构建源码，使用真实 preload/IPC 验证空白与损坏凭证都无法创建或打开工程、启动运行、探测集成或检查更新；允许导出机器信息。
2. 从已发布的相同版本 GitHub Release 下载安装包，核对标签源码 SHA、产物清单、字节数与 SHA256。
3. 当前用户安装、同版本覆盖安装，以 Windows UI Automation 读取正式安装版的激活页；不打开调试熔断开关。验证正常关闭与卸载残留。
4. 独立 Electron 进程运行真实 `NsisUpdater`：当前版本不更新，模拟旧版本下载公网 HTTPS 正式安装包并核对 SHA512/发布清单 SHA256；本机夹具返回篡改包，验证真实下载器拒绝它。

更新夹具只在独立验收进程中使用本机 HTTP，不修改产品的 HTTPS 要求，不签发产品授权，不执行安装器重启，也不创建支付订单。日志通过 Actions 保留，当前不依赖已满的 Actions artifact 存储。
