# 多人实时美颜实施记录

## 授权与目标

2026-10-05 用户确认：以像素蛋糕的人像质感为主要标杆，结合抖音直播伴侣的交互；要求多人瘦脸、大眼、美体，免费实现，操作集成到联动台，允许由 OBS 执行处理，并明确要求开始任务。

这项授权允许为选中的 OBS 来源加入本应用自有美颜滤镜，不授权修改其他滤镜、采集摄像头、控制推流或录像。普通 `.tblink` schema v1 和灯光 schema v2 不变。

像素蛋糕的照片精修作为效果参考，不作为运行依赖，不表示可复制其专有算法。像素蛋糕并非所有功能免费，参见其[官方说明](https://wiki.pixcakeai.com/guide/9631.html)。目标是不依赖付费 SDK 或云端按次服务，不能把原型标为已达到其效果。

## 架构

OBS 已有来源 → 自有原生 GPU 滤镜 → OBS 原有场景合成 → 已有 RGBA 预览桥 → 联动台。

正式实现另设分析工作器：读取滤镜处理前的缩小帧，返回带来源实例、序列、时间戳和置信度的逐人关键点与轮廓。渲染端不等待推理；过期数据按明确策略失效。禁止读取处理后画面再分析而造成反馈循环。

Electron 只负责统一参数、风格预设、状态与预览，不对正式视频二次合成。用户进一步明确无需成员绑定：同一来源中的所有人使用同一套参数，不建立成员身份档案。原画对比需要独立的处理前预览，不能通过关闭正式滤镜实现。

## 复现

在仓库根目录的 Windows PowerShell 中运行。已有仓库依赖和原生预览构建链为前提；没有编译器时先按现有项目流程准备。

```powershell
node tools/obs/beauty/prepare.mjs
node tools/obs/beauty/build.mjs
node tools/obs/beauty/verify.mjs 'C:/Program Files/obs-studio'

python -m venv artifacts/beauty-prototype/python
artifacts/beauty-prototype/python/Scripts/python.exe -m pip install --timeout 120 --retries 0 -r tools/obs/beauty/requirements.lock.txt
artifacts/beauty-prototype/python/Scripts/python.exe tools/obs/beauty/detect.py artifacts/beauty-prototype/portrait.jpg --model artifacts/beauty-prototype/face_landmarker.task --output artifacts/beauty-prototype/portrait-regions.json
artifacts/beauty-prototype/python/Scripts/python.exe tools/obs/beauty/make_fixture.py artifacts/beauty-prototype/portrait.jpg artifacts/beauty-prototype/paired.png
artifacts/beauty-prototype/python/Scripts/python.exe tools/obs/beauty/detect.py artifacts/beauty-prototype/paired.png --model artifacts/beauty-prototype/face_landmarker.task --output artifacts/beauty-prototype/paired-regions.json
node tools/obs/beauty/verify.mjs 'C:/Program Files/obs-studio' artifacts/beauty-prototype/paired.png artifacts/beauty-prototype/paired-regions.json
```

`verify.mjs` 可另外接收一张静态图片和对应区域 JSON，执行至少两人的独立区域验证。所有下载有固定 SHA-256；失败不自动重试。测试新建独立便携 OBS，使用随机鉴权，不读取用户 OBS 账户配置。结束核验精确路径、PID、启动时间和输出状态，只发送正常关闭；无法确认时保留进程与身份记录。测试不启动推流或录像。

静态原型 JSON 必须声明 `version: 1`、`mode: "static-fixture"`；每个人包含归一化椭圆 `cx/cy/rx/ry`、左右眼中心 `lx/ly/ex/ey`，以及 0–1 的 `smooth/white/slim/eye`。这个 JSON 入口不接受实时数据，也不应给运动素材使用。最多 16 KiB。实时模式使用下面的独立二进制通道。

## 实时链路增量（2026-10-05）

已完成开发原型的完整闭环：

1. OBS 原生滤镜通过官方 filter begin/end API 取得本滤镜之前的画面，以 `Raw` technique 缩小到最长边不超过 640；前面的用户滤镜仍按原顺序参与。
2. 两个 staging surface 交替读回，在下一渲染 tick 排出已采集帧，不等待下一次采集。采集按 67ms 相位调度，避免 30fps 下反复量化成 100ms。
3. `live.h` 使用带当前所有者 ACL 的 `Local\\tblink-beauty-<PID>-<实例>` 共享内存与非阻塞发布锁，每实例只保留最新帧。`transport.py` 只能打开已有通道，并限制每个实例同时一个工作器。
4. `worker.py` 从 OBS 读取 RGBA，不直接打开摄像头，也不使用截图轮询。通过 `analyzer.py` 固定执行全画面及两个重叠分区，映射坐标并合并重复检测。所有人目前使用相同的美颜默认值，不声称有持久身份。
5. 结果携带实例代次、帧序号和原始采集时间，插件核对自己的时间戳环；拒绝错误代次、未来帧、伪造时间、非法浮点值、超人数与显式分析错误。
6. 超过 250ms 的旧结果失效，清除变形并记录状态；这是当前明确的原型保护策略，没有实现过渡淡出。GPU 创建或读回失败会停止采集、显示错误并记录，只有显式切换实时模式才重新初始化。

协议头部和六人结果区总计 360 字节，帧区最多 640×640×4 字节；C 编译时断言帧区偏移，Python 按小端固定布局解析。这个协议为开发工具使用，尚未接入应用 DTO/preload。

### 实机验证与性能边界

最终增量证据：`artifacts/beauty-prototype/acceptance-I6YB5Z/result.json`。

| 检查 | 结果 |
| --- | --- |
| 静止双脸实时分析 | 8 秒处理 119 帧，结果实际改变 OBS 图像 |
| 防止处理后反馈 | 静止输入的全部分析帧只有一种 SHA-256，启用美颜不改变分析输入 |
| 工作器退出 | 超时后输出逐像素恢复原画，平均 RGB 差值 0 |
| 合成平移双脸视频 | 8 秒处理 117 帧，101 个不同原始帧哈希，左侧脸中心横向变化约 0.185 个画幅 |
| CPU 分析 p95 | 静止约 30.91ms；平移约 25.37ms |
| 从 GPU 采集时间到分析结果写回的年龄 p95 | 静止 78ms；平移 63ms；不含后续 OBS/Electron 显示延迟 |
| 原生协议测试 | 重复、代次、时间、序号、NaN、超人数、工作器错误、无人脸、超时均通过 |

曾出现两类失败，均保留测试证据：移除来源后立即同名创建受到 OBS 延迟销毁影响，测试改为使用不同的静态/运动来源名称；全画面单视图在较小人脸素材上检测为零，通过同一失败帧确认是检测尺度问题，再引入固定多视图分析。没有把业务失败隐藏为成功。

原先只在下一次采集时排出 staging frame，结果年龄 p95 为 125–141ms；调整读回时机后得到上表结果。这里依然存在 GPU→CPU 读回，`gs_stagesurface_map` 可能产生驱动等待，不能宣称零拷贝或绝对不阻塞。

验证素材是同一官方照片及镜像构成的两个区域，运动来自 FFmpeg 合成横向平移；没有验证真人舞蹈、遮挡、不同人物身份、四至六人、肤色覆盖、4K、正式机位或长时间稳定性。当前测试画布 640×360/30fps，不是 1080p60 验收。

## 免费依赖与发布门槛

- OBS SDK 固定 32.0.4，保留上游来源及 GPL 许可要求；目前仅生成开发产物。
- MediaPipe 代码采用 Apache-2.0，仍需单独确认所选模型权重、打包资源和各依赖的分发条款，不能把代码许可等同于模型许可。
- `requirements.txt` 声明开发探针直接依赖，`requirements.lock.txt` 记录本次通过验证的全部安装版本；Python 不加入最终桌面运行依赖。发布前仍需安装包哈希锁定和许可证清单。
- 测试图片只下载至忽略的 artifacts，不能加入安装包；目前没有取得再分发素材的依据。
- 当前自写 shader 是有限的传统图像处理；没有像素蛋糕的中性灰 AI、修复模型或美妆素材。
- MediaPipe 多脸模式不自带单脸模式的平滑能力；Windows 原生工作器与短时轨迹平滑需单独实现与测量。用户取消成员绑定，不实现身份注册或识别。
