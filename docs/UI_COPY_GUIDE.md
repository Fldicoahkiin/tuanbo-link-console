# 界面文案规范

2026-10-26 起，界面、提示、报错和日志里给用户看的文字都按这里写。目标是让现场操作的人一眼看懂：发生了什么，接下来该做什么。

## 写法

- 先说结果，再说原因，最后说怎么办。例如：“MIDI 时间码没有发出，音频照常播放。原因：……”。
- 报错里写明用户能做的下一步：去哪个设置页、点哪个按钮、检查哪根线。做不了任何事时说“请导出诊断包发给售后”。
- 用日常口语：“还没”不用“尚未”，“没有”不用“未”，“对不上”不用“不一致”，“检查”或“确认”不用“核对”。
- 不出现代码里的概念：会话、代数、受管、回读、档案、凭证、脱敏、通道、队列、入队等。
- 按钮名用“”，设置页路径用「」，例如：点“一键连接”；到「设置 → 音频与 MIDI」。端口、设备等名称用「」或“”括起来，同一个文件里保持一致。
- 数字和单位之间加空格：“500 ms”“2 秒”“8 KB”。中文里用全角标点。
- 拼接别人的错误信息时，把它放在“原因：”之后，避免出现“。。”或“。；”。

## 用词表

| 旧说法 | 现在的说法 |
| --- | --- |
| 内部主控 | 联动台播放 |
| 本软件 | 联动台 |
| 正式音频 | 音频 |
| 预检 | 开播前检查 |
| 布防 | 待命 |
| 未参与 / 本首无灯光 | 没有发出 / 这首歌不带灯光 / 不联动 |
| 受管 OBS 输出 | 联动台在 OBS 里创建的画面 |
| 回读 | 读回 / 读取控台确认 |
| 原生保留 | 控台原样 |
| 发行方 | 售后 |
| 集成档案 / 端口档案 | 本机设备设置 / 端口设置 |
| 编辑代理 | 编辑预览 |
| 凭证（指密码时） | 密码 |
| 脱敏 | 隐私处理 |

“恢复副本”“视频定位缓存”“播放主控”保留原名。

## 不能改的字符串

这些文字会被代码比较、写进 OBS 或控台，改了会出问题：

- OBS 里的场景和来源名：`团播联动台·…`、`·预备`、`·来源`、`·轨道·`，以及固定来源名“正式音频”。
- `packages/core/src/link-user-error.ts` 识别用的前缀：“连接配置校验失败：”“操作未能完成：”“所需文件或程序不存在”“音频解码或读取失败：”。
- 代码里用 `===`、`includes`、`startsWith` 比较的字符串，例如“名称已写入控台并回读确认”“素材不包含音频轨道”“音乐分析完成”。改之前先搜一遍谁在比较它。

改了文案要同步改测试里的断言。
