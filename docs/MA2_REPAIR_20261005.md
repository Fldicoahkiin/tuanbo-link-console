## 2026-10-05 补充：替代 P1 的操作流程

用户明确要求先导入 P1 即可发送原歌曲 MIDI 时间码，随后连接 MA2 网络载入节目 Cue，并在编辑后自动写回。此次源码与开发构建已调整连接操作；此前的 0.4.41 内测安装包不包含这次调整。

- P1 导入后的时间码输出不依赖先扫描 MA2 或存在本地灯光绑定；已有回归覆盖原歌曲起点。
- 设置中的“连接 MA2 并载入节目 Cue”和本机 onPC 连接，首次自动读取并应用唯一配对；已读 Cue 随工程保存。
- 再次显式连接先核对 Show 目录身份，相同则显示并复用带读取时间的工程缓存，不把缓存声称为实时更新。控台内容变化用“更新控台读取”。启动轮询和切页不会触发本流程。
- 读取后无失效配对、无连接前待提交修改，并且存在可写回时间线时，为这次连接启用编辑后同步。控台连接本身不会提交积压的本地修改。
- 结束编辑后沿用比较、写前检查、备份、写入、回读链路；播放期间暂存，停止后提交。配对失效阻断写入，失败停止且不自动重试。同步状态在工作台可见。
- **尚未完成用户要求的全部能力**：真实 3.7.0.5 混合动作仍缺原始样本；含未知原生动作的时间线不能完整写回，不能宣称所有 Cue 已支持实时反向同步。持续 MTC 精度阻断项仍见下文。

验证证据：`artifacts/ma2-connect-workflow/` 的 Electron 流程覆盖连接后读取、混合截图样本导入、切页与重开；`artifacts/ma2-connect-edit/` 覆盖不同名称的歌曲匹配、编辑位置、自动发起同步、确认回读后更新并保存基线。后者使用历史 3.3 原始导出作为输入、模拟网络回执，**不算实体控台写入证据**。核心回归另验证原始 XML 写前检查、回读、播放暂存与冲突阻断。

## 证据边界

### 2026-10-05 本机 Bug 排查补充

本轮通过新增失败用例复现并修复三类播放缺陷：

1. OBS 未就绪而音频/MIDI 仍在播放时，拖动播放头没有暂停并重置输出时钟。现在与正常联动模式一致：定位先暂停，继续时从新位置加原始偏移发码，不反复连接 OBS。
2. 同一暂停会话连续点击继续，会执行两次音频播放并留下重复计时器。现在合并同一播放会话的在途继续操作。
3. 旧歌曲继续操作的迟到结果会调用暂停，迟到联动错误也可能关闭新歌曲联动。现在在各异步阶段核对播放会话，旧结果不再改变新歌曲状态。

证据：`internal-playback-controller.test.ts` 新增用例先在旧实现失败，修复后通过；最终构建的音频独立播放、工作台、播放中编辑/撤销/重开、时间码异常保护与快捷键桌面复测见 `artifacts/bug-audit-20261005-player-fixed/`。读取恢复、混合截图数据和素材目录的桌面检查见 `artifacts/bug-audit-20261005/`。

初轮另有两处测试脚本失效：旧“取消选择”入口已改为“新建 Cue”；旧时间码脚本仍期待异常后自动 Full Frame 追赶。已分别更新为当前入口，以及“一次定位后异常停止发码、无补发、音频继续”的断言，并修复失败时测试退出被播放状态阻挡的问题。未降低精度门槛，未忽略失败。

## 实际 MIDI 持续测试未通过

本机 Windows、真实 HTML 音频播放时钟、专用 loopMIDI 回环端口 `TBLINK SOAK MTC`。使用缩小/恢复窗口、一次强制 GC、独立进程打开关闭回环端口的负载条件；没有向实体控台发送。

原计划 60 分钟。在约 1834 秒记录中，最大负向误差 **-63.0397 ms**，正向最大 **8.1107 ms**；验收门槛仍为 30 FPS 的一帧 **33.3333 ms**。发送侧误差约 -62.67 ms，不能归咎于接收回调。字节顺序未损坏，音乐仍在播放。明确超限后主动暂停验收音频以结束已失败测试，因此其后“播放意外停止”是测试结束动作，不是现场闪退证据。

已实施保护：调度滞后超过一帧时停止该 MIDI 通道，不补发过期 quarter-frame；音频继续，需要明确重新定位。取消此前自动 Full Frame 追赶做法。新增回归验证不补发、音频不中断；持续测试现在发现精度超限立即报告失败，门槛未放宽。

**这项保护不等于解决了持续发送精度。渲染线程的调度停顿仍是完整交付阻断项，60 分钟验收没有通过。** 下一步需要将有时限的时间码发送与界面负载隔离，同时保持真实音频时钟、暂停/定位取消和不补发历史消息的约束，再跑完整回环。不能只延长超时或隐藏提示。

证据位于 `artifacts/ma2-repair-20261005/mtc-hour/`，包含 `precision-failure.json`、`progress.json`、`delivery.json`、收发字节、长任务与资源采样。该目录保留失败记录。

## 使用与一次采集

1. 首次导入 P1 音频并保存 `.tblink`。以后打开该工程，不必重新选择 `.hia`。
2. 设置 → 设备连接 → MA2 控台，连接后读取。结果属于工程，切页继续；取消保留已经保存的对象。
3. 使用缓存处理歌曲配对。歧义或失效关系需要核对；只补读未完成项不重新全扫。
4. 在节目单选歌曲，再进入灯光工作台查看音频和 Cue。素材库中的多步序列先进入子菜单，单步明确调用控台。
5. 保存本地编辑不表示控台已更新。原生保留导致禁止写回时，继续查看与保留本地修改，不覆盖正式时间线。
6. **采集真实样本：在读取按钮旁点击“导出现场核对包”。** 已有缓存可直接导出，无需再次全扫；没有缓存才需读取一次。包内含原始 XML 和读取上下文，可离线复现。软件不会自动上传该包。
7. 若读取中断后重开提示恢复，查看已读条目并补读未完成项。若检查点损坏，保留工程及旁边的 `.ma2-recovery` / `.ma2-material-recovery` 目录供诊断，不覆盖原件。
