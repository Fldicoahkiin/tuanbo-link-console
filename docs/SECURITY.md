# 软件保护、密钥与后续加固

2026-09-28。目标是防止低成本复制、伪造许可、误发码和泄露服务端秘密，同时保持现场播放的可预测性。Electron 客户端运行在客户可控制的机器上，任何纯客户端方案都不能保证永不破解；源码压缩、混淆和 ASAR 打包都不是加密保证。

## 当前已做与边界

| 对象 | 当前措施 | 剩余限制 |
| --- | --- | --- |
| 收费入口 | 无注册/账号；必需许可；未激活不挂载工作区；产品 IPC 默认检查；拒绝 trial | renderer/MIDI 与主进程仍可被补丁修改，须结合发布签名和实机篡改测试 |
| 签名授权 | 服务端 Ed25519，客户端只带公钥；固定产品和机器；校验时间 | 修改客户端校验逻辑仍可能绕过，不是 TPM 信任根 |
| 激活码 | 128 位随机；SQLite 保存 HMAC-SHA256 索引和 AES-256-GCM 密文，带 AAD | 数据密钥同时承担索引和加密用途；尚未实现有版本的数据密钥轮换 |
| 本地凭证 | Electron safeStorage 保存兑换码和时间高水位；加密不可用则拒绝 | 不抵御本机管理员、调试注入或完整系统克隆；客户/订单数据库无整体应用层加密 |
| 机器码 | Windows MachineGuid 经产品域隔离 SHA-256 | MachineGuid 可更改/克隆，缺少设备私钥挑战证明 |
| 在线服务 | HTTPS 固定 origin，无重定向；10 秒、20KiB 响应上限；后台隔离；审计 | 单机限流在反代后共享；无自动支付，未做生产负载测试 |
| 离线与撤销 | 7 天租约；回拨超过 5 分钟拒绝；迁移等待旧租约结束 | 清空状态/虚拟机快照仍可能规避；已运行会话不因到期强停；旧永久离线文件不能撤销 |
| 发布包 | 禁止 DevTools、导航/弹窗；关闭 Node 调试入口；启用 ASAR 完整性和仅从 ASAR 加载；去掉 source map | Windows 包未实测 fuses 和篡改拦截；尚无正式 Authenticode 签名 |
| 自动更新 | 公司 HTTPS 静态源；完整包 SHA-512；禁止自动下载、退出自动安装和降级；需保存并停止联动后确认 | 摘要与安装包同源，摘要不证明发行人；签名发布者尚未配置；升级期限未执行 |

浏览器回归仅证明真实组件在测试桥下的行为，不能当作 Windows 防破解验收。生产私钥、后台令牌没有在本轮生成或分发。

## 凭证分工

| 凭证 | 保存位置 | 客户端可持有 | 轮换/泄露处理 |
| --- | --- | --- | --- |
| 许可 Ed25519 私钥 | 服务器受限文件，异地加密备份 | 否 | 新 kid 签发，先分发信任新公钥的客户端；保留合法旧许可所需公钥，明确撤销策略 |
| 许可公钥 | 受签名桌面包 | 是 | 属于信任配置，不能由未经认证 API 任意替换 |
| 激活码数据密钥 | 服务受限文件及备份 | 否 | 当前不能直接替换；需要带 key version 的索引/密文迁移及恢复测试 |
| 管理员 Bearer | 运维秘密存储/进程内注入 | 否 | 泄露即吊销并更换，审计订单/核款/迁移；不得作为客户订单凭据 |
| 激活码与签名许可 | 客户机 safeStorage/许可文件 | 是，属于客户秘密 | 隐去日志，丢失按购买证明找回；泄露后按租约规则撤销/换码 |
| 微信 API v3 密钥/商户私钥、支付宝应用私钥 | 后续商户服务秘密存储 | 否 | 按平台流程轮换；与许可签名密钥严格分离 |
| Windows 代码签名密钥 | 受控签名服务/HSM 等与采购证书匹配的设施 | 否 | 独立 CI 权限、时间戳、证书续期；验证真实证书发布者，不能猜名称 |
| TLS 私钥 | Caddy 数据目录 | 否 | 交由证书服务续期，保护目录和备份 |

密钥不放 Git、构建日志、命令行参数、公开静态目录或可下载诊断包。数据库虽加密激活码，订单客户名称等仍是明文，需磁盘/备份加密、最小访问权限和明确保留期限。新签名密钥公钥更新、生产域名调整都通过已验证的软件发布流程。

## 后续顺序与验收门槛

**第一步：商业上线前。** 采购并接入 Windows 代码签名，绑定真实发布者；把现有 `unsigned-candidate-confirmed` 发行检查升级为正式签名发布规则。验证首次安装以及更新签名，不允许仅凭 SHA-512 或 HTTPS 就宣称可信更新。落实备份恢复、私钥保护、反代限流、监控与服务故障流程。`updatesUntil` 与版本资格策略在销售条款明确后实现，避免永久使用与收费升级冲突。

验收：替换 `app.asar` 应被已安装包拒绝；伪造许可、换 machineCode、未知 kid、算法替换、过期凭证均拒绝；错误发布者或篡改安装包不能进入安装；同一笔支付重复通知只能发一组码。最后一项须在真实支付适配完成后验证，当前只有人工核款幂等测试。

**第二步：设备持有证明。** 设备生成私钥，仅把公钥和最小必要机器信息送服务器；服务端短时一次性 nonce 挑战，验证设备签名和重放记录。评估 Windows TPM/CNG 非导出密钥；无 TPM 时显示明确支持策略，不静默降为明文密钥。换机、系统重装、主板更换的政策和恢复流程先定，再实现；机器码哈希不等于彻底匿名化。

验收：复制许可文件或数据库至另一机器不能完成挑战；重复 nonce、超时响应、跨订单绑定拒绝；备份恢复不会倒退最大签发租约；断网在声明的租约内可使用，过期不开始新会话。

**第三步：提高修改成本。** 对实际敏感校验评估小范围原生模块、完整性检查和必要混淆，不重写全部业务，不把服务端私钥藏入 native 模块。先用可重复的补丁样本衡量效果，再决定投入。避免侵入式内核驱动、扫描无关程序或清除客户数据；加固错误不能强杀 OBS/P1、打断已授予的现场播放或删除工程。

每步记录：提交、构建版本、签名身份、攻击/恢复样本、Windows 版本、预期与实际结果。未完成项保留为未验收，不用“防破解完成”替代证据。
