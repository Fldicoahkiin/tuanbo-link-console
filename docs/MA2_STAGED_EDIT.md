# 播放中灯光编辑安全暂存

## 操作规则

- 播放中可以新增、移动、修改和删除本地 Cue；每次修改仍经 `setLightingCommand` 与 document store 执行，自动保存沿用现有工程机制。
- 正在运行的灯光输出保留启动时快照；本地编辑不会重建当前播放输出，也不会直接调用 MA2 写入。
- “MA2 待提交变更”按节目、Timecode 列出新增、删除和修改，显示前后时间、Cue、执行器和静音状态。数据从工程内最后确认的 MA2 基线推导，撤销、重做和保存重开均可恢复，不维护另一份覆盖工程的临时草稿。
- 未绑定轨道、本地备注和素材库名称不是 MA2 待写入对象。需要先在手动同步中明确关联轨道。
- 自动同步启用时，停止后自动重新核对；也可点击“停止并核对提交”。这个按钮先停止播放，绝不豁免播放禁写。正式播放暂停或联动会话尚未释放时仍须停止。
- 自动同步未启用或已经阻断时保留本地变更，用户须在 MA2 同步中回读、处理冲突并重新扫描启用；不因点击播放、停止或定时轮询而重试失败写入。

## 提交与中断

1. 校验工程会话和已扫描 Show 身份，读取每个绑定目标。
2. 检查事件身份，比较最后确认基线、本地内容和控台回读；存在歧义或冲突则阻断。
3. 复用 `Ma2ApplyService` 重新读取控台快照核对预览，合并并验证所有引用，写前再次检查播放状态。
4. 通过现有 SYNC 备份与写入，回读检查实际结果。
5. 只有确认完成且工程、播放会话及本地编辑仍匹配时，才经 `applyMa2ReadbackCommand` 更新本地与同步基线。

写前关闭自动同步或恢复播放不会发送该轮写入；已经发出的写入继续等待回读，不能冒充取消。此时继续编辑、切换工程或关闭同步，均保留当前本地内容并要求手动回读。多条目标按现有顺序执行，已确认目标不会因为后续失败回滚；不能把部分完成报告成全部成功。

播放中历史操作仅开放 `scope: lighting` 的本地灯光编辑命令，其他工程操作保持原有锁定。同步回读本身仍属于独立 LinkCommand，不伪装成本地编辑。

## 验证范围

- `ma2-staged-edit.test.ts` 覆盖真实 document store 命令历史、播放零请求、停止提交、写前变动、冲突、读取/写入/回读失败、恢复播放、写入期间关闭/编辑/换工程，以及保存重开与增删摘要。
- `ma2-auto-sync.test.ts` 和 `ma2-apply-service.test.ts` 继续验证现有自动同步与适配器写前/回读保护。
- `ma2-staged-edit.spec.ts` 与 `lighting-workbench.spec.ts` 验证 Windows Electron 编辑、待提交显示、历史操作和保存。
- 本轮使用模拟控台与本地 Electron，未对实体 MA2 或真实 onPC 发送写入；不作为实机验收。
