# MA2 连接读取回退与修复

## 0.5.16 直播间反馈与修复验证（尚未发布）

直播间使用实体 MA2 3.3.4.3。11 月 18 日导出的这一场日志中，首次准备 MIDI 选曲用了 196 秒，随后读了 57 条时间线和 695 个序列。第二次准备报告控台无需修改，仍耗时约 78 秒，之后又完整读取了相同数量的时间线和序列。同步中四次出现 `network.autoConnect` 参数校验失败，其中两次已经进入写后核对。截图中 Drop.mp3 和跪下.mp4 报错，其余 24 首显示一致。日志也记录了播放期间的等候、读取期间发生修改和网络超时，属于不同情形。

- 修正网络写入后准备选曲时所传的控台地址，按原流程走到真实读回。歌曲失败后只由该歌的修改或手动刷新再次尝试，其他歌曲完成或工程读取进度更新不会触发重写。去掉修改后固定等待 250 毫秒再等轮询的步骤。编辑提交就唤起同步，同一轮的连续编辑合并；控台正在答复时继续编辑，会在这次答复后处理最新改动。
- 重新连接仍检查控台选曲。完整的读取记录可以从工程或逐项恢复文件取回；时间线、素材分别核对地址、Show、软件版本和各自目录。目录相同、数据完整才复用。目录核对不能发现仅修改了 Cue 内容的情况，显示上次读取时间，点“更新控台读取”可重新取全。写入仍以本次真实读回为准。
- 保留连接时的读取顺序。首次读取素材分组核对每条序列，保留逐项保存和错误。工程里的进度分批写入，避免每收到一个序列或时间线就重新处理整份工程。单首同步只读这条时间线引用的序列；定时检查 Show 只取来源，不反复下载素材目录。

## 0.5.15 现场再次失败与 0.5.16 修复

11 月 18 日的新诊断确认软件 0.5.15、实体 MA2 3.3.4.3。登录成功后检查 Sequence 315 在约 15 秒返回超时及清理未确认，随后又出现组件未运行提示。没有取得该序列原始 XML，不能声称已经用现场原数据复现；也没有证据把后一个提示归因于用户切换 Show。

上版只消除了完整灯具数据的网络传输，却保留控台 Lua 对每个灯具 XML 节点的解释执行。大文本填充的模拟和空序列 onPC 测试遗漏了真实密集节点的开销。本机真实 onPC 中，上版算法对约 16 KiB 密集节点扫描并比较需 3.359 秒，256 KiB 已触及 5 秒响应超时。属于软件读取回退，不要求用户删减灯光内容。

本次实现保留同一 SEQGO：CueDatas 原样按块比较，外围 Cue 元数据单独解析；每批累计 4 MiB、256 个元数据 token 或约 100 ms 后返回进度。MA 内部指令配额暂停在预算内继续处理，不逐个占用网络往返。写前保留第二次导出完整比较，触发 Assign 只发一次，写后分批完整核对；不会把已写但未确认当成功。批次间仍检查 Show/组件来源。取消和错误关闭扫描文件。只修改读取核对路径，不改变 MIDI、时间码位置、音乐或 OBS。

本机 onPC 3.7.0.5 实测（合成数据，不代表现场总连接速度）：

- 128 MiB 密集灯具内容：扫描及完整比较 96 批，共 2200 ms，最慢一批 33 ms。
- 4096 条 Cue、约 8.8 MB 内容：扫描及完整比较 337 批，共 7120 ms，最慢一批 32 ms。
- 8 条 Cue、约 17 KiB 内容：同一检查 20 ms。
- 真实未分配执行器的自建 128 Cue 序列：通过最终代码的正式网络桥完成 Time → Go、完整备份和读回，再次检查为无需改动；两次合计 3542 ms，不含连接及插件安装。测试后核对对象名称及 Show 会话并删除自建序列。

自动化补充覆盖 33 MiB 密集节点的 Lua 指令预算、4096 Cue、闭合标签每个跨块位置、外围和内部 Trigger 区分、原始灯具/命令变化拒绝确认、取消前后、打开文件关闭、非法确认阶段和旧桥协议。下方为 0.5.15 发布时的历史记录，不是当前现场已通过的证明。完整发行结果见 [0.5.16 发布记录](RELEASE_0.5.16.md)。

边界：实体 3.3.4.3 与实际 Sequence 315 尚未验证；MA 原生 Export 的耗时仍取决于控台自身，不能宣称任意规模恒定秒读。需要完整序列内容的显式编排编辑继续沿用既有完整快照及容量保护，本次没有盲目提高所有协议上限。

## 现场证据

用户由 0.5.10 升级到 0.5.14，实体控台约 30 条 Timecode。诊断实际版本为 MA2 3.3.4.3。登录成功后，`link:ma2-prepare-playback` 持续 480334 ms，最终返回 `Bridge file exceeds limit`。此时网络状态仍已连接；不是 OBS 或播放检查拒绝，也不是连接 IP 错误。日志未记录超限对象编号，因此不能指认某一条用户序列。

## 回退链路

0.5.10 直接读取时间线目录和 Cue 元数据。0.5.14 在同一入口前增加了 MIDI 选曲准备，枚举 Timecode 范围、准备辅助选曲对象，并为每个歌曲引用序列通过 SEQUENCE 读取完整 XML。完整 XML 包含本次无需传输的灯具数据；远程分块传输随数据量增加，本机文件捷径掩盖了现场代价。插件原完整读取上限为 32 MiB，因此这一步既会慢，也会在大对象处失败。原目录读取没有相同的完整灯具传输需求。

准备阶段此前只设置 busy，没有进度编号、进度回调或取消句柄，所以用户看到没有变化的读取进度。两处问题在同一入口叠加。

## 实现与保护

- 保留唯一 `Ma2MtcSelectionService`，以 SEQGO 替换其完整序列网络读取。目录、歌曲 Cue、执行器和辅助选曲规则沿用现有实现；其余显式内容编辑的完整读取协议不扩展上限。
- 控台以 32 KiB 块扫描导出，不把完整序列载入 Lua 字符串或传回电脑。检查导出编号与直接 Cue Trigger；第二次导出逐字核对，已有 Go 序列完成后清除临时导出。
- 需要改 Time/Follow 的序列保留完整原备份，原位 Assign 后重新导出；除导出时间戳、直接 Cue Trigger 和结构性排版空白外逐字比较。CuePart 中灯具、Fade、Delay、命令和命令空白均参与比较。不做整序列重新导入，不重建灯具内容。
- 同次共享序列去重，明确重新连接仍重新核对。Show 和桥接会话校验在读取前、写入前执行。写前步骤可以取消或因播放开始而停止；一次已发出的写入和其读回在同一步完成，不自动重放。
- IPC 使用独立类型化请求，复用现有读取进度与取消任务；报告具体时间线/序列、已完成数量，失败和切换工程释放本次任务。错误保留具体对象上下文。
