# MA2 连接读取回退与修复

## 现场证据

用户由 0.5.10 升级到 0.5.14，实体控台约 30 条 Timecode。诊断实际版本为 MA2 3.3.4.3。登录成功后，`link:ma2-prepare-playback` 持续 480334 ms，最终返回 `Bridge file exceeds limit`。此时网络状态仍已连接；不是 OBS 或播放检查拒绝，也不是连接 IP 错误。日志未记录超限对象编号，因此不能指认某一条用户序列。

## 回退链路

0.5.10 直接读取时间线目录和 Cue 元数据。0.5.14 在同一入口前增加了 MIDI 选曲准备，枚举 Timecode 范围、准备辅助选曲对象，并为每个歌曲引用序列通过 SEQUENCE 读取完整 XML。完整 XML 包含本次无需传输的灯具数据；远程分块传输随数据量增加，本机文件捷径掩盖了现场代价。插件原完整读取上限为 32 MiB，因此这一步既会慢，也会在大对象处失败。原目录读取没有相同的完整灯具传输需求。

准备阶段此前只设置 busy，没有进度编号、进度回调或取消句柄，所以用户看到没有变化的读取进度。两处问题在同一入口叠加。

## 实现与保护

- 保留唯一 `Ma2MtcSelectionService`，以 SEQGO 替换其完整序列网络读取。目录、歌曲 Cue、执行器和辅助选曲规则沿用现有实现；其余显式内容编辑的完整读取协议不扩展上限。
- 控台以 32 KiB 块扫描导出，不把完整序列载入 Lua 字符串或传回电脑。检查导出编号与直接 Cue Trigger；第二次导出逐字核对，已有 Go 序列完成后清除临时导出。
- 需要改 Time/Follow 的序列保留完整原备份，原位 Assign 后重新导出；除导出时间戳、直接 Cue Trigger 和结构性排版空白外逐字比较。CuePart 中灯具、Fade、Delay、命令和命令空白均参与比较。不做整序列重新导入，不重建灯具内容。
- 同次共享序列去重，明确重新连接仍重新核对。Show 和桥接会话校验在读取前、写入前执行。写前步骤可以取消或因播放开始而停止；一次已发出的写入和其读回在同一步完成，不自动重放。
- IPC 使用独立类型化请求，复用现有读取进度与取消任务；报告具体时间线/序列、已完成数量，失败和切换工程释放本次任务。错误保留具体对象上下文。

## 验证记录

- Lua 真执行模拟：33 MiB Go 和 Time 序列通过，网络请求只含元数据及摘要，单次少于 12 条命令；大数据不进入网络响应。
- 30 条时间线共用一个 33 MiB 序列：连续两次明确连接，每次只检查一次该序列，完成数量为 30/30；已经准备好的控台不产生额外写命令。
- 覆盖非 Go 原位修改、完整备份、写前并发修改、写后灯具/命令变化、错误编号/空导出、密集 XML 节点跨块、Show 切换、播放开始、取消释放及取消后重新读取。
- 前端入口覆盖进度更新、异常清理后重连、工程切换取消旧任务。
- 本机 onPC 3.7.0.5 通过真实 Telnet 网络路径（禁用本机文件捷径），只创建未分配执行器的测试空序列。非 Go 修改及再次 Go 检查读回成功，两次合计 633 ms（不含连接及插件升级）；测试序列核对所有权后删除。测速记录保存在本机 artifacts，不提交用户 Show 或诊断包。
- 完整本地检查通过：4321 项单测、另 83 项按环境跳过；34 项发版脚本测试；类型检查、lint、正式模式构建和构建内容检查。独立 Windows 换行/定时器检查再次全通过，云端 Windows 单测 4324 通过、80 跳过。软件更新源、GitHub 和官网均已发布，详见 [0.5.15 发布记录](RELEASE_0.5.15.md)。
- 桌面仍有此前的候选版实例，启动器没有切换该实例；此次未将旧窗口当成新版 UI 验收。进度及取消入口由运行时回归覆盖，本机真实设备验证直接调用同一主进程实现与当前 Lua。

现场实体 3.3.4.3 尚未安装候选版验证，30 条模拟与本机 onPC 不等于实体已通过，也不能给现场读取时间作保证。零秒 Cue 和预滚的既有限制保持，详见 LIGHTING_WORKFLOW.md。
