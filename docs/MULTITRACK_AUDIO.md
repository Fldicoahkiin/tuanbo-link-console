# 多音轨与视频原声（0.4.2）

## 使用

先保存工程，停止播放，再从素材库将视频拖入时间线。程序检测并提取视频原声，在拖入位置生成独立音轨；已有歌曲音频会保留。每次添加的视频各有一条音轨，最多 64 条。

- 音频轨道与左侧标题逐行对齐；拖动片段改变位置，拖动两端裁剪，支持节拍和时间线吸附。
- 点击音频片段后，在音频属性中设置位置、素材入点、时长，或在播放头处分割。
- Delete 删除选中的音频片段；轨道标题右侧垃圾桶删除整轨。最后一条音轨也可以删除。
- 视频和提取出的原声是独立片段，后续移动或删除其中一个不会修改另一个。视频默认关闭内嵌音频，防止原声重复播放。
- 新增视频及其原声为一次撤销操作；后续音频编辑、删除支持撤销与重做。
- 没有音轨的视频只添加画面并明确提示；读取或解码错误会显示失败，不生成假波形或静音轨道。

新增和编辑音频需要处理实际音频文件。处理期间请等完成再添加下一段视频；工程或播放状态改变时取消写入，防止将旧操作应用到新工程。

0.4.3 支持旧工程中只有视频、尚未设置歌曲音频的节目：点击节目卡片播放时，先从已有且未关闭原声的视频恢复独立音轨，再由更新后的播放控制器执行正常预检和播放。恢复保留各视频的时间线位置、素材入点和裁剪长度，且可一次撤销。已明确关闭或分离原声的视频不会自动恢复，防止删除音轨后又被加回来。开发环境更新后需要完整重启后台，新旧 IPC 契约不能混用。

## 实现与工程兼容

每条音轨保存独立源文件、源文件哈希和片段范围，存放于 `referenceAudio.timeline.tracks`。所有工程修改通过 `LinkCommand`，异步提取结束后校验文档身份与修订号。严格的旧版 `timeline` 契约会拒绝多音轨工程，避免旧程序打开后静默丢失音轨数据；不要用旧版本覆盖保存。

编辑后用 FFmpeg 按 48 kHz 双声道渲染真实混合音频。单轨保持原始增益，重叠峰值使用延迟补偿限幅；主控播放混合音频，以实际播放位置驱动 MTC、灯光 Cue 和监测频谱。时间线空隙写入真实静音，源文件入点与片段位置分别保存。节拍分析与标记基于当前混合音频；修改音频后需重新检测。

内部主控播放只对所选节目进行资源、波形及动作预检，未完成的其他节目不会阻断当前歌曲；切到未完成节目仍会明确阻断。P1 / 全工程预检仍检查整个节目单。

## 验证边界

自动测试覆盖真实 FFmpeg 双声道混音、时间线间隙、已有音乐追加视频原声、重复出声保护、无音轨视频、切换工程期间取消导入、原子撤销及删除最后一轨。浏览器隔离工程验证轨道对齐、选轨、分割、移动、删除和撤销。未将这些测试视为 MA2 控台或现场 OBS 全链路验收。
