## 用户主流程

连接 MA2 → 读取控台灯光到工程中已有音频 → 按原始时间码唯一配对 → 在歌曲中查看 Cue 与音频。首次 P1 导入的音频、原始起点保存在工程；之后不要求重新选择 `.hia`。设置页只保留连接、读取概况与诊断入口。工作台的控台时间线列表沿用控台名称，选中已配对时间线同步选择对应歌曲；右侧以时间、执行器、序列/Cue、动作、原始名称列显示事件，下方保留音频波形。节目仍在节目单切换。

不能只凭截图确认哪首音频对应 mei-nan；截图没有 P1 原始起点数据。代码不再要求歌名相同，也不按序号配对。完整事件范围仅落入一个已确认歌曲区间时自动关联；区间重叠、未知起点、未正确导入裁剪音频时保持待核对。

## 已证实的代码根因与改动

| 根因 | 本轮改动 |
| --- | --- |
| Ma2CatalogSettings 的 useState 保存目录、失败、选择状态，卸载及上下文变化会清空 | 读取任务转为独立 store；结果、XML、目录、配对、失败、筛选及选择通过 LinkCommand 保存到 schema v2 工程；切页不取消任务，切工程才取消，结果不会写入其他工程 |
| readMa2Programs 与 ma2-import 遇任一未转换动作就拒绝整个 Timecode | 保留完整 XML 与不支持事件路径/原因，同时导入明确可解析的 Cue；原生保留绑定仍可与歌曲关联，素材库和波形可见 |
| 读取目录之外重复预览、全库读取和最后全量复核 | 扫描阶段缓存 XML、预览和索引，按引用序列懒读并在批次内复用；关联直接使用缓存，不再请求预览；保留每条一致性核对 |
| 将转换问题混为读取失败，重复堆列错误 | 分开已读取、已配对、可编辑、原生保留、需处理；单一可筛选列表与选中项详情 |
| 按名称解除时间区间歧义，缺乏起点时按零匹配 | 只用明确原始时间区间作唯一匹配；异常歌曲不阻断其他歌曲 |
| 工作台默认时间比例只展示开头几秒 | 首次打开音频自动适配整首，之后尊重手动缩放；已知 Cue 同时进入歌曲轨道、波形和素材库 |

旧版已经丢失且从未保存的扫描数据不能从新版本恢复。升级后需要一次读取并保存工程；之后切页、关闭重开、缓存查看与继续配对不再要求重读控台。原子保存错误现在附带底层错误原因；没有增加静默自动重试。

## 原生事件能力与保真

| 内容 | 查看 / 本地编辑 | 播放 | 写回 |
| --- | --- | --- | --- |
| 已验证转换范围内的 Goto、Go、Off，及既有 3.3.4 Master 支持 | 使用原始 Cue / 执行器名称，保留明确引用 | 按已有输出模式 | 仍须原有最新快照与冲突校验 |
| 3.7 Master、按键释放、Learn、Manual XFade 等未验证事件 | 原始事件表可见；不伪造成本地 Goto | 使用控台已有 Timecode 执行 | 整条绑定禁止写回 |
| 明确 Goto 引用但存在额外未支持参数 | 投影已知 Cue 位置与引用；额外语义仍标为原生保留 | 同上 | 同上 |
| 时间格式或引用无法解释 | 保存 XML 与原因，保留其他已读取条目 | 不猜测时间或动作 | 禁止残缺模型覆盖 |

原生保留绑定禁止直接 MIDI/网络部分事件重放，Cue 点选仅查看；自动同步跳过这些绑定，手工写回在发出桥接请求前被拒绝。用户修改已知 Cue 的本地位置不会改变控台原始 XML，也不会改变控台已有编排；需要明确显示这个边界。

MA 官方说明 Learn 与按下/释放、Temp 有各自语义，不能当作 Goto；Timecode Offset 作用于整条时间码，Slot 决定外部输入。中途定位能否立即恢复灯光还取决于控台 Status Call 等设置。本次没有自动更改这些现场设置。参考：[执行器按键](https://help2.malighting.com/grandMA2/en/help/key_exec_assign.html)、[Timecode 编辑器](https://help2.malighting.com/grandMA2/en/help/key_timecode_editor.html)。未取得足以验证 3.7.0.5 XML 所有动作的官方格式说明，所以没有删除版本门槛。

## 时间坐标

目前原生转换明确接受的格式仍为 30 FPS：绝对事件毫秒 = (原生 offset + 原生 event time) × 1000 / 30；歌曲 Cue 毫秒 = 绝对事件毫秒 − 已保存 P1 原始起点。没有把第一个 Cue 当作歌曲起点。

截图转录的 offset 14400 对应 480000 毫秒，Goto 原始时间 3 对应 480100 毫秒；假设歌曲原始起点为 480000，则这个 Cue 在歌曲 100 毫秒处。这个假设只用于软件回归，不是现场歌曲配对证据。25 FPS 用例保留原文并明确不转换；其他帧率和现场原始单位仍需原始导出核实。

P1 导入会实际把源文件 cut_start/cut_end 裁剪为导入音频，导入音频位置零已经对应裁剪后开头。原 MidiStartTime 单独保存为原始时间码起点，裁剪量不再重复相加；新增 sourceTrim 记录源裁剪范围及是否已应用。旧工程没有保存的源裁剪证据无法反推。裁剪失败而导入完整源文件的歌曲不自动配对。

内部播放输出 = 实际导入音频播放位置 + 原始歌曲起点；测试覆盖非零 480000 毫秒、裁剪 1500 毫秒、音频位置 2000 毫秒输出 482000 毫秒，并检查暂停不继续输出。实际 MIDI 接收、TC Slot、启动/定位/暂停行为及最终出灯仍未通过此次现场验证。

## 缓存与性能

缓存标记控台地址、Show、版本、读取时间，各条目另有读取时间；UI 明示是工程缓存、不是实时状态。取消和个别读取失败保留已完成内容，可以只补读缺失或失败目标，来源/会话改变时拒绝混入旧缓存；不做无限自动重试。

100 条时间线的离线规模用例包含一条读取失败，记录 201 次逻辑桥接请求，配对和 JSON 重开无需新增请求。该用例是内存桥接，**不是实际控台的耗时测量**。真实网络仍有 256 字节分块串行传输成本，本次没有未经实测扩大分块。

新增 metrics 保存总耗时、阶段耗时、逻辑请求数、解码传输量，以及真实 Telnet wireCommands、sentBytes、receivedBytes。尚无新版完整现场 Show 数据，不能给出“半小时已经降到多少秒”的结论。
