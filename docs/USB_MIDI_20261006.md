# USB MIDI 选择与连接修复（0.4.43）

## 问题与证据边界

现场另一台测试主机：P1 显示 Babyface Midi Port 1 与 USB MIDI Interface，联动台浏览器播放路径仅显示 Babyface。用户确认退出 P1 后仍失败，因此不能认定为 P1 占用。尚未取得该主机 Windows 枚举和驱动打开错误，物理 USB/MA2 出灯未验收。

已证实代码问题：设置页自己申请并保留 MIDIAccess；刷新按钮只刷新全局监视器，更新不到该下拉框。原生播放的一键连接也曾使用 Web MIDI 的名单和 open，可能误报或提前占用原生播放目标。原生驱动错误只显示编号。

## 改动

- 浏览器列表统一来自全局端口监视器。手动刷新同时读取 Windows 原生名单，失败清除过期名单，并把两套名单及错误写入运行日志。
- Windows 能枚举但浏览器漏掉的端口仍显示在时间码输出下拉框，可直接选择，标注 Windows 原生。这个明确选择保存端口，并采用 Windows 原生音频/MTC 引擎；不是播放失败后的自动切换。
- 默认音频线路保持默认；自定义音频线路只有能唯一对应 Windows 同名线路才迁移，否则明确要求核对，不能悄悄换音频设备。
- 一键连接对选定 Windows 输出执行真实 WinMM 打开、关闭检查，不发送 Cue 或时间码。检查通过与正在输出分开。共享同一端口的配置只检查一次，失败不自动重试、不改选 Babyface。
- 播放仍按实际音频位置加原始歌曲偏移输出。检查后释放接口，播放时由原生音频引擎打开。
- 打开错误保留端口名及原始错误；Windows 返回资源占用码 4 时显示原因。没有该错误证据时不宣称一定被 P1 占用。
- 原生检查新增 version 1 严格 Zod DTO；只允许端口名，不允许任意 MIDI 数据或控台命令。

## 验证方式

`scripts/verify-midi-selection.mjs <安装后的 exe> <新的 D 盘证据目录>`：

1. 在真实安装版 Electron 中，仅替换 Web MIDI 枚举，重现“没有 USB，点击刷新后出现”的场景。
2. 选择 USB MIDI Interface，确认配置保存；随后选择本机专用 Windows 测试端口 TBLINK SOAK MTC，检查切换为原生路径。
3. 真实点击顶部一键连接；在日志中核对 WinMM 端口打开、释放成功。OBS 连接指向不可用测试地址，不控制用户 OBS。
4. 播放静音 WAV，在真实 Windows 原生引擎中检查 MTC 发送计数、端口、480500ms 偏移及错误状态。
5. 正常关闭与重开，验证端口和引擎选择保留。

浏览器缺项属于注入复现。Windows MIDI 检查与发送使用本机专用虚拟测试端口，不能替代现场 USB 驱动、线缆及 MA2 收码/出灯验收。静音音源也不证明实际听觉输出。

## 现场操作

设置 → 音频与 MIDI → 时间码输出选择 USB MIDI Interface → 一键连接 → 播放歌曲。选择保存后不必每次重设。P1 原始起始时间继续随导入工程使用。

仍失败时，运行日志会保留 Windows 与浏览器各自看到的输出列表及实际打开原因。通过“运行日志 → 导出诊断”带回测试主机证据，不能仅据“未连接”猜测占用或驱动问题。

本次没有完成实体控台验收，也没有把这次短时回归作为六小时全链路验收。
