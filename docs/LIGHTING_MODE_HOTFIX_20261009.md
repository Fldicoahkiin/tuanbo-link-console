# 灯光模式切换与时间码提示修复（0.4.46）

## 修复范围

- 连接状态栏不再通过播放编译器检查端口。带原生保留事件的工程在切换网络/MIDI 模式、保存后重新打开时，不会因为“不能部分重放”的播放校验而导致渲染崩溃。实际播放仍拒绝不完整重放。
- 原生播放引擎的所有 MIDI 输出均按 Windows 原生路径检查，包括与 MTC 使用不同接口的灯光 Cue。输入仍按 Web MIDI 检查；没有自动更换引擎、端口或重试。
- React 错误边界显示具体错误并记录组件堆栈，暂停该工程自动重开。重新进入工作区前，如有未保存修改，必须先完成另存备份；取消另存则停留原处。工程原文件不删除。
- 时间码配对未核对时，只显示准确的未发送提示，不再同时附加“按开关输出”的通用说明。播放器提示在准备结束后显示，并在同一通知位置更新，避免多条累积。
- 输出菜单提供“核对控台时间线”入口。原生保留工程不再被错误建议切换网络直控。
- 网络与 MIDI 直控按当前本地时间线执行，不受旧时间码配对的无关限制；原生保留事件的独立保护仍然生效。切换模式不会自动确认配对。

## 用户截图对应的工程状态

只读检查本机工程，发现旧关联证据对应 202 秒音频，现用歌曲的音源与时长已经改变，配对处于 `stale`。这是实际需要核对的时间码关联，不能用屏蔽提示或强行确认代替。没有修改用户工程、Cue、偏移、音源或控台数据。

两个模式均报错的远端机器没有提供错误堆栈。已修复可复现的原生绑定渲染崩溃路径，并覆盖所有模式切换/重开；不将隔离测试视为该电脑实体 MIDI 已连接。

- 类型检查；1,637 项单测通过，61 项环境相关用例跳过；发布配置 5 项通过。
- Electron 8 项通过：原生/普通工程的三种模式切换、自动保存、完全退出重启、数据保留、异常工程暂停重开后手动恢复；播放连接/断开/空 Cue；待核对时间码重复播放的单条准确提示和关联检查入口；真实 WASAPI 与隔离 TCP 回执的后台调度、暂停恢复及拒绝指令处理。
