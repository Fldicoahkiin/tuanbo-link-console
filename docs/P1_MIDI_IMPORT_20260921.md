# 0.4.8：P1 全条目导入与 MIDI 自动输出

## 行为

- P1 每个歌曲条目进入节目单，保持原始顺序。单个媒体失败不会阻断整个工程。
- `cut_start` / `cut_end` 缺失、非数值、零时长或无效时，从实际媒体解码完整音频读取时长，并显示恢复说明。
- MP4/AAC 尾部差异不超过 250ms 时对 PCM 尾部补静音或截齐，不改变节目总长度和歌曲原 MTC 起点。WAV 按采样裁剪，避免容器包边界造成几十毫秒误差。
- 明显超出实际音频的裁剪范围按完整原音频恢复，保存恢复说明；这种恢复需重新核对音频内容与灯光结束位置，不宣称原裁剪完全保留。写回独立 P1 文件时将恢复歌曲裁剪起点设为零。
- 缺失文件、无音轨或无法解码的歌曲保留为停用的待修复节目，注明原因，不生成虚假音频。补齐原文件并重新导入后按来源标识原位恢复，保留节目 ID，不重复新增。
- 待修复条目写回 P1 时保留原 XML；导出重排后同步更新来源标识。原 `.hia` 不覆盖。
- 内部播放 P1 歌曲或已编排灯光时，未配置时间码输出会检测 MIDI。只有一个有效输出时自动连接；无输出或多个输出时明确阻断，已指定端口丢失不会擅自换口。忽略 Microsoft GS Wavetable Synth。
- 编辑器与播放主控显示实际输出口、帧率及实际发送的 MTC 位置。发送状态表示本机调用发送成功，不代表控台已收到。
- P1 音频工程不包含 MA2 Cue 列表；显示控台 Cue 仍需网络/插件读取。原控台节目可由原歌曲 MTC 驱动，但接线、控台时间码槽与节目播放状态需要现场核对。

## 验证

- `pnpm verify:release`：类型检查、835 项单测（35 项环境门槛跳过）、Lint、构建、Windows 产物验证通过。
- 自动识别 MIDI 的单测覆盖唯一接口、系统合成器过滤、无接口、多接口、实际完整帧/四分之一帧发送、暂停停止发送；正式播放器链路测试通过。
- 音频测试使用真实 FFmpeg / AAC，覆盖超过 40 秒 MP4、非零裁剪、截图所示 9～67ms 尾差与 45ms 超长采样。
- P1 测试覆盖零时长恢复、缺失歌曲占位、全部无可播放音轨、原位恢复、保存重开与导出原 XML 保留。
- 3 项 Electron 端到端测试覆盖一键 MIDI/Cue 发包、P1 正常/零时长/缺失文件混合导入并写回、44 秒 MP4 原声导入及重开。
- 最终 0.4.8 打包产物的 3 项端到端测试全部通过，恢复提示与待修复提示无重叠。NSIS 首装、同版本覆盖、启动、正常关闭、卸载通过，无测试进程或注册表残留。
- 安装包使用隔离用户目录测试。真实 MA2 控台接收与灯光动作尚未现场验收；不把模拟 MIDI 测试当作实机验收。

## 使用

安装桌面的 `Tuanbo-Link-Console-0.4.8-x64.exe`，重新选择原 P1 `.hia` 导入。旧版已跳过的条目不会仅因升级自动恢复，需重新导入。

“已恢复的歌曲”说明涉及完整原音频恢复；“待修复节目”列出缺文件或解码失败原因。后者需要提供可用原文件才能播放。
