# 0.2.16 连续播放与素材清晰度专项

## 范围

用户要求十首带素材节目接连播放，操作员仅在联动台导入、编排素材，在 P1 播放歌曲。当前电脑已有 OBS、P1、loopMIDI 及连接配置。媒体来源由联动台在受管 OBS 场景中创建，不需要操作员在 OBS 添加文件或手写指令。

用户目前没有提供十首实际直播文件。本次独立实机歌单用现有视频建立十项、每项 8 秒的 P1 原生连续播放，验证十个节目和素材生命周期。不能把这项测试描述成十种编码、高码率多层素材或数小时直播已验收。

## 本次修复

- 上一首请求延迟失败不会再中断正在准备的下一首，原问题已用失败回归测试重现后修复。
- 异常/中途首次时间码冻结后，已映射下一首开头或从头重播可建立新会话；同一首持续前进不会无限重试失败准备。主动停止仍须恢复监听。
- 未变化文件复用 SHA-256 校验结果；文件身份、大小、纳秒修改/变更时间变化后重新校验。缓存最多 256 项，校验期间变化的文件拒绝缓存。
- 真实 P1 时间码已证明播放时，不在每次切歌关键路径重复扫描 Windows 进程。初始连接保留进程路径、身份、版本核验；切歌仍检查素材、OBS 库存、凭据和磁盘。
- 已映射工程重开后，生成 P1 联动工程自动识别当前 P1 文件，不要求手写路径。

## 自动化证据

- 十首循环十轮，100 次会话、45,000 个模拟 MTC 样本，逐样本检查节目内帧位置和准备次数；这是逻辑压力测试，不是假装 P1 的实机时间码。
- 十首带视频循环三轮，验证旧素材停止先于新素材启动，最终活动素材为零。外部 OBS 在此测试中为受控替身。
- 慢 OBS 请求期间 MTC 不阻塞、旧请求迟到失败隔离、停止期间准备完成不播放、失败后下一首恢复。
- 十份未变化素材检查十轮仅读取十次内容；变化和期望摘要不符均不能当成成功。
- 全部 267 项测试、类型检查、ESLint、生产构建通过。最终界面测试、安装生命周期、实机日志及摘要随交付提供。

## 实机观察与边界

首轮 P1 自动连续播放十项，十项 OBS 视频均启动成功，前九项在切歌时停止成功，未出现素材动作失败。最后一项 P1 停止发送 MTC 后视频冻结，日志记录 timecodeLost；这是当前暂停/停止共用的保护行为，不能把它描述成已自动判断自然结束。操作员停止联动负责最终清理。

首轮测得 Windows 进程扫描约 810ms，是切歌准备的主要耗时，因此增加上述优化；最终复测数据以随附实机日志为准。

最终 0.2.16 复测：十项全部按顺序启动，素材动作失败为 0。各项从 `idle → preflight` 到素材成功的耗时为 132、118、119、119、114、121、127、117、129、133ms。该数字包含软件预检与 OBS 请求完成，不代表摄像头曝光到直播平台的端到端延迟。重播时 P1 的旧末尾时间码触发保护，随后收到第一首开头后自动恢复第一首，无须操作员解锁。

故障注入：主动断开 OBS WebSocket 后，P1 播放被预检明确阻断，成功素材动作数量为 0，不伪报跟随成功。最终界面回归 15/15；安装、同版本覆盖、启动、正常退出、卸载通过，残留进程/注册表均为 0。

操作员通过联动台“停止联动”及“连接设备并恢复 P1 自动监听”恢复连接后，重新点击 P1，前三项素材再次成功启动，素材动作失败为 0。之后停止 P1 并清理测试会话，恢复交付配套工程。

最终安装包 SHA-256：`0723029A92FFF9EDF7E1AF27B443364A28324D7CFBD1418C847EAE6B08B3ABC4`。

素材保持原文件字节，不做额外有损编码；OBS 正式画面已截图确认。当前原片为 448×960，OBS 画布/输出为 1080×1920，现有布局放大约 2.766 倍，因此不承诺原生高清细节。用户未来导入素材的分辨率、原有压缩、高码率解码和同时显示层数仍需要按实际文件验收。

没有执行 OBS 推流或录像操作，也没有操作直播伴侣开播。没有宣称零 bug、干净 Windows 账户、实体摄像头/灯光控台或长时间直播已验证。
