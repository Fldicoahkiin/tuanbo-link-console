# MIDI 接口占用修复（0.5.4）

## 现场现象（0.5.2 反馈）

- 现场接法：一个「USB MIDI Interface」同时设为时间码输出、灯光 MIDI 输出、P1 时间码输入和灯光录制输入。
- 正式播放的时间码打不开该接口，Windows 返回错误 7（单用户驱动拒绝第二个打开者时返回 4 或 7），P1 也连不上。
- 偶发切歌失败：引擎刚收到新指令就被读时钟，读到上一首的状态。
- 同一份日志里约 146 条「本曲原位置 … 已改变」是 MA2 同步旧检查的报错，0.5.3（c974507、d6915af）已去掉，0.5.4 不再处理。

## 根源

Chromium 的 Web MIDI 在 Windows 上只要页面持有 MIDIAccess，就会打开电脑上全部 MIDI 输入和输出，且一直保持到窗口关闭。编辑器、灯光工作台、录制和顶栏状态都会申请 MIDIAccess，所以界面一打开这些页面，单用户 USB 接口就被界面自己占住。退出 P1 也无济于事。

## 现在的做法

- Web MIDI 权限一律拒绝。界面的 MIDI 全部经主进程 `MidiPortBroker`（`apps/desktop/src/main/link/midi-port-broker.ts`）：每个接口名一个驱动进程，有人用时才开，最后一个使用者关闭后就关；窗口刷新或界面进程退出时全部释放。
- 接口列表由主进程每 3 秒读取一次（只枚举，不打开），变化推给界面；读取失败停止自动刷新，等用户手动刷新。
- 正式播放优先：时间码、动作 MIDI、灯光 MIDI 和一键连接的接口检查在打开输出前先「占用」它。界面对该输出的使用立即关闭并显示原因，占用期间界面不能再打开。驱动进程真正退出后才算接口空出。
- 停止播放时先让引擎停发并释放时间码接口（`stop-mtc`），再归还占用，P1 等其他软件随即可用。
- 同一输出同时设成两种用途、被其他软件占用、电脑上有多个同名或多个候选输出时，提示写明原因和去哪里改。
- 引擎在指令完成后才更新代数，读时钟等到状态稳定，切歌不再读到旧状态。

## 验证

- 单测：`midi-port-broker.test.ts`、`midi-access.test.ts`、`native-player-device-change.test.ts`（占用、停止释放、换接口、占用提示）。
- e2e 用 `test-e2e/midi-ports.ts` 在主进程替换 `link:midi-*` 通道模拟接口；`mtc-soak.spec.ts` 的测量输入改走同一通道，不再能挂钩界面发送，去掉了逐字节比对和「断开不重开」两项。
- 未做实机验收：需在现场 Windows 电脑上确认 USB MIDI 接口在停止播放后可被 P1 打开、播放时时间码正常到达 MA2。
