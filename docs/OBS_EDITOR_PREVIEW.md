# OBS 采集来源编辑预览（2026-09-11）

编辑画布通过 OBS 来源截图显示现有来源及滤镜。正式场景仍由原播放运行器切换。

OBS 的 GetSourceScreenshot 只在渲染截图期间临时增加 showing 引用，不能保证异步采集来源已经就绪。新增本机 Lua 桥在编辑器持续查看来源时保持 showing；不增加 active、不切换 Program、不调整场景项、滤镜或音频，不启动推流与录制。

## 首次配置

设置 → 设备连接 → 导出 OBS 预览脚本。软件打开脚本目录，在本机 OBS 的工具 → 脚本中加载 `tblink_preview.lua`，只需一次。之后从编辑器查看摄像头、窗口或显示器采集时自动保持预览。

导出不等于加载成功。设备页每秒检查当前 OBS 进程写回的状态，显示未加载、已就绪或脚本错误。状态超过三秒未更新就失效；加载、卸载及运行异常均回写状态。旧脚本升级后需要在 OBS 中重新加载。

脚本与通信文件统一放在系统“文档/团播联动台/OBS预览”目录。Lua 通过 `script_path()` 定位文件，并使用 OBS 自带的 JSON 文件接口处理中文路径，不依赖 AppData 目录或 Lua 标准文件 I/O。

当前桥仅支持本机回环地址（localhost、127.0.0.1、::1）连接的 OBS，且需 Windows 内置采集类型 dshow_input、window_capture、monitor_capture。远程 OBS 保持原截图功能，不会操作本机同名来源。窗口关闭、目标失效、设备故障仍可能没有画面，不再把透明截图直接断言为“OBS 未激活”。

## 生命周期与目标隔离

- 通过监听端口确认 OBS 进程 PID，拒绝不属于 obs64/obs32 或存在歧义的端口。
- 每个 PID 使用独立请求文件，写入临时文件后替换；会话和每个来源都有随机心跳标识。文件不含密码。
- 只在观察到新的心跳后保持来源，历史请求文件不会在脚本启动时激活摄像头。
- 最多 128 个预览来源；离开编辑器、切换内容、断线或应用退出后，心跳停止，约两秒内释放桥自身持有的引用。OBS 本身使用中的来源不受影响。
- 不对媒体来源保持 showing，避免编辑预览重启视频或音频。

## 校验与限制

TypeScript 单元测试覆盖并发来源、连接切换期间的迟到请求、目标验证失败和远程隔离；LuaJIT 生命周期夹具覆盖过期释放、旧文件不重激活、会话变化、来源删除和脚本卸载。运行 `python tools/obs/test_preview.py` 使用本机 OBS 自带 LuaJIT，但其来源 API 为模拟对象，不是实机采集验收。

类型检查、Lint、构建与“打开编辑器保留 OBS 原场景”Electron 回归测试通过。仍需首次在 OBS 加载脚本，并核对实际摄像头/窗口/显示器的预览及正式播放。不能把这些模拟测试表述为完整实机验证。
