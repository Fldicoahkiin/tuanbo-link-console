# P1 点击播放自动联动（0.2.15）

> 2026-11-12：这份只作记录。0.5.9 起跟随 P1 搬到主进程，现在的做法和规矩见 [架构说明](./ARCHITECTURE.md) 第 3 节「跟随 P1 时」和 [只有一处实现 · 播放](./ONE_PLACE_PLAYBACK.md) 的「P1 跟随」；下面写到的界面里的文件有些已经删掉。

用户要求保留 P1、只用软件连接，点击 P1 音频后自动控制 OBS。本版本以此更新旧版“每首手动选择并布防”的操作要求。

## 使用

1. 读取 P1 当前工程，保留原有 Cue。未绑定的手工节目与 P1 音频在 SHA-256 完全相同且两边均唯一时自动合并，避免导入后出现没有编排的重复歌曲。
2. 点击“生成点击播放联动工程”，在 P1 打开生成的独立 `.联动台.hia`。原 P1 文件保留。
3. 联动台打开保存的 `.tblink` 后自动监听。点击 P1 歌曲即可自动选节目、检查连接并执行时间线。无需逐首选择和布防。
4. P1 暂停或停止均会停止发送 MTC，联动台冻结 Cue 并暂停活动视频。P1 同位置继续会恢复并将视频定位至真实时间码；切歌和从头重播会先清理旧会话再开始新会话。
5. 点击联动台“停止联动”会清理输出并暂停自动监听。编辑完成后，使用“连接设备并恢复 P1 自动监听”。

## 连接与边界

- 本机通过已验证的 P1 MIDI 兼容修复和 loopMIDI 连接，不需要 USB-MIDI 硬件。端口存在不代表收到时间码。
- 采用 P1 自带 `MidiStartTime`（单位秒）为歌曲分配互不重叠的区间。播放器始终提供真实播放位置，本地时间只用于检测信号超时。
- 首次从歌曲中途接入、未知区间、反向时间码、异常前跳会阻断，不猜测歌曲，不补发跨过的非幂等动作。
- 0.2.16：保护性冻结后，后续收到已映射下一首开头或从头重播的真实 MTC 时可建立新会话；同一首继续前进不会反复重试失败准备。操作员主动“停止联动”仍保持停止，直至恢复监听。
- P1 暂停与停止都不发 MTC，单凭这条链路无法区分二者，默认保留冻结画面；再次点击歌曲即可开始对应会话。需要立即清空时使用联动台“停止联动”。
- 修改歌曲数量、参考音频时长后必须重新生成 P1 工程；不更改音乐的 Cue 编辑仍可直接保存。
- 当前使用 30 fps 实机验收；支持整数 24/25/30 fps，29.97df 自动映射尚未开放。
- 分配的总时间区间（含间隔）小于 15 小时。实测 P1 1.14.2 在 16 小时丢失小时高位，因此明确限制，防止错误选歌。

## 素材清晰度

导入媒体按原文件逐字节复制，不将编辑器预览、缩略图或压缩代理交给 OBS 正式输出。导入前后校验 SHA-256；预检检查媒体文件状态，首次和文件身份、大小、纳秒修改/变更时间变化时重新读取摘要，文件被替换或损坏时拒绝运行。缓存最多 256 项，避免每次切歌扫描全部大视频。

OBS 从工程内原素材路径解码，画布和输出尺寸都检查。放大超过原始像素、OBS 二次缩放会提示。软件不重新有损编码媒体，但不能补回原素材已有的压缩损失或低分辨率细节，也不能保证直播平台编码后完全无压缩。

本机测试素材 `387..MP4` 原始 448×960，现有时间线放大约 2.766 倍。OBS 画布及输出均为 1080×1920。它的画面质量受源文件限制，不能标记为原生 1080p。

## 实机记录（2026-09-08）

- P1 一分钟偏移：3 秒收到 360 条真实 quarter-frame，分钟字段为 1。
- P1 一小时偏移：3 秒收到 360 条真实 quarter-frame，小时字段为 1。
- P1 十五小时偏移：3 秒收到 360 条真实 quarter-frame，小时字段为 15。
- 无手动布防点击 `387..MP4`：自动匹配已有两 Cue 节目，OBS 视频启动；约 4 秒、9 秒、14 秒的来源显示/切换/隐藏返回成功。
- 暂停后 OBS 活动媒体暂停成功，原位置继续后恢复为 running；同曲重播重新触发；点击另一首音频自动匹配另一节目并执行其现有编排。
- OBS 窗口已观察到正式视频画面。现有机位测试使用显示器采集来源，未把它冒称为已验收的实体摄像头。

自动化与安装包验收结果见对应交付审查记录。

0.2.16 连续播放专项：已连接且收到真实 P1 时间码的自动切歌复用已建立的进程身份/版本，不在切歌关键路径重复运行 Windows 进程扫描。首次连接、手动预检仍完整扫描；素材、OBS 库存、凭据和磁盘仍检查。已映射工程重开后，生成操作会自动识别当前 P1 文件，无需填写路径。

最终媒体入点实机修复：OBS 开启“非活动时关闭文件”时，必须先启用输入并等待可播放状态，再设置非零入点。等待解码不会阻塞 MTC 接收。详见 [本次交付检查](DELIVERY_AUDIT_20260908.md)。
