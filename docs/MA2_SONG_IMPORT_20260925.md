# 0.4.32 歌曲灯光导入修复

> 2026-09-26 复审：以下为 0.4.32 历史记录，不能作为现场可用性结论。后续现场截图确认读取约半小时、54 条因原生转换门槛未导入、44 条待核对、切页丢失扫描状态。此前仅保存成功导入的数据，没有保存整个读取流程；模拟验证未覆盖这些问题。本轮修复、证据与未完成现场验收见 [0.4.33 读取流程复审](MA2_READ_WORKFLOW_20260925.md)。

现场反馈：MA2 已连接，目录有多条 Timecode 和事件；读取进度为 0/53，结果区却同时显示 0/90 首歌曲关联。该截图说明已得到 53 条候选配对，不能据此认定没有歌曲匹配。未取得现场原始 XML，因此不推断全部读取失败的具体控台事件类型。

## 实施

- 现有歌曲主入口为“读取控台灯光到现有歌曲”，不读取 P1、不弹 `.hia` 文件选择框。P1 音乐导入为可选折叠区。
- 网络预览不再通过 SNAPSHOT 传输完整序列及灯具参数。只读 Timecode XML、按引用序列读取原生 Cue 索引/编号/名称，并再次核对 Timecode XML；Cue 元数据仍经双读和目录核对。控台写入与双向同步保持原 SNAPSHOT 校验流程。
- 读取时显示当前 Timecode 和歌曲，隐藏尚未完成的结果统计。90 首歌曲的明细默认折叠，配对入口在结果后展开。
- 独立验证每条完整时间线，正常部分通过一个 LinkCommand 应用并可一次撤销，失败项保留目标和明确原因。不丢弃未转换事件后导入残缺时间线，不自动重试。取消或工程改变中止整个尚未提交的读取批次。
- 歌名比较忽略空格、加号、连字符和下划线差异，仍须完整事件时间范围吻合且唯一；重名歧义不自动分配。
- 导入完整时间线时，同时将其中使用的 Goto Cue 引用加入该歌曲的灯光素材库，按序列、数值 Cue 编号和播放位置去重；保留已有素材，不为 Go/Off 凭空生成 Cue。

## 验收边界

本机单测和模拟网络 Electron 测试不能替代现场 MA2 3.7.0.5 的实际全 Show 导入。现场仍有未支持的动作时，本版显示对应 Timecode 和原因，保留其他已完整导入的灯光。不要把成功导入的条数当作实际出灯验证。

验证：`pnpm verify` 通过，970 项测试通过、40 项跳过；5 项打包版 Electron 用例通过（网络接口模拟，P1 解析、音频导入、工程保存、工作台为真实代码）。覆盖部分失败后再次直接读取而不打开 P1 文件、时间线与素材卡片均显示 Cue，以及歌名不同但 P1 起始偏移分别为 3600/7200 秒的配对。该偏移案例保存的歌曲内事件为 0/1500 毫秒，播放与 MA2 绑定起点保持 3600000/7200000 毫秒。内部播放测试另验证音频 1 秒加 3600000 毫秒偏移后输出 3601000 毫秒 MTC。0.4.32 NSIS、版本信息和发布清单校验通过。
