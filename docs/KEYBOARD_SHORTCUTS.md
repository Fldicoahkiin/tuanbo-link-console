# 快捷键

2026-11-11（0.5.9，04 设计 K7；K10 补上剪切、标记、节拍、手动踩点和停用片段的键，2026-11-12）。键位只在一张表里：`apps/desktop/src/renderer/src/link/keys/keymap.ts`。界面上写的键名（工具栏按钮的提示、右键菜单、「定位」菜单）都从这张表读，改表就跟着变。规则测试 `keys/key-routing-rules.test.ts` 守着下面这些用户定下的规则。

状态：已实现，自动化验证通过（单测、类型检查、lint）；**未实机验证**，剪映的键也还没在现场的剪映上核对（见第 4 节）。

## 1. 用户定下的规则

- **停止**（00-order 第 8 节第 1 题，取代 04 设计 4.10）：
  - Esc 照旧停止，按「输入框 → 弹窗 → 拖动 → 页面 → 全局」的顺序轮到它：输入框、对话框、打开的面板和拖动先拿走 Esc。
  - Shift+Esc 是第二个停止键，在哪儿都能停止：对话框开着、拖动中、输入框里、按钮和滑块上。它只停止，对话框不关，拖动不取消。它是“对话框里的键不碰节目”唯一的例外。这个键可以在设置里换（K8，见第 6 节）。录键的输入框（设置里改快捷键的框）照样把它录下来。
  - 「设置 › 播放 › 快捷键 › 单按 Esc 停止」，默认开，每台电脑记住（`localStorage` 的 `tblink.key-switches`）。关掉后单按 Esc 只关面板、取消选中、取消拖动。
- **首页的键不变**：空格、开了「方向键切歌」时的 ↑↓、卡片上的 Enter、每首歌自己的快捷键。↑↓ 换歌只在首页。
- **编辑器和灯光工作台照剪映专业版的默认键**；和剪映不一样的地方在表里写了原因（`differsFromJianying`）。
- **按住 Enter 只算一次**：除了多行文字框，按住 Enter 时重复的按键由路由先拿走，按钮、表单、Go 执行器键、Cue 点和修改框都只收到第一下。

## 3. 和设计（04 设计第 5 节）不一样的地方

- 停止键：设计是“只有 Shift+Esc 停止，单按 Esc 不停”；用户在 00-order 第 8 节第 1 题改成“Esc 照旧停止，加 Shift+Esc，加开关”。所以时间线上的 Esc 默认还是停止，只有关掉开关后才是取消选中。
- 编辑器的 Ctrl+X（K10）：剪贴板复制时照旧记片段是哪一个（粘贴时按它现在的样子），剪切时另外存一份剪切那一刻的片段，片段不在了就粘贴这一份。剪切只做画面片段，触发点不剪切。剪切的片段原来那条轨道要是因为空了被去掉，粘贴到最上面新建的一条。
- N 照剪映是「自动吸附」开关，不是“跳到下一拍”；吸附点里有这首歌的节拍（`songBeats`）。编辑器的开关记在这台电脑上（`stores/timeline-view-store.ts`）。拖动、修剪时按住 Alt 临时不吸附：Alt 从指针事件的 `altKey` 读，不登记按键，松开 Alt 后下一次移动恢复。
- K10 加了上一个 / 下一个标记（Shift+M / Alt+Shift+M）、停用 / 启用（V，只有灯光片段）、手动踩点（Ctrl+J）、上一个 / 下一个节拍（没有默认键）和编辑器的剪切。
- 改停止键、改编辑器的键：K8 做了，见第 6 节。
- K10 和剪映不一样的地方：V 只停用灯光片段（画面片段没有停用这个状态）；Ctrl+J 播放中踩的拍点停了才出现（剪映是马上出现），因为节拍在播放中不写；剪映没有跳到节拍的键，联动台这两项默认没有键；Ctrl+X 不剪切触发点。

## 5. 只能现场验证的

- Windows 上微软拼音、搜狗输入法开着时（焦点不在输入框），Shift+Esc 能停止，也不会切换中英文。
- 在对话框里、拖动中、输入框里按 Shift+Esc：节目停，对话框不关，拖动不取消。
- 按住 Enter：Go 执行器键、「下一首」按钮、Cue 点、修改框都只算一次（实体 MA2）。
- 按住 → 连续逐帧时 OBS 不卡、红字正常。
- 把随时停止的键换成别的（比如 Ctrl+F12）：首页、编辑器、灯光工作台三页都能停，输入框里、对话框开着、拖动中也能停；关掉软件再打开还是这个键。
- 从 0.5.8 升上来：灯光工作台以前改过的键照旧；退回 0.5.8 时那边的键也没变。
- K10：播放中跟着音乐按 Ctrl+J 踩几下，停止后拍点一起出现、提示“写进了 N 个踩的拍点”，Ctrl+Z 一次全部去掉；灯光工作台里同样。编辑器里 Ctrl+X 剪切一个画面片段、挪播放头、Ctrl+V 放回来，OBS 画面跟着对。V 停用一个灯光片段，播放时这段不出灯，控台的时间线上也是停用（实体 MA2）。

## 6. 在设置里改键（K8）

2026-11-11（0.5.9，04 设计 4.11）。状态：已实现，自动化验证通过；**未实机验证**。

- **在哪儿改**：设置 › 播放 › 快捷键。分「停止」「全局」「编辑器」「灯光工作台」「时间线」几组，每一行写着做什么、联动台的键、剪映里叫什么和它的键；和剪映不一样的写了原因。改过的行有「恢复默认」，最上面有「全部恢复默认」。改了马上生效，工具栏提示、右键菜单、打点按钮上的键名跟着变。
- **能改的**：编辑器、灯光工作台、时间线上的键（一个操作可以有几个键，也可以一个都没有），和随时停止的键（默认 Shift+Esc）。剪映没有默认键的操作（上一个 / 下一个节拍）在表里写着“没有键”，自己设。
- **不能改的**（行上写着原因，没有修改按钮）：空格（播放 / 暂停）、单按 Esc（只有开关）、保存 / 另存为 / 撤销 / 重做、复制 / 剪切 / 粘贴 / 全选、删除（Delete / Backspace，和灯光点共用）、首页的键。
- **不收的键**：Windows 和输入法自己用的组合（带 Windows 键的、Alt+F4、Alt+Tab、Ctrl+Space 等，`key-chord.ts` 的 `isSystemChord`）、Esc、Tab、Enter。
- **撞键就拒绝**，并说出是哪个操作占着：同一页上两个不同的操作不能用同一个键（全局的键在每一页都算；编辑器的键只和编辑器页上的比，灯光工作台的同理；时间线的键两页都算）。Ctrl 加字母时，Ctrl+Alt 加同一个字母也算保存、撤销这些工程键。同一个操作在两页各有一份（比如回到开头）不算撞。
- **随时停止的键**：要按住 Ctrl、Alt 或 Shift 再按一个键，或者用 F1–F12；Shift 只能配 Esc 或 F 键（Shift 加字母会在输入框里打出字）；不能是空格、Enter、Tab、方向键、Home / End、Delete、Backspace 这类在输入框里有用的键；不能是系统组合；不能和任何一页的任何键一样；不能空着。
- **S**：给任何一个操作设了 S，“分割改成了 Ctrl+B”那条提示就让开，S 做你设的事。
- **存在哪儿**：这台电脑的 `localStorage`，键名 `tblink.key-overrides`，只存改过的：`{"version":1,"keys":{"lighting":{"lighting.stamp":["KeyK"]}},"stop":"Ctrl+F12"}`。规则在 `keys/key-settings.ts`，状态在 `stores/shortcut-store.ts`。
- **从 0.5.8 搬过来**：第一次打开时，没有 `tblink.key-overrides` 就读一次 0.5.8 的 `tblink.timeline-shortcuts`（灯光工作台的 6 个键），和默认一样的不写，改过的写成灯光工作台的键。旧的键名只读不写，退回 0.5.8 时它原样还在。搬过来的键要是撞了 0.5.9 的新默认键（比如打点设成了 N、K），照旧留着，设置页那一行标出来，请自己改一个。
- **读不出来**：设置页最上面写明原因，这时用默认键；在设置里改一次键或「全部恢复默认」后重新存好。
- **歌曲自己的快捷键**：停止键（Esc、Shift+Esc 和换过的随时停止的键）、系统组合、保存撤销这些工程键不收，和以前一样；是编辑器或灯光工作台页上的键时提醒一句（“在编辑器和灯光工作台里，X 是「…」，在那两页按它不会播这首歌”）。时间线自己的键（比如 Ctrl+B、Ctrl+J）不提醒：焦点在时间线上时本来就不播歌。
- **空格和 ↑↓ 照旧可以给歌曲**（K10，00-order 第 8 节）：这些是窗口自己的键，歌曲的快捷键比它们先算，所以设了以后输入框下面一直写着拿走了什么，比如空格：“空格 也是「播放 / 暂停」的键。设给这首歌以后，在首页和编辑器时间线以外的地方按它就是播这首歌，不再是「播放 / 暂停」。在灯光工作台里，空格 是「播放 / 暂停」，在那一页按它不会播这首歌。”这句话只在 `keys/key-settings.ts` 的 `songKeyNote` 里定，它说的和路由实际做的一样（`key-settings.test.ts` 守着）。

## 7. 守门：按键只有一个监听（K9）

2026-11-11（0.5.9，04 设计 K9）。状态：已实现，自动化验证通过。

- **ESLint**（`eslint.config.mjs` 的 `KEY_LISTENER_RESTRICTIONS`，`no-restricted-syntax`）：在渲染进程里、`link/keys/` 以外，不许 `addEventListener('keydown' | 'keyup' | 'keypress')`、`onkeydown =` 这类属性和 `onKeyDownCapture` / `onKeyUpCapture`。例外只有 `link/keys/`（路由自己）和测试文件（假窗口要挂监听），写在 `KEY_LISTENER_EXCEPTIONS` 一处。
- **扫描测试**（`keys/key-routing-scan.test.ts`）：
  - 用同一份选择器把渲染进程的源码扫一遍，没跑 lint 也拦得住；再查 lint 配置确实在用它。
  - 查 lint 一行看不出来的事：文件里有 `onKeyDown=` / `onKeyUp=` 的，要用 `ownKeys` 说明哪些键归它，不然窗口的键先动手。不用 `ownKeys` 的只有文件里 `ALLOWED` 名单上的几个普通输入框，各写了原因。
- 组件 `onKeyDown` 里不再需要 `stopPropagation`：路由在窗口的捕获阶段先拿到键，冒泡阶段没有别的按键监听。只有祖先元素自己也处理同一个键时才要留，比如菜单（`ui/Menu.tsx`）经 portal 冒泡回打开它的地方。
