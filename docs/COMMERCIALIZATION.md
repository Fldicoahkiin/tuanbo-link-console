初稿：2026-09-21；更新：2026-09-29。状态：授权服务与官网已部署公网 HTTPS，生产销售关闭；真实支付及 Windows 客户端交付验收尚未完成。部署证据见 [COMMERCIAL_DEPLOYMENT.md](COMMERCIAL_DEPLOYMENT.md)。

2026-09-28 最新决策：不建设客户账户、注册、登录或企业成员门户；机器码＋激活码，一码一机，所有产品功能付费后开放，不提供免费编排或试用。以下对应设计已经更新，取代 2026-09-21 的免费和账户方案。授权服务与客户端入口已实现；真实支付与自动开票验收仍未完成。见 [LICENSE_SERVER.md](LICENSE_SERVER.md) 和 [PAYMENTS_AND_TAX.md](PAYMENTS_AND_TAX.md)。价格按下方 2026-09-29 决策更新，换机与授权使用细则尚待落实。

当前首发：月付与年付订阅；首批客户为多直播间团播公司；一台主机销售一份独立授权，不附赠备机。价格已有最新用户决策，尚未开售；未确认的服务额度和授权细则不能直接作为已生效合同。

## 1. 产品定位和销售单位

销售“节目、音乐、画面与灯光的一体化现场编排及联动”，主要价值是降低多直播间培训、重复操作和现场排错成本。不能宣传替代 OBS、灯光控台或直播伴侣，也不能承诺自动开播、涨粉或收益。

以主机为销售单位：一台主机需要一份独立授权，不采用并发浮动主机授权。主播人数、操作员账号、节目数、素材数、Cue 数均不计费。操作员可以交班，不额外购买人员账号。

一份授权只绑定一台主机，第二台和备机均需另购。公司套装只是多份单机授权的采购折扣，不允许多台电脑共用一份授权。所有使用主机均需购买，换机需办理原授权迁移。

产品不拆出残缺的基础版和复杂的灯光插件收费包。所有付费主机授权具有相同且已验收的核心能力；企业采购差异体现在主机授权数量、订单与服务，不体现在故意限制节目数量。

## 3. 全功能付费与到期行为

首次启动只提供授权入口；未激活不挂载工作区，不恢复工程或自动连接设备。工程创建、打开、编排、素材预览、设备读取及输出均需要付费授权。主进程产品接口默认检查许可，新接口不能因未加入黑名单而自动免费。

不提供试用，不接受旧协议中的 trial 许可作为产品使用资格。已开始的付费现场会话不因到期或服务器断线突然停止；结束后新操作重新校验。曾通过授权的本次应用进程允许保存未完成工程，停止、断开和关闭始终可用，用于保护已有数据与设备状态；这不是免费编排模式。

买断区分使用期限与升级期限。升级服务到期不撤销已购版本使用权，未来商业更新需按版本发布时间校验资格。当前更新模块尚未实现该发行筛选，不得宣称已支持收费升级。

## 4. 设备绑定、换机和离线

- 无客户账户；个人和公司以订单、激活码、机器绑定区分。一张企业订单可购买多份独立单机码，交给不同操作员使用。
- 激活码是持有凭据，需要加密保存；不能只凭公开订单号查询激活码。购买、订单找回和开票入口需使用不可猜测的订单凭据或验证购买时的联系方式，仍不要求注册。
- 当前机器码为 Windows MachineGuid 的产品隔离哈希；没有 TPM 或设备私钥证明，不能保证抵抗系统克隆。重装、硬件更换须提供迁移恢复流程。
- 当前客户端每次启动联网验证，失败不进入工作区；七天凭证不等于允许跳过启动校验，也不会扩大已付费订阅期限或升级期限。运行中会话与撤销限制见 [发布链路](RELEASE_CHAIN.md)，相关使用条件需在开售前说明。
- 服务端撤销阻止再次签发；已签发离线凭证不能即时收回。当前迁移等待旧凭证到期及五分钟容差，不承诺即时换机。离线永久许可独立管理，不承诺可远程即时注销。
- 服务器只签发授权与处理订单，不介入音频、Cue、MTC 的实时计时。

## 5. 购买、支付、退款和售后

完整流程：选择个人/企业采购及主机数量 → 展示方案、金额、服务日期、发票及条款 → 服务端创建订单 → 官方扫码收银台 → 支付渠道验签/查单确认 → 幂等发放权益 → 领取各台激活码并绑定设备 → 下载对应版本及配置指南。

按用户顺序先接支付宝，微信同步办理；支付宝通知、主动查单和发码接口已部署，但生产新售关闭。公司合同对公付款需人工核款，再通过受保护的运营入口发授权。禁止凭客户付款截图自动发货，禁止把收款密钥放 Electron 中。

订单金额由服务端商品版本、主机授权数和优惠计算，客户端不可上传最终应付价格。支付回调必须验签、解密、核对商户、订单、金额和币种；同一支付流水只产生一次权益变更。主动查单与回调共用同一事务。支付成功但发货失败显示“已支付，授权处理中”，服务端可重放任务，不让客户再次付款。超时关闭与迟到支付按查单最终事实处理。

退款规则作为待法务核定的商业承诺：首次购买 7 天内可申请兼容性退款；先支持复现，无法解决可退，不用“已激活概不退款”覆盖所有情形。重复购买、支付成功未交付由客服核对处理。部分退授权根据订单实付和主机授权明细计算，不能退完套装再保留所有权益。买断退款需告知注销授权；离线撤销限制见上一节。

退款状态与渠道退款单绑定；退款确认前不当作已退款，退款确认后更新权益、发票处理和审计。撤销权限不打断已运行会话。折扣、退款、续费、升级都保留原订单价格快照。

基础支持建议工作日 10:00—19:00，1 个工作日内首次响应，属于响应目标，不是解决时限；首期不卖无人值守的 24 小时 SLA。

可选服务建议价：远程部署 999 元/公司（最多 3 台、一次预约、最多 2 小时）；培训 1,499 元/2 小时；现场交付按工时、差旅和范围单独报价。软件缺陷排查不能强制转收费培训。备份、预检、日志导出不得成为高级付费功能。

## 6. 客户界面与运营后台

设置保留“本机授权”：机器码、授权客户、类型、使用期限、升级期限及离线凭证期限。首次启动显示“激活团播联动台”，激活后进入原工作区；不加入客户注册和登录。

待实现购买页：含税价格、授权数量、期限、机器绑定说明、退款及隐私条款、微信/支付宝支付。付款后展示激活码和订单凭据，提供下载留存。企业采购仅增加购买方抬头、税号、联系人及数量，不建设成员系统。

订单找回、续费、退款申请、开票申请走订单凭据或验证联系方式。不能以机器码本身作为查询订单、退款或迁移的身份凭据。

内部运营仍需受控认证，当前为私网管理 API 与令牌；“客户不注册”不代表后台可以无鉴权。运营界面、角色权限和完整支付对账页面尚未实现。

## 7. 技术设计与仓库落点

保留 Electron + TypeScript + Zod。新增小型 TypeScript 授权/订单 API 和关系数据库即可，不首期拆微服务。客户端只持签名公钥，服务端签名私钥由专门密钥服务或受控签名进程保管，不进仓库、前端包或日志。

当前实体为订单、单机授权和审计。自动收款接入再增加商品/价格版本、支付流水、退款、开票任务和对账记录，不添加客户账号和成员表。金额、授权数量、已付期限由服务端订单决定。

授权载荷已由 packages/schema 定义 product、licenseId、customer、machineCode、kind、issuedAt、useUntil、updatesUntil 及可选在线 lease。客户端只信任配置的 Ed25519 公钥；签名私钥与支付密钥仅由服务器保管。
客户端边界：

1. packages/schema 定义授权状态与 IPC DTO，不向 LinkProject 加授权字段。
2. main/link 的 LicenseService 校验签名、设备和时间资格，保存受保护的本机状态；renderer 只显示结果。
3. runtime 的正式会话入口和主进程外部输出边界检查许可，使用进程内会话句柄承接运行中资格。禁止只靠 renderer 按钮隐藏；播放、P1 布防、自动启动、MIDI 输出、控台写入都要覆盖。
4. 所有产品能力统一要求付费授权；原 Command、工程 schema、预检及错误处理保持不变。
5. 会话检查仅发生在准备/启动阶段，云端授权服务不得成为 Cue、音频时钟或 MTC 实时路径中的依赖。
6. 商业更新接口只返回符合 updatesUntil 的版本；提供公开签名下载或短效下载地址，移除客户 GitHub Token 配置。签名验证失败阻止安装，不替换正在运行的版本。

关键 API：创建/查询订单、支付回调、领取权益、设备激活/释放、下载离线授权、刷新授权、查询合格版本、申请退款。支付回调幂等、激活并发控制、订单查询凭据隔离和签名密钥轮换必须有测试。

后台故障时，已有有效离线授权继续运行；新付款保留订单可查、等待补发；不临时默认为未授权，也不通过隐藏异常伪造成功。

## 8. 正式销售前的门槛

初始源码核查未发现商业化模块；现已新增离线签发与本机验签基础，真实支付、自动开票及生产部署仍未完成；UpdateCenter 已切换公司 HTTPS 更新源并移除客户 GitHub Token 配置，升级期资格限制待实现；THIRD_PARTY_NOTICES 记录了 GPL FFmpeg 与 IBT/Marsyas。既有文档还明确实体 MA2 未完整验收。旧记录不是本次重新验收结果。

必须完成：

- 实体 MA2 的连接/登录、Cue 读写回读、MTC 时间对齐、断线和恢复验收；OBS、内部音频与 P1 核心工作流长时运行。此前“点连接无反应”不能仅靠模拟测试就算现场修好。
- 全新 Windows 安装、签名发布、更新/回滚、普通权限、不同 DPI、弱网/断网、单机绑定、设备迁移；正式输出期间不弹购买窗口、不自动停止。
- 付费入口锁定、订阅到期、买断升级到期、撤销、回拨、克隆、离线签名篡改；可随时保存/导出用户数据。
- 支付金额篡改、重复/乱序回调、付款后断网、退款重复处理、并发抢占主机授权、订单越权、服务端灾难恢复。
- 商户主体、支付签约、发票、最终用户协议、隐私说明、退款政策及实际部署地区要求落实，最终条款由相应专业人员核定。
- 分发物许可证审计：FFmpeg 对应源码/构建配置/许可材料、IBT 源码与构建、OBS 原生插件及其链接方式逐项核查。GPL 允许收费，但收费不免除许可证义务；不能因为外部进程通信就自行宣称闭源方案已合规。

试点合同明确支持的硬件和软件版本，不把未验收功能当正式卖点。上线首期建议 3—5 家公司，每家先 1 个直播间跑通再扩到多席。

| 阶段 | 交付 | 出口条件 |

## 10. 收入测算与持续决策

用 3 台年付 5,999 元计算：10 家年合同额 59,990 元，30 家 179,970 元，100 家 599,900 元，分别对应 30/90/300 个单机授权。这是情景计算，不是销量预测，也不是净利润；服务费不计入稳定续费收入，买断收入不计入 ARR。

每客户贡献 = 实收收入 − 退款 − 支付渠道费用 − 税费 − 云服务分摊 − 获客/渠道佣金 − 实际支持工时成本。买断还需预留后续维护成本，不能把首笔现金全部视为利润。

首批记录：购买→激活→首次成功联动→第二直播间增购；另统计每席支持工时、激活成功率、故障会话、退款原因、续费和增购主机。指标只上传去标识的产品事件，工程、音视频、节目名和控台内容不默认上传。诊断附件由客户主动选择。

首轮 10 家价格访谈＋3—5 家真实付费试点后调价：若支持成本过高，先修复部署和诊断，不简单压低售价；若客户只愿买单机，重新验证多直播间定位；不要在无数据时规划大量渠道代理。

待经营者确定：正式产品名称及商标、销售/收款主体、报价和税务口径、域名/服务器、客服资源及联系方式、首批试点名单。已确定的买断＋订阅和公司客群无需再次询问。
