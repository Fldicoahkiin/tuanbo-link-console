# 团播联动台全界面重设计计划

日期：2026-09-21。状态：核心工作区结构重构已实现，0.4.10 已打包并验证打包程序；增强项与实机验收尚未全部完成。实施范围、截图及剩余项见 [实施记录](./UI_REDESIGN_IMPLEMENTATION.md)。

## 一、为什么上一轮变化不明显

上一轮完成了主题变量、字号、对比度、交互状态和部分无障碍基础工作，但保留了主要页面的信息架构、空间分配和操作顺序。因此它属于界面基础整顿，不应被当作全界面重设计完成。

现有截图显示：节目单上方播放器、频谱、时间监看占据三块同等强调的面板，下方内容稀疏，右侧属性表单常驻；灯光页出现主导航、内部导航、素材库和编排区层层并列，最小窗口工具栏换行。这些是布局和任务优先级问题，继续叠加配色覆盖不能解决。

本次核查时，安装包 `apps/desktop/dist/Tuanbo-Link-Console-0.4.9-x64.exe` 修改时间为 15:52:31，最后渲染构建时间为 16:34:12。上一轮没有重新生成安装包，不能证明用户正在使用最后一次界面构建；也不能据此断言用户打开了哪个版本。

## 二、目标与边界

目标是让每个页面首先回答：当前正在做什么、下一步做什么、出错后在哪里处理。成品是适合 Windows 现场操作的专业桌面工作台，吸收 Apple 的清晰层级、直接操作和克制动效，不照搬 macOS 窗口装饰或手机导航。

设计依据为已安装的 apple-design、mobile-native、better-interface、better-layout、better-typography 及其颜色、文案、无障碍、控件细节配套技能。Apple Design 为参考资料，不是可安装技能。mobile-native 仅采用适合桌面的输入方式、滚动和交互规则。项目要求的 frontend-design 与 TypeScript 专用技能此前未找到，不宣称已经加载；实施遵循项目设计系统与严格 TypeScript 规范。

必须保留全部已有业务能力，包括 OBS 原生预览与所选来源编辑、参考波形、低功率开关、P1 跟随、内部主控、Cue、灯光编排和 MA2 同步。简化界面通过重新分组和按上下文展示完成，不能通过删除能力实现。

不改变正式媒体输出归属，不增加推流、录像或直播伴侣开关控制。不改变工程 schema、计时来源和断线行为。工程修改仍通过 LinkCommand；跨边界错误必须可见、可追溯，不能被视觉简化掩盖。

## 三、逐页改造方案

| 范围 | 当前问题 | 目标结构与具体变化 |
| --- | --- | --- |
| 全局框架 | 导航、项目操作、设备状态竞争注意力 | 建立固定主导航、紧凑项目栏和统一状态入口。清楚展示工程名、保存状态和当前工作区；设备异常从摘要进入详情。编辑器属性栏可调整宽度、可收起，保存用户布局偏好。 |
| 欢迎与新建工程 | 入口与创建表单缺少统一流程 | 明确新建、打开、最近工程；创建弹窗采用统一字段、校验和焦点规则。缺失文件、打开失败等直接给出可执行处理。 |
| 节目单 | 三块仪表过重，卡片稀疏，属性常驻 | 主内容优先展示当前节目、下一节目和节目顺序；播放控制靠近当前节目。以紧凑节目列表作为编排主视图，保留适合点播的卡片视图。选中后显示详情，默认避免空属性区占空间。频谱和详细时间码进入可展开监看区，关键播放状态持续可见。 |
| 播放列表 | 列表管理与节目操作不够清晰 | 列表选择和新建、重命名、排序形成稳定分组；明确当前选中与当前播放的区别。长名称有可访问的完整文本入口，拖动与键盘操作语义一致。 |
| 视频编辑器 | 素材、画布、时间线和属性缺乏明确主次 | 左侧素材库，中间大画布，右侧所选对象属性，下方可调整高度的时间线。画布与时间线成为视觉主体；未选择对象时显示简短操作提示。OBS 连接状态、选中来源、同步异常在画布附近清楚呈现。 |
| 时间线与 Cue | 工具分散、按钮密集、轨道信息拥挤 | 统一播放头、标尺、缩放、吸附、轨道头和选择状态。高频工具常驻，低频操作进入清楚命名的菜单；保留快捷键提示。拖动、裁剪、对齐和越界反馈保持一致。 |
| 灯光工作台 | 多层侧栏、库区空白、工具栏换行 | 合并内部重复导航；素材库集中搜索、分类与素材结果。灯光时间线和参考波形获得连续的主空间，右侧按选择显示编排与参数。常用素材可直接加入时间线，详细素材管理按需打开。MA2 连接、待同步变更与同步结果在固定区域展示。 |
| 设置 | 分组入口、表单、说明和诊断混在一起 | 保留 4 组、14 个设置页，使用单一设置目录和统一表单内容区。设备页按状态、连接操作、配置、诊断排序；高级参数渐进展示。不同页面采用同一标签、帮助、错误、保存反馈规则。 |
| 预检与日志 | 状态信息容易变成零散提示 | 预检突出阻断项、定位入口和下一步；日志提供级别、来源、时间过滤与详情查看。排练首错阻断和直播失败继续的区别显式呈现。 |
| 更新、导入、来源选择与弹窗 | 各流程布局和反馈不一致 | 使用统一弹窗、进度、结果与错误结构；重要操作有明确结果。长流程支持已有取消能力，不新增虚假取消按钮；更新保持独立窗口的现有行为。 |

设置完整清单：OBS Studio、MA2 控台、音频与 MIDI、虚拟 MIDI、高级与诊断、播放主控、播放习惯、快捷键、监看与性能、视频定位、时间码同步、场景工作方式、界面外观、软件更新。

每个页面同时设计空白、正常、选中、编辑、加载、断线、失败和禁用状态；不适用的状态在清单中说明。菜单、提示、确认、导入结果和错误详情均在范围内。

## 四、统一视觉与交互规范

1. 层级：全局导航、页面任务、编辑内容、上下文属性四级明确。使用留白和背景区分区域，减少所有容器都有边框的情况。一个区域只突出一个主要操作。
2. 密度：保留专业工具的信息量，减少重复说明和无意义空白。组内紧凑、组间明显，避免一味放大控件导致有效工作区缩水。
3. 字体：采用 Windows 系统字体栈；正文建议 14px、控件 13–14px、辅助文字不低于 12px、页面标题 18–22px，最终以实机可读性调整。时间码使用等宽数字，表格数字对齐。
4. 色彩：深浅主题共享语义变量；强调色用于选中和主要动作，状态色有文字或图标配合。画布内容与轨道业务颜色保留独立语义。
5. 控件：按钮、输入、选择器、标签页、菜单、工具栏、空状态、错误与弹窗共用规范。图标使用 lucide-react；仅图标按钮必须有可访问名称和提示。
6. 动效：只服务于展开、选择、拖动等状态理解；尊重减少动态效果设置。现场播放和时间码更新不增加装饰动画。
7. 操作：键盘焦点可见，弹窗正确限制并恢复焦点，危险操作和普通操作分开。悬停不是唯一信息入口，错误不能只靠短暂 toast。
8. 尺寸：先在 1540×960 确定标准布局，同时约束 1180×720 最小窗口。空间不足时收起次要面板、调整工具分组，不裁掉主操作；时间线允许受控二维滚动。

## 五、执行阶段与交付门槛

### 阶段 0：完整盘点与可见基线

- 建立页面、组件、菜单、快捷键、弹窗和异常状态清单。
- 对当前程序与安装版本分别记录版本、路径、构建时间，排除打开旧版本的混淆。
- 使用同一份工程保存四个主页面的深浅主题基线截图；覆盖有数据、长名称和断线状态。
- 为现有能力建立“旧入口 → 新入口”对应表，保护功能完整性。

交付：界面清单、能力对应表、基线截图。门槛：明确全部范围，不以四张空白页面截图代替完整盘点。

### 阶段 1：确定结构与高保真设计

- 先完成全局框架和节目单、视频编辑器、灯光工作台、设置四个核心页面。
- 使用真实密度的节目、素材、轨道和设备状态；同时给出深浅主题及最小窗口适配。
- 第一组重点对比为节目单和灯光工作台：展示旧版、新版并排图，标注空间分配与操作步骤变化。
- 补齐选择、属性展开、库区切换和错误定位等关键交互原型。

交付：页面结构图、高保真效果、关键交互与前后对比。门槛：主布局、信息主次和高频流程已有明显改善；不能仅凭颜色变化进入全面实现。设计检查先由实施者完成，不默认增加逐页等待用户批准的流程。

### 阶段 2：整理设计系统和公共组件

- 明确主题、字号、间距、控件尺寸和状态变量的唯一来源。
- 梳理 link.css、appearance.css、各工作区样式及 interface.css 的覆盖关系，按组件归属逐步整合。
- 迁移一个组件后再移除其失效规则，不直接清空旧文件，不继续增加最后加载的全局覆盖补丁。
- 建立公共按钮、表单行、工具栏、面板、状态、空状态和弹窗结构。

交付：变量规范、公共组件与样式归属表。门槛：深浅主题与交互状态一致，没有依赖导入顺序才能偶然生效的冲突。

### 阶段 3：全局框架与节目单重构

- 实现导航、项目栏、状态入口、当前与下一节目区域、列表/卡片和上下文详情。
- 保留播放列表管理、音频与 MTC 监看以及所有播放模式入口。
- 检查实际选歌、切换列表、修改节目、播放/停止和异常反馈，不只截图。

主要落点：LinkApp、ProjectWorkspace、ProjectPlayerControls、ProgramGrid、ProgramPlaylistPane、P1TimeMonitor、SongPlaybackProperties。

交付：可运行的全局框架与节目单、前后对比、操作回归结果。门槛：正常使用路径清楚，最小窗口仍能完成主要操作。

### 阶段 4：视频编辑器与灯光工作台重构

- 先建立共用编辑器框架，再分别处理视频与灯光任务，避免强行统一不同业务。
- 调整素材库、画布、属性和时间线占比，完成面板尺寸与折叠行为。
- 统一选择、拖动、缩放、快捷键与空状态；把灯光多层导航整理为任务清楚的入口。
- 保留 OBS 所选来源的双向编辑边界，以及 MA2 待同步变更和结果的明确展示。

主要落点：CueWorkspace、ResourceLibrary、ReferenceStage、ObsLiveCanvas、ReferenceTimeline、各 Inspector，以及 LightingEffectDock、LightingCueComposer、LightingTimeline 等。

交付：两个完整工作台、真实数据演示、时间线操作回归。门槛：拖动和编辑没有被新的布局容器、焦点或滚动行为破坏。

### 阶段 5：设置与所有辅助流程

- 完成全部 14 个设置页；每页覆盖默认值、编辑、连接中、成功与错误等适用状态。
- 统一新建、打开、导入、OBS 来源选择、日志、预检、软件更新和通知。
- 检查高级参数仍可发现，帮助文案说明实际作用，不能隐藏重要现场风险状态。

交付：完整界面覆盖清单。门槛：不存在主页面已改、弹窗和次级页面仍沿用旧体系的遗漏。

### 阶段 6：视觉与行为验收

- 深浅主题分别验证 1180×720、1540×960、1920×1080。
- 验证 Windows 125%、150% 缩放及适用页面 200% 放大；网页缩放测试不能替代实际系统缩放检查。保留时间线二维编辑特例，其他主内容不能横向丢失。
- 数据覆盖：空工程、少量节目、大量节目、长中英文名称、多轨道、缺失媒体、设备断开和错误详情。
- 检查键盘全路径、焦点、对比度、减少动态效果；对未实测的读屏与高对比模式明确标注。
- 按修改范围执行 typecheck、lint、构建、相关单测及 Electron e2e，发布前执行项目规定的发布校验。
- 用实际录屏验证完整流程：打开工程 → 选节目 → 编辑素材/Cue → 保存 → 重开；另验证灯光编排、设置与错误定位。

交付：验收矩阵、对比截图、操作录屏、测试结果和剩余限制。门槛：自动化通过与视觉合格分别判断，不能互相代替。

### 阶段 7：Windows 打包与实际交付

- 在 Windows 原生环境执行发布校验并生成新安装包；按项目版本策略处理版本，不覆盖混淆旧构建。
- 核对安装包版本、时间和校验值，启动打包产物复查主要界面。
- 交付安装包及明确的启动位置，确保用户看到的是本次重设计构建。
- 记录 OBS、P1、MA2 等真实外设联调状态；未连接实机的部分保持待验收，离线测试不算实机通过。

交付：新安装包、发布说明、已验收与待实机验收清单。门槛：源码更新和开发预览不能单独代表最终交付完成。

## 六、最终完成标准

- 四个主页面的布局、信息层级和主要操作区均有清晰可辨的变化，而不仅是颜色、圆角与字号。
- 全部旧功能都有新入口对应，没有因简化界面丢失监看、预览或高级配置。
- 当前节目、选中对象、播放状态、计时来源和阻断错误不存在容易混淆的视觉表达。
- 最小窗口可以完成核心任务，弹窗、菜单、工具栏与错误详情没有不可达内容。
- 深浅主题、控件状态、字体与间距一致；公共规则可维护，不继续累积覆盖补丁。
- 测试、截图、录屏和打包运行证据对应同一构建；现场硬件限制如实列出。
- 用户获得可打开验证的新 Windows 安装包。
