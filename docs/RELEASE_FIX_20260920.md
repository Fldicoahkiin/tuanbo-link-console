# 0.4.5：纯 MIDI 现场与 P1 裁剪修复

## 现场反馈与处理

- 用户通过电脑 MIDI 接口接控台，要求声光时间码同步、Cue 编排及选中 Cue 即发送；网络读取和双向编辑可选。
- 新机器默认“仅 MIDI（时间码与 Cue）”；已有明确配置的本机/网络模式保留，可在设备连接中手动改为 MIDI。切换时关闭已有网络配置的启动连接并断开网络，保留地址及密码。
- MIDI 模式不显示网络未配置、网络登录及扫描面板，不进行顶部 MA2 状态轮询、自动编辑同步或一键连接 MA2 网络。网络/本机编辑功能仍可明确选择。
- MIDI 模式提供独立 P1 导入及写回入口，不依赖 MA2 扫描。

## P1 修复

- 非零 `cut_start` 不再拒绝整个歌单：用随软件提供的 FFmpeg 将实际选段解码到工程音频资产，歌曲零点对应原始裁剪起点。
- 解码只发生在导入时；顺序处理歌曲，校验输出 WAV 只读文件头，不把整首音频载入内存。没有新增 GPU 工作或常驻转码进程。
- 导出保留原音频路径与 `cut_start`，按歌曲时长计算 `cut_end`。原工程不覆盖，输出独立 `.联动台.hia`。
- 导入同时设置歌曲内部播放时间码偏移为 P1 原 `MidiStartTime`，无需先绑定 MA2 时间线。已有工程需重新读取 P1 才应用该导入修复。
- 保存重开后可通过文件选择导出，不要求 P1 进程运行。请选择上次读取/导出的对应文件；来源哈希保护仍有效。
- 不猜测缺失素材，不把非法裁剪替换为零；负起点、终点不大于起点、选段超出可解码音频均报错。

## Cue 与一键连接

- 一键连接重新枚举当前电脑的 MIDI 接口。唯一有效硬件输出自动绑定主控时间码及灯光动作；忽略 Microsoft GS 软件合成器。多个候选、已配置端口消失或重名均明确报错，不随意改发到其他端口。
- 一键连接打开端口但不发送 Cue。灯光轨道选择默认输出时使用 `lighting-events-output`；明确指定的端口不可用时阻断，禁止偷偷回退。
- 编辑台默认开启“选中 Cue 实时播放”，通过 MSC 发送所选 Cue（组合点发送对应组合）。手动关闭后不发送；快速改选、退出编辑台或关闭开关会取消仍在等待的旧请求。恢复工程选中状态不自动触发。
- MIDI 无控台执行回执，界面只报告“已发送”。需要现场在控台开启 MIDI Show Control 输入，并匹配设备号与执行器编号格式。可编排已有 Cue 的引用、时间与动作，不能通过普通 MIDI 读取或编辑 Cue 内部灯具参数。
- 灯光工作台明确选择 MTC 时间线播放或 MIDI 直接触发 Cue，避免将两种输出方式混淆。
- 控台 Lua 插件已随安装包内置；设备连接的 MA2 页面顶部提供“导出控台插件”，离线可用。仅 MIDI 触发不要求插件；网络扫描与同步仍需将插件安装到控台。
- 网络连接说明已放到账号字段上方，指出网线、Telnet Login Enabled 和 Show 用户的位置。
