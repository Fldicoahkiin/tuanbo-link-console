# 灯光工作台本轮修复记录（2026-10-06）

本轮基于用户新反馈：整首歌后半段 Cue 不触发但显示“发送中”；拖动希望立即写回；停止后保持最后灯光；节目卡缺灯光标识；素材只显示当前歌曲且过大。用户不知道输出方式，暴露了设置层级的问题。

## 已实施

- 灯光输出方式固定在时间线播放按钮旁，显示时间码跟随、网络直控或 MIDI 触发；停止后可选择，沿用 LinkCommand 保存。正在播放时不偷偷换输出方式。移除侧栏重复选择器。
- 素材库默认使用控台序列视图，完整工程序列池优先于歌曲旧目录；单步点击调用，多步进入原名称、原编号子菜单。读取控台并配对后补读全序列池，同来源已完整缓存重新连接时复用。素材失败不清除已读歌曲 Cue。
- 紧凑的 42px 行高虚拟网格、搜索、分类和键盘导航。控台活动 Cue 未回读时仅显示指令已发送。
- 歌名前增加小灯光图标，不加卡片行高。
- 显式停止补充本节目目标的 Off：网络针对绑定执行器/序列，MIDI 直控使用既有 MSC 编码及原输出端口。先取消旧播放队列，目标变化拒绝发送，不自动重试。不会发送全局 Off 或停用 Timecode，避免停止后破坏原有再次跟随方式。
- 自动同步 hook 不再因通知回调身份变化重建；挂载时接收已经存在的明确同步请求。
- 修复工作台全局快捷键截获素材库 End/Home 的冲突。

## 软件验证

- 严格类型、ESLint、构建和完整 Vitest 回归已运行。证据日志位于 D:\团播联动台工作数据\046*。
- Electron 实际界面测试：1000 个构造序列，验证有界 DOM、搜索、单步调用、多步子菜单、原编号、键盘导航、可见输出选择器。使用隔离免激活内测构建。控制调用采用测试 IPC，不属于实体出光验收。
- 构造三分钟、90 步调度回归覆盖最后一步；停止回归覆盖去重、取消、断线/目标变化与 MIDI Off 编码。这些结果不能证明用户的真实后半首问题已解决。

## 未完成和明确限制

- 后半首现场不触发尚未定位；没有此次歌曲的真实工程、原生时间线及运行日志，不能把“发送中”当作控台执行证据。
- 播放中原生混合时间线实时写回未开放。现有完整 XML Import 不具备安全运行中最小修改证据，仍保留保护。已验证可写绑定在停止播放、拖动结束后自动核对与同步；未知动作时间线保持原文并禁止破坏性写回。
- 仅 MTC、无 MA2 网络时，停止发码不等于关闭控台执行器；没有明确的独立关闭通道时不能承诺灭灯。实体 Off、淡出、时间码再次播放需现场验收。
- 全序列池真实规模耗时、MA2 3.7.0.5 写回、六小时现场链路未在本轮验收。未发布为“上述五项全部完成”。

## 2026-10-07：自主开始同步、撤销与工程存档

本节补充后续实测，不能把上一节的现场限制视为已全部解除。

- 删除工作台顶部常驻待提交说明。侧栏提供开始/暂停同步、状态详情、撤销/重做、保存与存档。连接和打开工程不会自动启用写回。
- 开始同步后，停止播放且编辑结束一秒后自动核对。每次写入前先保存完整 `.tblink` 存档，失败即阻止控台写入。手动同步也走相同存档要求。保存按钮保存本地工程并另存快照，不表示控台 Show 已保存。
- 存档与工程同目录，共用原素材；D 盘工程的存档也在 D 盘。子菜单列出时间和原因，可定位文件；恢复时通过打开工程入口选择该存档，重新核对控台后决定同步。仅恢复工程不会自行输出灯光。
- 修复回读占用撤销步骤、撤销时退回过期控台基线的问题。控台确认只更新历史帧中的同步基线；用户编辑仍可一步撤销/重做，启用同步时反向写回。
- 真实 onPC 发现 `getobj.name(Cue 50)` 返回“050 蓝光 50”，`getobj.label` 和 XML 返回“050 蓝光”。轻量目录改读原始 label，避免与写前 XML 核对误判冲突。
- 原传输逐个回读 256 字节，1.6MB 序列产生数千次网络往返。现在每个命令核对 32 个带独立身份的片段；写入时对完全一致的原始快照使用控台缓存引用，避免再次上传整份序列。控台仍重新导出并逐字核对当前快照，目标、引用或内容不同不能使用缓存；失败不重发。桥版本变化仍须重新建立匹配的组件会话。
