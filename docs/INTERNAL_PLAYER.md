# 内部音乐主控与 MA2 onPC

> 这是 0.3.0 到 0.4.x 时的说明，只作记录。里面的行为有些已经改了（比如 OBS 断开不再停歌，画面失败照常放音乐）。现在的结构见 [ARCHITECTURE.md](./ARCHITECTURE.md)，规则见 [AGENTS.md](../AGENTS.md) 和 [LIGHTING_WORKFLOW.md](./LIGHTING_WORKFLOW.md)；不一致时以它们和代码为准。

0.3.0 增加内部音乐主控，保留原有 P1 跟随。工程中的播放模式需要明确选择，不会因 P1 或 OBS 断线自动换时钟。

## 使用

1. 打开工程，进入左侧“工程与节目单”，选择“本软件主控”。
2. “添加音乐（可多选）”将本机音频导入工程。未保存工程会先显示保存位置选择。导入成功后形成歌曲卡片。
3. 在节目卡片上右键进入 Cue 编辑器，添加原始视频、图片、摄像头画面和 MIDI 动作。OBS 受管来源、图层、定位、启停由软件维护。
4. 展开同页“音乐与灯光连接”，选择 MIDI 输出与监听设备。此电脑最终采用已实测回送的系统端口：软件输出选择 `Default App Loopback (A)`，MA2 onPC MIDI In Device 选择 `Default App Loopback (B)`，MIDI From onPC Command Wing 选择 No。这是一对交叉回环端点，不是同名输入输出。默认 MIDI 时间码进入 TC Slot 2；对应的 MA2 时间码演出要使用该槽。
5. 点击歌曲卡片直接播放。可暂停、继续、停止、重播、上一首、下一首、拖动定位、单曲循环或顺序连播。列表最后一首结束后停止；不自动回到第一首。音量和 0.5 秒淡入/淡出在播放器中操作。

内部模式不启动 P1，也不要求 P1 输入 MIDI。原有 P1 跟随使用原先独立端口；不要将两个主控的时间码输出接到同一端口。灯光端口可以关闭，单独运行音乐与 OBS。

## 音频与画质

- 正式歌曲使用媒体解码器的实际播放位置，OBS 时间线与 MIDI 输出跟随该位置。
- MIDI 逐条发送已到期消息，不在系统中留下无法取消的未来消息。暂停、停止和切歌清空本软件调度状态。
- OBS 有一条启用的默认桌面音频、且送入音轨 1 时，复用该音频通路；否则建立本软件拥有的应用音频采集。不会修改用户原有来源。若已存在不确定的设备映射或两条重复桌面采集，会明确报错，不猜测通路。
- 内部主控默认关闭视频原声，避免同一首歌同时从播放器与视频中发声。需要素材原声时显式勾选“同时播放视频素材原声”；各素材自己的原声开关仍生效。
- 素材按 SHA-256 校验并保留原文件字节，不进行视频转码、代理替换或二次有损压缩。视频/图片直接由 OBS 解码与合成；音频提取使用 PCM WAV。
- 原始分辨率、工程与 OBS 画布、缩放及直播编码决定最终观感。448×960 原视频放大到 1080×1920 不会变成原生高清；本软件不能保证直播平台端无压缩。OBS 输出缩小或素材放大会在预检中提示。
- 编辑器试听可能被 OBS 已开启的桌面音频采集；正式演出在工程与节目单操作。

## 中断与定位

音频位置超过 500ms 不推进、MIDI 调度超过 100ms 不能跟上或 MIDI 端口断开会停止歌曲和时间码，并显示错误。OBS 断开也会停止内部主控，清理失败明确保留错误；重新连接后，由用户明确重播，避免自动跳回直播。

OBS 中断后，进入软件“设置”，在 OBS 卡片点击“重新连接 WebSocket”；回到工程与节目单点“停止播放”完成旧输出清理，再点击歌曲。整个恢复过程在本软件中完成，无须到 OBS 添加或操作素材。

定位会先停止旧节目输出，重建目标时间的可见视频与摄像头状态。不会补执行已经越过的 MIDI/MSC 或其他一次性动作。暂停定位仍保持暂停。

每首歌曲自动分配唯一的灯光时间码区间，右侧音频属性显示起点，歌曲之间预留间隔。调整顺序、增加歌曲或改变时长后，要核对 MA2 时间码演出的对应起点；软件不自动生成艺术性的灯光 Cue。内部模式当前支持 24、25、30 fps；29.97df 会明确阻止播放。单份内部节目单与区间间隔总长必须小于 24 小时。顺序切歌包含预检和媒体准备间隔，不是无缝音频拼接。

本版实现的是音乐节目主控与声画/时间码联动，并未承诺逐项复制 P1 的全部专有功能或兼容所有 P1 工程类型。没有实体控台，本次仅验证 MA2 onPC 软件接收，未验证实体灯具、DMX 输出、平台推流或真实十首完整演出。
