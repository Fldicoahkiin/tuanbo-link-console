## 修复

1. P1 正式跟随原先没有调用灯光事件调度器。现在从 P1 的有效时间码驱动网络 / MIDI 灯光输出，自动选歌使用歌曲相对时间，普通跟随扣除已配置偏移；暂停、断流、跳转及切歌取消旧队列，恢复不补发过去的 Cue。
2. P1 模式下工作台本地音乐预览缺少可见联动开关。已在左侧播放设置增加“时间线播放控制灯光”；与“选中 Cue 实时播放”分开。
3. 编辑已有 Cue 会重建到新轨道。现在保留原轨道、片段、事件编号、静音状态与输出配置，避免改变原有 MA2 同步映射。
4. 追加导入工程遗漏组合 ID、同步轨道映射和待绑定轨道 ID 重映射。现在这些引用一起重映射，埋步字段继续保留。

## 使用与限制

- Sequence Pool 与软件埋步选择“网络 · 直接播放序列池”。准备 Cue 需在控台事先保存为灭灯就位状态。
- P1 模式下，仅在工作台播放参考音乐时，需要勾选“时间线播放控制灯光”；正式 P1 跟随由运行会话发送。
- 点选 Cue 的实时预览只调用正式效果。测试完整埋步从准备时间之前播放。
- 软件埋步目前不写入控台 Timecode；遇到该组合明确阻断，不能称为所有输出模式均已走通。
- 当前网络故障会停止该输出会话并报告错误，不自动重试。现场需验证实际接收延迟、同一序列前后 Cue 对灯具的影响以及断线后的人工恢复。
# 0.4.28 时间码调度修复补充

针对“发送延迟超过 100ms，已停止播放”：发送器现在区分短暂调度阻塞与音频位置异常。调度间隔超过 100ms、但不超过 500ms，且音频进度与实际经过时间相差不超过 100ms 时，丢弃未完成的旧消息组，按实际音频发送完整定位帧并开始新一组四分之一帧；播放器保留恢复提示。不外推音频位置，不集中补发旧时间码。超过 500ms、音频跳变、端口断开或失效仍阻断，须手动重播。

验证：全量 950 项单测通过、40 项跳过；四种帧率短暂延迟恢复及异常阻断回归通过。Electron 真实音频测试注入 200ms 界面阻塞后继续播放，650ms 阻塞后停播；MIDI 和 OBS 接口使用模拟，不能代替实体控台验收。完整帧与四分之一帧定义参考 [MIDI Association](https://midi.org/midi-time-code)。
